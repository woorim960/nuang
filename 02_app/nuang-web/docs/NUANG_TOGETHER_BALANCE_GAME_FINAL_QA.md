## 실제 E2E 실행 기록

### 1차 실행

- 방 코드: `M8ZSGB`
- 구성: 취향 종합전, 2명, 8문항, 비공개 초대방
- 방 생성: 통과
- 두 번째 참여자 입장: 통과
- 두 번째 참여자 8문항 저장 및 완료: 통과
- 방장 응답: QA-002로 실패

결함 수정 후 동일 범위를 새 방에서 처음부터 다시 검증한다. 테스트 방 코드는
운영 사용자에게 노출하거나 제품 지표에 포함하지 않는다.

### 결함 수정 후 2인 브라우저·API 교차 검증

- 구성: 취향 종합전, 2명, 8문항, 비공개 초대방
- 방장: 실제 인앱 브라우저
- 두 번째 참여자: 별도 참여 토큰을 사용하는 실제 HTTP API
- 양쪽 8문항 응답 저장: 통과
- 결과 상태: `waiting → final`
- 결과: 88점, 8문항 중 7개 일치
- 만장일치와 갈린 선택: 인원 합계 및 선택지 문구 일치
- 1:1 상세: 본인과 상대의 8개 선택, 같은 선택/다른 선택 필터 통과
- 새로고침 후 참여 세션과 최종 결과 복원: 통과

### 3인 미완료자 관리·방장 마감

- 생성·동일 요청 재시도: 같은 방과 같은 방장 참여자를 반환
- 동일 참여 요청 재시도: 좌석 중복 없이 같은 참여자를 반환
- 방장과 참여자 1명 완주: `current` 결과 생성
- 미완료 참여자 내보내기: 현재 인원 3명에서 2명으로 반영
- 같은 참여 토큰 재입장: `participant_removed` 403
- 방장 마감: `current → final`
- 최종 결과: 완주자 2명, 1개 1:1 조합, 비교 문항 8개

### 3인 전원 완주 그룹 결과

- 첫 번째 완주: `waiting`, 결과 비공개
- 두 번째 완주: `current`
- 세 번째 완주: `final`
- 완주자 3명, 전체 1:1 조합 3개, 조합별 비교 문항 8개
- 각 참여자 응답에서는 본인이 포함된 1:1 결과 2개만 반환

### 보안·운영 경계

- 브라우저 anon key의 `response` 원본 테이블 조회: `42501` 차단
- 브라우저 anon key의 내부 결과/방 RPC 직접 실행: `42501` 차단
- 비로그인 피드 모집방 생성: `feed_auth_required` 401
- 잘못된 방 코드 조회: 40회까지 404, 41번째 요청 `rate_limited` 429
- 마감 방 코드 입장: 참여 폼 대신 마감 안내와 같은 팩 재시작 링크 표시
- QR 초대 열기·닫기, 360px 모바일 초대·결과 화면: 통과
- 로그인 계정으로 2인 공개 모집방을 만들고 실제 공개 피드글 생성·카드 노출·
  참여 링크·`1자리 남음` 표시를 확인했다.
- 별도 익명 참여자와 방장이 각각 8문항을 완료한 뒤 50점 최종 결과를 실제
  공개 피드에 공유하고, 재플레이 링크가 같은 팩의 방 만들기 화면을 여는 것을
  확인했다.
- 결과 공개 projection은 `score`, `packSlug`, `roomName`, `highlight`,
  `packTitle`, `scoreLabel`, `resultStatus`, `completedCount`만 포함했다.
  방장·참여자 닉네임, 개인 답변, 선택지별 개인 기록은 포함되지 않았다.
- QA-006 수정 후 새 공개 모집글을 만들고 1초 이내 피드 새 요청에서 카드가
  보이는 것을 다시 확인했다.
- 실방 검증에서 생성한 비공개 QA 방 8개, 공개 QA 방 3개, 공개 피드글 3개와
  종속 응답·결과는 검증 직후 정확한 ID로 삭제했다. 해당 게시글·방·연결 행의
  잔여 수가 모두 0개임을 확인했다.
