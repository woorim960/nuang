# 뉴앙 검사 포트폴리오와 공개 기준

## 1. 검사 탭의 역할

검사 탭은 검사를 많이 보여주는 목록이 아니다. 사용자가 지금 무엇을 하면
좋을지 빠르게 고르고, 결과를 믿고, 커뮤니티와 관계 탐색으로 자연스럽게
이어지는 출발점이다.

검사 탭은 다음 네 목적만 사용한다.

| 메뉴 | 고객의 질문 | 포함 범위 |
| --- | --- | --- |
| 추천 | 지금 무엇을 하면 좋을까? | 뉴앙 코드의 다음 행동, 오늘의 짧은 놀이, 함께하기 |
| 나 알아보기 | 나는 어떤 사람일까? | 뉴앙 코드와 검증을 마친 자기이해 검사 |
| 함께하기 | 우리는 무엇이 같고 다를까? | 친구 성향 맞히기, 초대 검사, 비교 대상 찾기 |
| 별난 연구소 | 의외의 내 모습은 뭘까? | 진단이 아닌 짧은 선택 놀이 |

`나 자신`, `관계`, `감정·회복`처럼 사용자 관점에서 경계가 겹치는 메뉴는
`나 알아보기`로 합친다. `친구와`는 가족·연인·동료까지 확장할 수 있도록
`함께하기`로 부른다.

## 2. 전문 역할과 책임

| 역할 | 공개 전에 반드시 확인할 일 |
| --- | --- |
| 제품 기획 | 고객이 얻을 가치, 진입·완료·재방문 동선, 중복 검사 제거 |
| 심리측정·검사 설계 | 측정 개념, 대상 인구, 문항 구성, 채점, 신뢰도·타당도 근거 |
| 임상·상담 심리 | 민감 주제의 위해 가능성, 결과 표현, 도움 연결 기준 |
| 콘텐츠·국어 | 번역체 제거, 전 연령 이해도, 문항과 결과 문구의 일관성 |
| UX 디자인 | 한 화면의 한 가지 주 행동, 모바일 가독성, 접근성, 상태별 화면 |
| 브랜드·일러스트 | 아이콘·캐릭터의 의미와 품질, 뉴앙다운 시각 체계 |
| 개발 | 서버 재채점, 공개 상태 강제, 버전 보존, 저장·삭제·복구 |
| QA·접근성 | 320px부터 데스크톱까지, 키보드·스크린리더, 실패·빈 상태 |
| 개인정보·법무 | 민감정보 최소 수집, 동의·보존·삭제, 연령과 이용 목적 |
| 데이터 분석 | 문항 품질, 이탈률, 결과 분포, 공정성, 공개 후 이상 탐지 |

제품 책임자는 각 역할의 결과가 충돌할 때 고객 가치와 검사의 정직성을
동시에 만족하는 최종 결정을 기록한다.

## 3. 검사 상태와 고객 공개 상태

검사의 연구 상태와 고객 공개 여부는 서로 다른 값으로 관리한다.

```ts
type Lifecycle =
  | "draft"
  | "internal_review"
  | "research_only"
  | "pilot"
  | "validated"
  | "released"
  | "retired";

type PublicationStatus = "draft" | "ready" | "published" | "paused";

type IntendedUse =
  | "play"
  | "self_reflection"
  | "trait_estimation"
  | "screening";
```

- `published`인 검사만 검사 탭에 표시한다.
- `pilot` 검사는 `play` 또는 제한된 `self_reflection` 용도로만 공개할 수 있다.
- 세 문항의 짧은 탐색 결과를 대표 성향이나 정확도 향상 근거로 사용하지 않는다.
- 문항이 준비되지 않은 검사는 빈 카드나 `준비 중` 카드로 숫자를 채우지 않는다.
- 모든 시작·결과·저장·공유 API는 같은 공개 상태를 확인해야 한다.

## 4. 공개 게이트

각 게이트는 단순한 참·거짓이 아니라 누가, 언제, 어떤 근거로 판단했는지
보관한다.

```ts
type GateEvidence = {
  status: "not_started" | "in_review" | "passed" | "failed";
  reviewedBy?: string;
  reviewedAt?: string;
  evidenceArtifactId?: string;
  population?: string;
  locale?: string;
  sampleSize?: number;
  decisionNote?: string;
};
```

검사별 필수 게이트는 다음과 같다.

1. 측정 개념과 이용 목적
2. 문항 내용 검토
3. 고객 문장 이해도
4. 파일럿 응답 품질
5. 신뢰도
6. 타당도
7. 연령·성별 등 집단 공정성
8. 안전 문구와 도움 연결
9. 개인정보·법무
10. 모바일 UX와 기술 QA

`released`는 필수 게이트가 모두 통과했을 때 서버가 계산하는 상태로 만들고,
관리자가 문자열만 바꿔 확정할 수 없게 한다.

## 5. 결과 리포트의 최소 기준

모든 결과는 아래 질문에 답해야 한다.

1. 이번 결과에서 가장 가까운 모습은 무엇인가?
2. 어떤 답 때문에 이 결과가 나왔는가?
3. 생활·관계에서는 어떻게 나타날 수 있는가?
4. 잘 활용하면 어떤 장점이 있는가?
5. 조심하면 좋은 점은 무엇인가?
6. 오늘 바로 해볼 수 있는 작은 행동은 무엇인가?
7. 이 결과가 뉴앙 코드에 반영되는가?

놀이 결과의 숫자는 정확도·신뢰도처럼 표현하지 않는다. 내부 버전, QA 등급,
S1·S2 같은 운영 정보도 고객에게 노출하지 않는다.

## 6. 별난 연구소 원칙

별난 연구소는 별도로 유지한다. 제목은 궁금증을 만들되 결과는 다음 원칙을
지킨다.

- 사람의 우열이나 위험성을 판단하지 않는다.
- 질환·범죄 성향·의학적 상태를 진단하지 않는다.
- 짧은 답변으로 상대방을 대신 판정하지 않는다.
- 결과는 `이번 선택에서 가까운 방식`으로 표현한다.
- 뉴앙 코드와 공식 성향 리포트를 바꾸지 않는다.

우선 공개 가능한 주제:

- 말할까, 기다릴까, 정리할까?
- 나는 왜 쉬어도 안 풀릴까?
- 싸운 뒤, 나는 어떻게 풀까?
- 공감과 해결책 중 무엇이 먼저 떠오를까?
- 규칙과 결과를 판단할 때 무엇을 더 볼까?
- 갈등에서 내 선을 어떻게 지킬까?

## 7. 민감 검사 결정

### 애착

한국어 번안, 사용권, 관계 맥락과 연령 검증을 마친 뒤 조건부로 제공한다.
고정된 사람 유형을 단정하지 않고 `관계에서 걱정이 커지는 경향`과
`가까워질 때 거리를 두는 경향`을 연속적인 정도로 보여준다.

### 사이코패스·소시오패스

짧은 모바일 놀이로 진단 결과를 제공하지 않는다. 공식 도구는 훈련된
전문가, 성인 대상, 충분한 문항과 면담·외부 정보 검토 또는 별도의 사용권을
요구한다. `사이코패스 72%`, `소시오패스 유형`, 범죄 위험 예측은 뉴앙의
검사 신뢰도를 해친다.

사용자의 궁금증은 `공감과 책임을 대하는 방식`, `규칙과 결과를 판단하는
방식`처럼 일상 행동을 다루는 독립적인 자기성찰 콘텐츠로 해결한다. 이를
사이코패스나 반사회성 인격장애와 연결해 홍보하지 않는다.

## 8. 구현 순서

1. 검사 허브에서 미공개·연구용 검사 숨김
2. 핵심 검사 상태에 맞춘 한 가지 다음 행동 제공
3. 별난 연구소를 놀이 의미와 한 디자인 체계로 정리
4. 시작·결과·저장·공유가 같은 공개 원장을 사용하도록 통합
5. 코어 검사의 연구 게이트와 고객용 표현 정합화
6. 주제 검사의 서버 재채점과 결과 정책 확정
7. 검증을 마친 새 검사를 한 개씩 공개
