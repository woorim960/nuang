## 0. 이번 개편의 최종 결정안

결과 리포트는 성향지도로 보내기 위한 중간 화면이 아니다. 사용자가 검사를 마친 자리에서 다음 질문에 먼저 답을 얻는 **독립된 1차 보고서**여야 한다.

1. 나는 대체로 어떤 성향인가?
2. 왜 이런 결과가 나왔는가?
3. 생활·관계·일에서는 어떻게 나타나는가?
4. 잘 작동하는 점과 막히기 쉬운 점은 무엇인가?
5. 나와 주변 사람이 어떻게 하면 더 편해지는가?

이번 개편은 아래 다섯 가지를 제품 규칙으로 고정한다.

1. 코어와 정밀 결과 모두 결과 리포트 안에서 해당 성향지도 본문의 **최소 20% 이상**을 제공한다.
2. `방향 점수`, `중심`, `경계`, `두 방향을 오간다`, `세부 신호` 같은 내부 측정 언어를 쉬운 생활 언어로 바꾼다.
3. 검사·채점·콘텐츠 버전과 내부 식별자는 데이터에는 보존하되 고객 화면에서는 제거한다.
4. 과거 결과의 측정값은 임의로 복원하지 않지만, 현재 고객에게 공개된 해당 코드의 일반 해설은 별도 콘텐츠 층으로 충분히 제공한다.
5. 성향지도는 결과 설명의 대체물이 아니라, 리포트를 충분히 읽은 뒤 남은 80%를 이어 보는 확장 콘텐츠로 둔다.

사용자 화면에는 서비스 신뢰를 스스로 낮추는 경고를 반복하지 않는다. 데이터 출처와 발행 상태의 엄격한 구분은 내부 계약과 운영센터에서 처리한다.

## 1. 현행 화면이 이렇게 만들어진 이유

### 1.1 직접 원인

현재 사용자가 보고 있는 과거 정밀 결과는 코드와 이름은 남아 있지만 다음 완료 데이터가 부족하다.

- 다섯 영역 점수의 상태와 경계 정보
- 세부 성향별 유효 응답 수
- 결과 근거 상태
- 결과 문구 버전
- 대안 코드
- 원본 결과 식별자 또는 응답 스냅샷 hash
- 결과 콘텐츠 스냅샷

`adaptAccountCoreResult`는 이 값들을 임의로 만들지 않는다. 필수값이 부족하면 결과를 `partial`로 분류하고, 현재 계약에서는 고객 가이드 섹션과 측정 섹션을 함께 닫는다. 그 결과 남는 것은 대체로 다음 세 가지다.

- 코드 overview 세 문장
- 성향지도 이동 카드
- 결과 읽는 기준

상단 목차도 실제로 표시된 섹션만 보여주므로 `한눈 요약 · 성향지도 · 읽는 기준`처럼 보인다.

### 1.2 원래 의도

기존 구현은 다음 문제를 먼저 막는 데 초점이 있었다.

- 과거 결과에 없는 점수나 세부 정보를 추정하지 않기
- 완료 당시 문장을 현재 문장으로 몰래 교체하지 않기
- 승인되지 않은 데이터센터 canonical을 고객에게 공개하지 않기
- 마이·완료 화면·공유 화면에서 서로 다른 결과가 보이지 않게 하기
- 개인 측정값이 공개 화면으로 유출되지 않게 하기

이 원칙은 유지해야 한다. 문제는 **측정 사실을 엄격히 보존하는 일**과 **현재 공개된 코드 설명을 제공하는 일**을 같은 문으로 묶어 함께 닫았다는 점이다.

### 1.3 제품 관점의 판단

기술적으로는 보수적이지만 사용자 경험으로는 불완전하다.

- 사용자는 검사 완료의 보상으로 자신에 대한 충분한 설명을 기대한다.
- 링크만 제시하면 “결과가 없어서 다른 페이지로 보낸다”고 느낀다.
- 성향지도로 이동하면 검사 결과와 일반 코드 설명의 연결이 끊긴다.
- 사용자가 가장 궁금한 강점·약점·관계·일상 설명을 다시 찾아야 한다.
- 결과 리포트의 공유·재방문·정밀 검사 전환 가치가 낮아진다.

따라서 V3는 정확성 안전장치를 없애는 것이 아니라, 측정 결과와 코드 일반 해설을 분리하여 **정확하면서도 충분한 리포트**를 만든다.

고객 공개 가이드는 32개 코드 모두 15장 구조를 가진다.

1. 핵심 모습
2. 이름의 의미
3. 다섯 글자
4. 글자 조합
5. 생각과 반응
6. 평소 생활
7. 가족
8. 친구
9. 연인
10. 마음 가는 사람
11. 일과 공부

15. 참고 근거

즉 결과 리포트가 빈약한 주원인은 콘텐츠 부재가 아니라 **현재 콘텐츠 계약과 노출 정책**이다.

### 2.2 이미 구현돼 있으나 공통 리포트에서 빠진 자산

기존 `TraitMapResultBridge`에는 다음 기능이 이미 존재한다.

- 다섯 글자 요약
- 생각과 반응
- 평소 생활
- 마음 가는 사람
- 연인
- 가족
- 친구
- 일과 공부
- 스트레스와 회복
- 코드별 preview 2,000자 이상 자동 검사

현재 통합 결과 리포트는 이 브리지를 사용하지 않고, 정밀·완전 결과에만 일부 장을 조건부로 조립한다. V3는 기존 브리지를 그대로 다시 붙이는 것이 아니라, 이 자산을 새 excerpt manifest와 공통 템플릿에 흡수한다.

### 2.3 주의할 점

32개 가이드는 고객 공개 가이드로 사용할 수 있지만 데이터센터의 `customer_approved canonical`과는 다른 콘텐츠 층이다.

- 고객 공개 가이드: 현재 제품이 코드 일반 설명으로 제공하는 콘텐츠
- 실제 측정: 이번 사용자의 답에서 계산된 점수와 세부 성향
- 승인 canonical: 전문가·근거·운영 승인을 마친 더 정밀한 개인화 문장

V3는 고객 공개 가이드를 충분히 활용한다. 승인 canonical 0건을 이유로 결과 전체를 비우지 않는다. canonical은 이후 기존 내용을 대체하지 않고 더 정밀한 강조 문장으로 보강한다.

## 3. 고객 언어 전면 교체안

### 3.1 용어 교체표

| 현재 표현                | 문제                                         | 고객용 표현                                 |
| ------------------------ | -------------------------------------------- | ------------------------------------------- |
| 결과 읽는 기준           | 규칙·주의사항처럼 들림                       | 결과를 이해하는 방법                        |
| 방향 점수                | 무엇의 방향인지 알 수 없음                   | 이번 답에서 더 가까운 쪽                    |
| 환산한 값                | 채점 과정을 알아야 이해 가능                 | 두 모습 중 어느 쪽에 가까웠는지 보여주는 값 |
| 다섯 영역                | 다섯 가지가 무엇인지 알 수 없음              | 다섯 생활 주제를 모두 풀어 쓰기             |

| 선명한 방향              | 구체적으로 무엇이 선명한지 모름              | 이번 답에서 특히 두드러진 모습              |
| 세부 신호                | 분석 시스템 용어처럼 들림                    | 구체적으로 나타난 모습                      |

| 완료 당시 기록           | 데이터 누락 안내처럼 들림                    | 고객 화면에서 제거                          |
| 검사 버전·채점 버전      | 운영 식별자이며 해석에 도움 없음             | 고객 화면에서 제거                          |

### 3.2 `결과를 이해하는 방법` 최종 권장 문안

#### 내 결과 화면

> 뉴앙은 답변을 다섯 가지 생활 주제로 나눠 살펴봐요. 사람들과 있을 때의 에너지, 무엇에 먼저 관심이 가는지, 관계에서 먼저 살피는 것, 일을 시작하고 이어가는 방식, 걱정과 감정이 커지는 속도예요.

> 각 항목은 서로 다른 두 모습 중 이번 답이 어느 쪽에 더 가까웠는지 보여줘요. 한쪽 숫자가 높다고 더 좋은 성향이거나 능력이 뛰어나다는 뜻은 아니에요.

> 두 쪽이 비슷하게 나왔다면 양쪽과 관련된 답을 비슷한 정도로 골랐다는 뜻이에요. 어느 한쪽이 뚜렷하지 않은 것도 자연스러운 결과예요.

> 이 리포트는 나의 모든 모습을 단정하는 결론이 아니라, 이번 답이 어느 모습에 더 가까웠는지 이해하기 쉽게 정리한 내용이에요.

빠른 검사에는 다음 한 문장을 덧붙인다.

> 첫 성향 검사는 나의 큰 흐름을 보여줘요. 정밀 검사에서는 같은 흐름이 생활 상황에 따라 어떻게 나타나는지 더 자세히 살펴봐요.

정밀 검사에는 다음 한 문장을 덧붙인다.

> 정밀 성향 검사는 큰 흐름과 함께 생활 속에서 구체적으로 나타난 모습도 살펴봐요.

#### 공개·공유 결과 화면

> 이 화면은 공유된 뉴앙 코드의 기본 설명만 보여줘요. 개인의 답변 내용과 점수는 결과를 만든 사람만 볼 수 있어요.

### 3.3 다섯 글자 영역의 표현 방식

기본 화면은 숫자보다 결론을 먼저 보여준다.

#### 한쪽이 비교적 뚜렷한 경우

> 이번 답에서는 사람들과 함께 있을 때보다 혼자 생각을 정리하며 회복하는 모습에 더 가까웠어요.

#### 두 쪽 값이 비슷한 경우

> 이번 답에서는 사람들과 어울릴 때와 혼자 쉴 때에 관한 답이 비슷하게 나타났어요. 어느 한쪽만 나의 모습이라고 보기는 어려워요.

값을 유지한다면 주된 제목은 `방향 점수`가 아니라 아래처럼 쓴다.

- 함께 있을 때 활력 32
- 혼자 정리하며 회복 68

보조 설명:

> 숫자는 두 모습 중 이번 답이 어느 쪽에 더 가까웠는지 비교하기 위한 값이에요. 확률·백분위·능력 점수가 아니에요.

### 3.4 고객 화면에서 숨길 정보

다음 값은 데이터·감사 로그·운영센터에는 계속 보존하되 결과 리포트 DOM에는 출력하지 않는다.

- assessment release ID
- scoring release ID
- scoring model version
- code scheme version
- result copy version
- guide version
- content version
- manifest digest
- trait map baseline ID
- canonical variant ID와 version
- section ID와 source class
- response snapshot hash
- 내부 누락 코드와 omission code
- 완료 당시 내부 프로필 이름

사용자에게 계속 보여줄 정보는 다음 정도면 충분하다.

- 검사 종류: 첫 성향 또는 정밀 성향
- 완료 날짜
- 뉴앙 코드와 현재 서비스 이름
- 실제 결과 설명
- 참고한 연구 자료

참고 자료는 `결과를 이해하는 방법`과 분리하여 `뉴앙은 무엇을 참고했나요?`라는 접힘 영역으로 둔다.

## 4. 상세지도의 20%를 정의하는 방법

글자 수만 늘려 같은 말을 반복하거나, 짧은 문단 몇 개를 가져와 20%라고 부르면 안 된다. **분량과 주제 범위**를 함께 검사한다.

### 4.1 분량 기준

`리포트에 실제 포함된 고객 가이드 본문 글자 수 ÷ 같은 가이드의 전체 비근거 본문 글자 수`

- 코어 결과: 최소 20%, 목표 20~24%
- 정밀 결과: 최소 25%, 목표 25~35%
- 공백·버튼·목차·참고문헌은 분량에서 제외
- 리포트 안의 접힌 상세 내용은 포함
- 성향지도 링크를 눌러야 보이는 내용은 포함하지 않음
- 최소 절대 분량: 공백 제외 2,000자

리포트가 상세지도의 정확히 20%에서 끊겨야 한다는 뜻은 아니다. 사용자에게 필요한 한 주제가 중간에 잘리지 않도록 완결된 문단 단위로 선택하며, 그 결과 20%를 조금 넘는 것을 허용한다.

### 4.2 주제 범위 기준

다음 여덟 주제 중 최소 일곱 주제를 리포트 안에서 다룬다.

1. 핵심 성향
2. 다섯 글자의 의미
3. 다섯 성향이 함께 작동하는 방식
4. 평소 생활
5. 일과 공부
6. 스트레스와 회복
7. 관계
8. 강점·과사용·조정

한 주제만 길게 써서 분량을 채우지 못하도록 한 주제가 결과 본문의 30%를 넘지 않게 한다.

### 4.3 읽기 시간 목표

- 코어 결과: 약 4~6분
- 정밀 결과: 약 6~9분
- 첫 10초: 코드와 핵심 모습 이해
- 첫 60초: 왜 이 코드가 나왔는지 이해
- 리포트 완독: 생활·관계·강점·주의점까지 이해

긴 내용을 모두 펼쳐 놓지 않고 핵심은 기본 노출, 세부 사례는 접힘으로 제공한다.

## 5. 결과 리포트 V3 모바일 정보 구조

상단 목차는 아이콘이나 `몇 개 섹션` 표기 없이 다음 다섯 묶음으로 제한한다.

`요약 · 내 코드 · 생활 · 관계 · 성장`

### 5.1 결과 히어로 — 10초 이해

기본 노출:

- 첫 성향 결과 또는 정밀 성향 결과
- 뉴앙 코드와 현재 이름
- 핵심 한 문장
- 완료 날짜
- 공유

히어로에는 점수표와 기술 정보를 넣지 않는다.

### 5.2 한눈에 보는 내 모습 — 기본 펼침

현재 overview를 단순히 좋은 말 세 개로 보여주지 않고 다음 흐름으로 재편한다.

1. `자연스럽게 잘하는 것`
2. `이 방식이 과해지면 생기는 일`
3. `조금 더 편해지기 위해 해볼 것`

세 문장은 서로 따로 노는 카드가 아니라 `강점 → 비용 → 조정`으로 이어져야 한다. 현재 overview만으로 비용·조정 데이터가 부족하면 고객 가이드의 `strength_and_growth`에서 이미 게시된 문단을 선택한다.

### 5.3 왜 이런 결과가 나왔을까 — 기본 펼침

다섯 글자를 사용자의 생활 질문으로 설명한다.

1. 사람들과 있을 때 에너지가 살아나는가, 혼자 있을 때 회복되는가
2. 확인된 사실과 새로운 가능성 중 무엇을 먼저 보는가
3. 관계에서 해결할 일과 상대 마음 중 무엇을 먼저 살피는가
4. 일을 계획대로 이어가는가, 그날 상황에 맞게 바꾸는가
5. 불편한 일이 생겼을 때 걱정과 감정이 천천히 또는 빠르게 커지는가

각 항목은 다음 순서로 보여준다.

- 쉬운 질문
- 이번 답에서 더 가까운 모습
- 일상에서 보이는 행동 한 문장
- 우열이나 능력 차이가 아니라는 필요한 경우의 짧은 설명
- 선택형 상세에서만 비교값

### 5.4 다섯 성향이 함께 움직이는 방식 — 기본 펼침

고객 가이드의 `core_pattern`과 `combined_pattern`에서 편집자가 고른 완결 문단을 제공한다.

단일 글자 다섯 개를 나열하는 것만으로는 사용자가 자신의 성향을 하나의 이야기로 이해하기 어렵다. 이 섹션은 다음 흐름을 설명해야 한다.

- 무엇을 먼저 알아차리는가
- 어떤 생각이 이어지는가
- 실제로 어떤 행동을 고르는가
- 잘 맞는 환경에서는 어떤 강점이 되는가
- 부담이 커질 때 무엇이 꼬이기 쉬운가

### 5.5 생활 속의 나 — 요약 공개, 상세 접힘

다음 세 장면을 우선 제공한다.

1. 평소 선택하고 움직일 때
2. 일하거나 공부할 때
3. 지치거나 긴장할 때

각 장면의 고정 구조:

- 한 줄 결론
- 구체적인 일상 장면
- 잘 작동하는 점
- 막히기 쉬운 순간
- 편해지는 방법 또는 스스로 확인할 질문

코어 결과도 코드 일반 설명으로 이 섹션을 제공한다. 다만 개인 측정처럼 쓰지 않고 `이 코드의 설명에서는 이런 생활 모습도 함께 다뤄요`라는 층을 유지한다.

정밀 결과는 실제 유효 세부 성향을 이용해 관련 장면의 우선순위를 조정할 수 있다. 점수가 없는 장면을 개인 사실처럼 만들지 않는다.

### 5.6 사람들과 지낼 때 — 선택형 상세

가족·친구·연인 장문을 한꺼번에 펼치지 않고 탭 또는 접힘으로 제공한다.

- 친구
- 연인
- 가족

각 관계의 공통 구조:

- 가까워질 때 보이는 모습
- 서운하거나 갈등이 생겼을 때
- 내가 해주기 쉬운 것
- 내가 받고 싶은 것
- 잘 통하는 말

코어 결과는 각 관계의 요약과 대표 장면을, 정밀 결과는 더 많은 완결 문단을 제공한다.

### 5.7 잘 작동할 때와 막힐 때 — 기본 펼침

결과 리포트가 모두 좋은 말만 하지 않도록 다음 네 요소를 고정한다.

1. 잘 작동할 때
2. 같은 방식을 너무 오래 밀어붙일 때 생기는 실제 비용
3. 나 또는 주변 사람이 먼저 알아차릴 수 있는 신호
4. 균형을 되찾는 작은 방법

현재 고객 가이드의 `strength_and_growth`를 기본 자료로 사용한다. 승인 canonical의 `overuse_cost`가 생기면 더 정밀한 강조 문장으로 보강한다.

### 5.8 오해받기 쉬운 순간과 잘 통하는 말

고정 구조:

- `겉으로는 이렇게 보일 수 있어요`
- `실제로는 이런 마음일 수 있어요`
- `내가 이렇게 말하면 오해가 줄어요`
- `상대가 이렇게 말해주면 편해요`

고객 가이드의 `misread_and_conversation`을 사용하며, 중요한 문장은 한 문장 공유를 지원한다.

### 5.9 이번 결과에서 생각해볼 한 가지

승인 행동 실험이 없는 상태에서 새로운 조언을 런타임으로 만들지 않는다. 대신 선택한 고객 가이드 장의 기존 `checkQuestion`을 한 개 제공한다.

예시 구조:

> 최근 비슷한 상황에서 나는 무엇을 먼저 알아차렸고, 실제로는 어떻게 행동했나요?

승인 canonical 행동 실험이 생기면 이 섹션 아래에 별도 `이번 주에 해볼 작은 실험`을 추가한다.

### 5.10 더 깊이 읽기 — 성향지도 연결

성향지도 CTA는 위 핵심 본문 뒤에 둔다.

권장 문구:

> 여기까지는 이번 결과에서 먼저 알아두면 좋은 핵심이에요. 성향지도에서는 친구·연인·가족·일·회복에 관한 더 긴 설명을 이어서 볼 수 있어요.

버튼은 막연한 `/map/{code}` 첫 화면이 아니라 현재 주제의 장으로 연결한다.

- 친구 → `#chapter-08`
- 연인 → `#chapter-09`
- 가족 → `#chapter-07`
- 일과 공부 → `#chapter-11`
- 스트레스와 회복 → `#chapter-12`
- 강점과 성장 → `#chapter-13`
- 오해와 대화 → `#chapter-14`

### 5.11 결과를 이해하는 방법·참고 자료 — 마지막 접힘

- 앞서 확정한 쉬운 문안만 제공
- 검사·채점·콘텐츠 버전 제거
- 참고 자료는 별도 접힘
- 개인정보·공유 범위는 실제 행동이 일어나는 위치에서 안내

## 6. 코어 결과와 정밀 결과의 차이

두 결과는 같은 골격을 사용한다. 코어 결과가 짧은 검사를 사용했다는 이유로 결과 리포트를 링크 모음으로 만들지 않는다.

| 항목               | 코어 결과             | 정밀 결과                                  |
| ------------------ | --------------------- | ------------------------------------------ |
| 결과 골격          | V3 전체 골격          | V3 전체 골격                               |
| 상세지도 대비 분량 | 최소 20%              | 최소 25% 권장                              |
| 개인 측정 근거     | 다섯 큰 성향          | 다섯 큰 성향 + 유효한 세부 성향            |
| 조합 설명          | 코드 일반 해설        | 코드 일반 해설 + 유효한 세부 모습 우선순위 |
| 생활 장면          | 코드의 대표 장면      | 대표 장면 + 이번 답에서 두드러진 장면      |
| 관계               | 가족·친구·연인 핵심   | 더 많은 관계 장면과 대화                   |
| 강점·비용          | 코드 수준 고객 가이드 | 코드 가이드 + 승인 개인화 문장             |
| 행동 안내          | 기존 조정 문단·질문   | 기존 조정 문단 + 승인 행동 실험            |
| 숫자               | 기본보다 결론 우선    | 결론 우선, 비교값은 선택 상세              |
| 다음 행동          | 정밀 검사·성향지도    | 주제 검사·함께하기·성향지도·공유           |

코어 결과에서 `이번 사용자가 관계에서 반드시 이렇다`고 말하지 않는다. 코드 일반 설명과 이번 응답에서 확인한 다섯 큰 성향을 시각적으로 구분하면 충분한 내용과 정직성을 함께 지킬 수 있다.

## 7. 과거 결과를 풍부하게 만드는 정책

### 7.1 세 가지 콘텐츠 층

| 층                       | 의미                                         | 과거 결과 처리                           |
| ------------------------ | -------------------------------------------- | ---------------------------------------- |
| 완료 당시 측정 사실      | 코드·저장된 점수·실제 응답 근거              | 없는 값은 만들지 않음                    |
| 현재 고객 공개 코드 해설 | 현재 서비스가 해당 코드에 제공하는 일반 설명 | 코드가 유효하면 현재 가이드 excerpt 제공 |
| 승인 개인화 canonical    | 특정 점수·맥락과 연결된 정밀 해석            | 정확한 snapshot과 승인 ref가 없으면 생략 |

### 7.2 legacy current-guide overlay

기존처럼 스냅샷이 없다는 이유로 결과 전체를 비우지 않는다.

- 유효한 5글자 코드가 있으면 현재 고객 공개 가이드의 20% excerpt를 제공
- 저장된 측정값만 표시하고 없는 점수·facet은 만들지 않음
- 코드 일반 설명을 개인의 완료 당시 측정 사실처럼 저장하지 않음
- 내부적으로 `current_guide_overlay` 해석 상태와 사용한 guide/excerpt version을 기록
- 사용자에게 복원 실패 코드나 내부 버전 경고를 노출하지 않음
- 완료 당시 점수와 현재 코드 해설의 시각적 제목을 구분

권장 제목:

- 측정 사실: `이번 답에서 나타난 모습`
- 현재 가이드: `{코드}를 더 자세히 이해하면`

### 7.3 backfill 가능 조건

원 응답과 정확한 검사·채점 release가 모두 보존된 결과만 서버에서 재검증한 뒤 snapshot을 backfill할 수 있다.

다음 경우에는 재채점하거나 값을 추정하지 않는다.

- 원 응답이 없음
- 정확한 release를 찾을 수 없음
- 문항 구조가 달라짐
- hash·원본 식별자를 확인할 수 없음

이 경우에도 코드 일반 해설은 제공할 수 있다.

## 8. Result Excerpt Manifest 설계

현재처럼 `slice(0, 2)`로 앞 문단을 기계적으로 자르지 않는다. 코드별로 결과 리포트에 사용할 완결 문단을 명시하는 불변 manifest를 둔다.

```ts
type ResultExcerptManifest = {
  code: string;
  guideVersion: string;
  excerptVersion: string;
  targetRatio: number;
  items: Array<{
    reportSection:
      | "core"
      | "five_letters"
      | "combined"
      | "daily"
      | "work"
      | "recovery"
      | "relationship"
      | "strength"
      | "misread"
      | "reflection";
    chapterSlot: TraitMapCustomerGuideChapter["slot"];
    sectionKey: string;
    paragraphKeys: string[];
    quickAllowed: boolean;
    fullAllowed: boolean;
    defaultExpanded: boolean;
    mapAnchor: string;
  }>;
};
```

### 8.1 작성 원칙

- 현재 고객 가이드의 기존 문단만 선택
- 런타임 AI 요약·자동 문장 생성 금지
- 문단 중간 자르기 금지
- 각 장·section·paragraph에 안정적인 ID 부여
- 코드별 핵심 흐름이 완결되는지 편집 검수
- 좋은 말만 남지 않도록 강점·비용·조정 균형 확인
- 한 코드의 문단을 다른 코드에 무분별하게 재사용하지 않기
- 쉬운 한국어와 중복 표현 검사

### 8.2 자동 계약 검사

32개 코드 모두 다음을 통과해야 한다.

- 코어 excerpt 20% 이상
- 정밀 excerpt 25% 이상 권장
- 최소 2,000자
- 필수 주제 7개 이상
- 한 주제 최대 30%
- 존재하지 않는 paragraph ID 0건
- guide version 불일치 0건
- 금지 내부 용어 0건
- 검사·채점·manifest ID 고객 DOM 노출 0건

### 8.3 결과 스냅샷

신규 완료 결과에는 다음을 보존한다.

- excerpt manifest digest
- guide version
- excerpt version
- 실제 표시한 section·paragraph identity
- privacy scope
- 적용 surface

완료 당시 측정·개인화 콘텐츠는 기존처럼 정확한 버전으로 재현한다. 현재 가이드를 따르는 living overlay는 별도 층으로 기록해 둘을 섞지 않는다.

### 8.4 고객 가이드 불변 아카이브

현재 스냅샷 해석기는 과거 고객 가이드 원문을 불변 상태로 보관하지 않는다. 이 상태에서 가이드가 개정되면, 이전 결과가 참조하던 version을 찾지 못해 리포트가 다시 비어 보일 수 있다.

구현 원칙:

- 현재 공개 중인 32개 코드 가이드를 version별 불변 archive로 먼저 보존
- 결과의 guide version과 excerpt manifest digest로 정확한 원문을 해석
- 가이드 개정은 이전 원문을 덮어쓰지 않고 새 version을 추가
- 운영상 공개가 철회된 내용과 현재 가이드 overlay 정책을 분리
- 정확한 과거 archive를 찾을 수 없으면 측정 기반 개인화만 닫고, 현재 공개 가이드 overlay는 유지

### 8.5 로컬 완료와 계정 저장 시점

로컬 결과를 계정으로 옮길 때만 스냅샷을 만들면, 검사 완료와 계정 저장 사이에 가이드 문구가 달라질 수 있다. 따라서 로컬 검사를 완료한 순간 다음 값을 함께 보존한다.

- guide version
- excerpt manifest digest
- 프로필 이름 release
- result copy version

계정으로 저장할 때는 이 완료 시점 기록을 서버의 불변 archive와 대조해 검증한다. 사용자가 나중에 로그인해도 완료 당시 리포트가 달라지지 않아야 한다.

### 9.1 기본 노출과 접힘

기본 펼침:

- 히어로
- 한눈에 보는 내 모습
- 왜 이런 결과가 나왔을까
- 다섯 성향이 함께 움직이는 방식
- 잘 작동할 때와 막힐 때

요약 노출 후 상세 접힘:

- 평소 생활
- 관계별 상세
- 일과 공부
- 스트레스와 회복
- 오해와 대화
- 참고 자료

사용자가 리포트의 핵심을 보기 위해 모든 아코디언을 열 필요는 없어야 한다.

### 9.2 시각 위계

- 뉴앙의 기존 부드러운 표면·여백·타이포 체계 사용
- 섹션마다 장식용 아이콘을 붙이지 않음
- `10개 섹션` 같은 구조 숫자를 고객에게 표시하지 않음
- 카드를 과도하게 중첩하지 않음
- 제목 → 한 줄 결론 → 구체 장면 → 조정 순서 유지
- 긴 문단은 2~3문장 단위로 나눔
- 공유·피드백 버튼은 본문보다 시각적으로 앞서지 않음

### 9.3 접근성

- 320~430px에서 가로 넘침 없음
- 44px 이상 터치 목표
- 200% 확대에서도 본문과 탭 사용 가능
- 관계 탭과 다섯 글자 탭의 키보드 이동 지원
- 색만으로 더 가까운 쪽을 구분하지 않음
- 접근성 문장에도 `방향 점수` 같은 제거 대상 용어를 사용하지 않음
- 동작 줄이기 설정 존중

## 11. 피드백과 자동 개선

별도 긴 설문을 추가하지 않는다. 기존 리포트 문장 피드백 구조를 사용한다.

- `나와 비슷해요`
- `상황에 따라 달라요`
- `나와 달라요`
- 선택 이유: 상황 차이, 너무 넓은 표현, 문구가 어려움, 중요한 내용 누락 등

V3에서는 다음 section에만 최대 3회 피드백을 배치한다.

1. 핵심·조합 설명
2. 강점과 막힘
3. 오해와 대화

문구 이해도는 `wording_unclear` 신호로 자동 집계한다. 리뷰 요청을 늘리지 않고 실제 리포트를 읽는 과정 자체가 개선 자료가 되게 한다.

자동으로 가능한 일:

- content version별 적합도 집계
- 이해 어려움·중요 내용 누락 반복 감지
- 우선 검토 후보 생성
- 이전·새 문장 반응 분리

자동으로 하면 안 되는 일:

- 문장 자동 발행
- 표본이 적은 비율로 검사 정확도 선언
- 사용자 피드백만으로 측정 구조 변경
- 전문가 검토 없이 과사용·행동 조언 추가

## 17. 구현 완료 및 품질 점검 기록

### 17.1 P0 · 쉬운 언어

- `결과를 이해하는 방법` 최종 문안을 공통 템플릿에 적용했다.
- 다섯 생활 주제를 실제 이름으로 풀어 쓰고, 비슷한 값은 `양쪽과 관련된 답을 비슷하게 골랐다`고 설명한다.
- 검사·채점·콘텐츠·가이드 version과 내부 ID를 고객 DOM에서 제거했다.
- 숫자는 두 모습의 비교값이며 확률·순위·능력 점수가 아니라는 설명을 적용했다.
- 고객 가이드 원문과 snapshot은 바꾸지 않으면서, 화면에서만 편집용 중복 접두어와 이어 붙은 문장부호를 자연스럽게 정리한다.

### 17.2 P1 · 독립된 1차 결과 보고서

- 32개 공개 코드 가이드의 version archive 조회 계약을 추가했다.
- `nuang-core-result-excerpt.v1` manifest와 결정적 digest를 구현했다.
- 코어는 최소 20%, 정밀은 최소 25%, 공백 제외 최소 2,000자를 자동 검사한다.
- 13개 핵심 장을 고르게 선택하고 한 주제가 선택 본문의 30%를 넘지 않게 한다.
- `강점과 성장` 장은 강점·과사용 비용·균형·성장 문단 전체를 보장하고, `오해와 대화`는 모든 소주제를 최소 한 문단씩 보장한다.
- 첫 요약을 `자연스럽게 잘하는 것 → 과해지면 생기는 일 → 조금 더 편해지는 방법`의 직설적인 흐름으로 재구성했다.
- 조합 패턴, 생활, 관계, 강점과 비용, 오해와 대화, 자기 점검 질문을 하나의 공통 리포트에 넣었다.

### 17.3 P2 · 과거 결과와 완료 시점 무결성

- 유효한 과거 5글자 코드는 없는 점수나 facet을 만들지 않고 현재 공개 가이드로 충분한 리포트를 제공한다.
- 완료 snapshot과 현재 가이드 fallback을 별도 해석 상태로 분리했다.
- 결과 snapshot에 정확한 `guideVersion`과 `excerptManifestDigest`를 보존한다.
- 계정 저장은 완료 snapshot을 사용하고, 로컬 완료는 응답 hash를 대조해 snapshot을 한 번만 원자적으로 부착한다.
- archive 또는 manifest를 정확히 찾지 못하면 측정 개인화는 닫고 현재 공개 가이드 fallback만 사용한다.

### 17.4 P3 · 모바일 UX

- 완료 결과·마이 최신 결과·계정 결과·공개 결과가 `CoreResultReportTemplate` 하나를 사용한다.
- 목차는 `요약 · 내 코드 · 생활 · 관계 · 성장` 다섯 항목으로 제한했다.
