## 0. 이 문서의 결정

Release 2의 제품 기반은 구현했지만, 다음을 실제 데이터 없이 완료됐다고 말하지 않는다.

- 성향 검사의 신뢰도·재검사 안정성·구조 타당성
- 연령·성별 등 집단 사이의 측정 동등성·DIF
- 32개 코드 이름의 이해도와 구분 가능성
- 데이터센터 canonical 문장의 고객 공개 적합성
- 코드·facet별 과사용 비용과 작은 행동 실험의 유용성

사용자 화면에는 서비스를 스스로 깎아내리는 경고 문구를 반복하지 않는다. 대신 내부 운영과 발행 단계에서 근거 수준을 엄격히 구분하고, 근거가 없는 수치·문장만 고객 화면에 내보내지 않는다.

별도 `파일럿 검사`, 별도 `인지 면접 검사`를 사용자에게 추가하지 않는다. 공개된 검사를 하는 과정 자체가 문항 이해·응답 수정·결과 적합도·재검사 데이터를 만드는 구조여야 한다. 필요한 추가 질문은 일부 사용자에게만, 본래 흐름 안에서, 짧고 건너뛸 수 있게 제공한다.

자동화의 목표는 `자동 발행`이 아니라 아래 흐름이다.

`관찰 → 이상 신호 집계 → 수정 후보 생성 → 전문가 검토 → 제한 노출 → 실제 반응 확인 → 운영 승인 → 새 버전 발행`

## 2. 외부 기준을 적용하는 방식

뉴앙은 의료 진단 도구가 아니지만, 자기보고형 측정도구를 다루는 원칙은 검증된 측정 표준에서 가져온다.

- [Standards for Educational and Psychological Testing](https://www.testingstandards.net/): 타당성은 검사 자체에 붙는 영구 인증이 아니라 특정 점수 해석과 사용 목적을 지지하는 누적 근거로 관리한다.
- [COSMIN Study Design Checklist](https://www.cosmin.nl/wp-content/uploads/COSMIN-study-designing-checklist_final.pdf): 내용 타당성, 구조 타당성, 내적 일관성, 신뢰도·측정오차, 측정 동등성을 각각 다른 설계와 분석으로 확인한다.
- [COSMIN 측정 연구 자료](https://www.cosmin.nl/finding-right-tool/conducting-study-measurement-properties/): 신뢰도 연구의 표본 수는 하나의 고정 숫자가 아니라 목표 ICC, 정밀도, 반복 측정 설계에 따라 정한다.
- [NIH PROMIS Qualitative Item Review](https://pmc.ncbi.nlm.nih.gov/articles/PMC2810630/): 문항의 맥락, 문장 본체, 응답 척도, 시간 범위, 원 출처를 함께 관리하고 중복·모호함을 체계적으로 줄인다.

뉴앙의 32개 코드는 사람이 자연적으로 32개 상자에 정확히 나뉜다는 주장을 하지 않는다. 분석의 기본 단위는 연속적인 5개 축과 10개 facet이며, 5글자 코드는 사용자가 결과를 기억하고 이야기하기 위한 제품 표현으로 검증한다.

## 3. 구축해야 할 데이터 묶음

### D1. 문항 경험 데이터

문항별로 다음 신호를 수집한다.

- 문항 ID·instrument version·제시 순서
- 응답 완료 여부
- `문구가 어려움`, `비슷한 경험 없음`, `상황에 따라 다름`, `응답하고 싶지 않음`
- 응답 수정 횟수 bucket
- 고민 시간 bucket
- 검사 중단 위치
- 기기 너비·언어·시간대 같은 최소 기술 맥락

직접 응답 원문을 품질 대시보드에 복사하지 않는다. 운영센터는 집계 신호를 우선 보고, 연구 분석용 원 응답은 별도 권한과 보관 기간을 적용한다.

### D2. 심리측정 응답 데이터

분석에 필요한 최소 열은 다음과 같다.

- 익명화된 participant/account study key
- assessment attempt ID
- item ID·revision·release ID
- ordinal response
- 응답 시각·완료 시각
- scoring model·code scheme version
- 누락·유효 응답 상태
- 5개 domain과 10개 facet의 산출 점수
- 동일 사용자의 재검사 연결 key와 간격

분석 dataset에는 닉네임, 이메일, 전화번호, 게시물 내용, 자유서술을 넣지 않는다.

### D3. 문장별 결과 적합도

`report.core_result_feedback`에 다음을 버전 고정으로 저장한다.

- 결과 소유 계정과 result report ID
- profile code·quick/full
- section ID·content key·content version
- manifest digest·trait map baseline
- `fit / depends / not_fit`
- 선택적 이유
- 노출 surface와 접수·검토 상태

같은 사용자가 같은 결과의 같은 section을 다시 평가하면 새 행을 무한히 추가하지 않고 최신 응답으로 갱신한다.

V3 결과 리포트의 운영 우선순위는 다음 세 section이다.

- `profile_overview`: 강점 → 과해질 때의 비용 → 조정 방법
- `strength_and_overuse`: 강점·과사용·균형·성장 전체
- `misread_and_conversation`: 오해·실제 의도·잘 통하는 말

생활·관계·일·회복 section에도 피드백 버튼을 계속 추가하지 않는다. 위 세 section의 반복 신호와 `중요한 내용 누락` 이유를 가이드 전체 수정 후보로 사용한다.

### D4. 코드 이름 검증 데이터

32개 이름별로 다음을 본다.

- 한 번 읽고 어떤 사람인지 이해되는가
- 1글자만 다른 이웃 코드 이름과 구분되는가
- 부정적 낙인·능력·도덕성·성별 고정관념으로 오해되는가
- 7일 뒤 이름 또는 핵심 의미를 기억하는가
- 친구에게 공유하고 싶은가
- 이름과 본문 설명이 같은 방향을 말하는가

모든 사용자에게 매번 묻지 않는다. 신규 이름 릴리스 노출자 중 작은 무작위 비율에 한 번만 제시하고, 결과 읽기 흐름 안에서 1~2문항으로 끝낸다.

### D5. canonical 고객 발행 데이터

문장 하나의 최소 레코드는 다음을 모두 가져야 한다.

- `contentKey`
- `canonicalVariantId`와 정확한 숫자 version
- 적용 코드·축·facet·맥락
- claim kind와 placement
- 원 연구·독립 근거 ID
- 고객용 한국어 문장
- privacy scope와 허용 surface
- 위험 영역
- 7개 역할별 결정과 검토 메모
- 쉬운 한국어·중복·재조합 감사 결과
- publication state와 manifest digest

### D6. 과사용 비용과 행동 실험

과사용 비용은 단점을 낙인찍는 문장이 아니라 `어떤 강점이 어떤 조건에서 어떤 비용으로 바뀌는가`를 설명해야 한다.

필수 구조:

1. 평소 강점
2. 과해지는 촉발 조건
3. 관찰 가능한 행동
4. 자신 또는 타인에게 생기는 비용
5. 반례·상황 의존성

행동 실험은 다음 조건을 모두 지킨다.

- 한 번의 구체적인 상황에서 5분 안에 시작 가능
- 성격을 바꾸라는 명령이 아니라 다른 선택을 시험하는 제안
- 성공·실패 대신 관찰할 신호가 있음
- 의료·법률·금융·관계 단절 같은 고위험 결정을 유도하지 않음
- 사용자가 원치 않으면 건너뛸 수 있음
- 실행 전후에 무엇이 달랐는지 짧게 확인 가능

## 4. 공개 서비스 안에서 수집하는 흐름

### 4.1 검사 중

사용자의 기본 행동은 문항에 답하는 것이다. 추가 품질 신호는 다음처럼 흐름에 묻는다.

- `판단 어려움`을 누른 경우에만 가장 가까운 이유 한 개 선택
- 답을 여러 번 바꾸거나 오래 머문 사실은 bucket으로 자동 기록
- 같은 문항에서 반복적으로 이해 어려움이 높아지면 운영센터 우선 검수
- 피드백을 선택하지 않아도 다음 문항으로 정상 진행

### 4.2 결과를 읽는 중

- 핵심 모습, 강점과 과사용, 오해와 대화의 최대 3개 section만 평가
- `나와 비슷해요`는 한 번 탭으로 완료
- `상황에 따라 달라요 / 나와 달라요`는 선택적 이유를 한 번 더 묻기
- 완료 시점 content key·version이 서버 저장본과 같을 때만 수용
- 하나의 긍정 비율을 전체 검사의 타당성으로 해석하지 않음

### 4.3 재검사

별도 연구 검사를 강요하지 않는다.

- 사용자가 14~30일 뒤 자발적으로 같은 release를 다시 완료하면 재검사 후보로 연결
- 너무 짧은 반복은 기억 효과 때문에 본 분석에서 분리
- release가 바뀐 반복은 안정성 분석이 아니라 버전 비교로 분리
- 재검사 권유는 앱 전체에서 반복하지 않고, 연구 동의자에게 제한된 빈도로만 노출

### 4.4 이름·문장 이해

- 전체 노출자의 작은 비율만 무작위 선택
- 한 세션에서 한 종류의 품질 질문만 제시
- 검사 완료 직후는 즉시 이해, 7일 이후 재방문은 회상으로 분리
- 자유서술은 초기 기본값으로 사용하지 않고, 필요한 경우 별도 동의·보관 정책을 먼저 마련

## 5. 표본 운영 목표

아래 숫자는 `이 숫자를 넘으면 검증 완료`라는 법칙이 아니다. 분석을 시작하고 정밀도를 확인하기 위한 뉴앙의 운영 목표다. 최종 판단은 신뢰구간, 모형 적합도, 항목 분포, subgroup 크기와 누락률을 함께 본다.

| 단계                |                                                   시작 목표 | 용도                                        | 이 단계에서 금지되는 결론             |
| ------------------- | ----------------------------------------------------------: | ------------------------------------------- | ------------------------------------- |
| 데이터 배관 점검    |                                             유효 완료 200건 | 누락·중복·문항별 분포·이벤트 연결 확인      | 신뢰도·타당성 홍보                    |
| 1차 구조 탐색       |                                      정밀 완료 1,000건 이상 | ordinal EFA/CFA 후보·문항 품질·축 상관 확인 | 32유형 실재 주장                      |
| 독립 구조 확인      |                          이후 비중복 정밀 완료 1,000건 이상 | 고정한 모형의 holdout 확인                  | 탐색 표본과 합친 적합도만 제시        |
| 재검사              |                  같은 release 300쌍 이상을 시작 목표로 설계 | 점수·축 방향·코드 안정성과 측정오차         | 짧은 간격 반복을 일반 안정성으로 확대 |
| DIF·측정 동등성     | 비교 집단별 300건 이상, 전체 2,000건 이상을 시작점으로 검토 | 성별·연령대 등 항목 기능 차이               | 표본이 작은 집단을 문제없다고 선언    |
| 문장 적합도 관찰    |                                   코드·section·version 30건 | 심각한 불일치 조기 감지                     | 문장 승격                             |
| 문장 제한 승격 검토 |                             코드·section·version 100건 이상 | 적합·상황 차이·반례 패턴 검토               | 전문가 승인 없는 자동 발행            |

희귀 코드 때문에 32개 코드별로 같은 표본을 억지로 맞추지 않는다. 심리측정 분석은 축·facet과 문항을 우선하고, 코드별 문장 분석은 표본이 쌓인 범위만 표시한다.

## 6. 분석 계획

### 6.1 분석 전 고정할 것

- 포함·제외 기준
- 지원 release와 문항 revision
- 중복 attempt 처리
- 너무 짧은 완료·연속 동일 응답·과도한 누락의 처리
- 탐색 표본과 확인 표본 분리 seed
- 기본 모형과 대안 모형
- 1차·2차 지표
- 다중 검정 보정과 DIF effect size 기준
- 분석 실패 시 수정 가능한 범위

이 항목을 분석 결과를 본 뒤 유리하게 바꾸지 않는다. 변경 시 새 분석 version과 이유를 남긴다.

### 6.2 데이터 품질

- 문항·척도 선택지별 빈도와 바닥/천장 효과
- 문항별 누락률과 중단률
- 응답 시간 분포와 비현실적 속도
- long-string, 반복 pattern, 응답 수정
- 같은 기기·세션의 중복 제출
- release ID·문항 수·score snapshot 불일치

빠르게 답했다는 이유 하나만으로 사용자를 제외하지 않는다. 여러 신호를 결합한 사전 규칙을 사용하고, 포함/제외 두 분석의 민감도를 함께 본다.

### 6.3 구조 타당성

- Likert 응답을 연속 정규값으로 단순 취급하지 않고 ordinal 상관과 적절한 추정법을 사용
- 5개 domain·10개 facet의 사전 구조를 CFA로 확인
- 탐색 표본에서 EFA/parallel analysis를 보조로 실행
- 한 문항이 여러 축에 걸쳐 강하게 작동하는지 확인
- 수정지수만 보고 문항을 반복 삭제하지 않고 문항 의미와 근거를 함께 검토
- holdout 표본에서 동일 모형을 다시 확인

### 6.4 신뢰도와 오차

- 축·facet별 omega 중심 보고, alpha는 비교용 보조 지표
- 전체 문항을 하나의 alpha로 합쳐 다차원 검사를 단일 척도처럼 설명하지 않음
- 재검사에서는 연속 점수 ICC·상관, 축 방향 일치, 경계 구간 이동을 함께 확인
- 점수 차이가 측정오차 범위 안인지 볼 수 있도록 SEM과 필요 시 최소 변화 기준을 내부적으로 계산
- 표본과 근거가 충분하기 전에는 고객에게 `정확도 95%` 같은 표현을 사용하지 않음

### 6.5 수렴·판별·기준 관련 근거

- 5개 축과 개념적으로 가까운 한국어 검증 척도를 사전에 선택
- 사용할 도구의 저작권·상업 이용·번역 권한을 먼저 확인
- 가까운 구성개념은 중간 이상의 관련, 다른 구성개념은 낮은 관련이라는 방향 가설을 분석 전에 기록
- 친구 수, 연애 성공, 업무 능력 같은 결과를 성향 점수의 단순 기준으로 삼지 않음
- 자기보고 한 번만으로 실제 행동을 증명했다고 표현하지 않음

### 6.6 측정 동등성·DIF

- 연령대, 성별, 검사 기기, 첫 검사/재검사 등 사전에 정한 집단만 분석
- 인구통계 정보는 선택적 연구 동의와 목적·보관 기간을 먼저 정의
- configural → loading/threshold 동등성 순으로 확인
- ordinal logistic 또는 IRT DIF를 사용하고 p-value뿐 아니라 effect size를 함께 봄
- 집단별 표본이 부족하면 `문제 없음`이 아니라 `판단 보류`로 기록
- DIF가 발견되면 문항 의미·번역·맥락을 검토하고 점수 비교에 미치는 영향을 simulation으로 확인

### 6.7 코드 안정성

- 5글자 전체 일치율만 보지 않고 각 축의 점수 차이와 경계 여부를 함께 봄
- 45~55 경계에 있던 사용자의 코드 이동을 측정 실패로 단정하지 않음
- 안정성은 `축별 점수`, `축 방향`, `전체 코드` 세 수준으로 보고
- 이름 회상률과 코드 안정성을 분리

## 7. 713개 canonical 검토 순서

713개를 같은 우선순위로 한 번에 검토하지 않는다.

### 7.1 P0 — 결과 첫 화면

첫 공개 목표는 코드별 다음 5개 이내다.

- 핵심 해석 1개
- 과사용 비용 2개
- 작은 행동 실험 2개

32개 코드 기준 최대 160개 claim부터 시작한다. 동일한 canonical을 여러 코드가 공유할 수 있으므로 실제 고유 문장 수는 줄어들 수 있다.

### 7.2 P1 — 생활 맥락

- 관계·업무·회복 장면의 직접 근거가 있는 문장
- 1,321개 미확립 맥락 전이와 101개 동일 맥락 finding 부재 항목을 우선 분리
- 가족·친구·연인·업무를 개인의 확정 행동처럼 말하지 않음

### 7.3 P2 — 성향지도 상세

- 결과 첫 화면과 중복되지 않는 설명
- 반례와 상황 조건
- 이웃 코드와의 차이를 한 축 이상 명확히 설명

### 7.4 7개 역할의 책임

| 역할          | 승인 질문                                                 |
| ------------- | --------------------------------------------------------- |
| 성격심리      | 구성개념과 문장이 맞고 유형 낙인을 만들지 않는가          |
| 심리측정      | 점수·축·facet이 허용하는 해석 범위인가                    |
| 연구방법      | 근거와 맥락 전이가 추적 가능하고 반례가 있는가            |
| 쉬운 한국어   | 한 번 읽고 이해되며 추상 명사·전문 용어가 적은가          |
| 안전·개인정보 | 진단·능력·도덕성 단정, 민감 추론, 공개 범위 문제가 없는가 |
| 제품 콘텐츠   | 핵심이 분명하고 반복이 적으며 다음 행동과 연결되는가      |
| 데이터 품질   | ID·version·출처·코드 적용·manifest가 재현 가능한가        |

AI 에이전트는 중복·금칙어·근거 누락·이웃 모순·쉬운 문장 사전 점검을 할 수 있다. 전문 역할의 최종 `approve`를 AI 결과로 대체하지 않는다.

## 8. 발행 게이트

문장은 아래를 모두 통과해야 `customer_approved` 후보가 된다.

1. canonical lineage와 source version 존재
2. 적용 코드·축·facet이 유효
3. evidence finding 최소 1개
4. 고위험 문장은 독립 근거 2개 이상
5. 7개 역할 모두 approve
6. 쉬운 한국어 통과
7. 재조합·중복 감사 통과
8. 허용 surface와 privacy scope 일치
9. 제한 노출에서 심각한 오해·불일치 중단 기준 미충족
10. 운영 책임자의 manifest 발행 승인
11. 32개 코드의 코어 20%·정밀 25%·최소 2,000자·주제 30% 이하 통과
12. 강점과 성장 장 전체 및 오해와 대화의 모든 소주제 포함
13. 완료 snapshot의 guide version·excerpt digest 복원과 공개 범위 회귀 통과

새 manifest는 기존 digest를 수정하지 않고 추가한다. 과거 결과가 참조한 manifest, 이름 release, 고객 가이드 version, canonical version은 불변 아카이브에 남긴다.

- 계획한 집단의 측정 동등성·DIF가 판단 가능하거나 판단 보류로 명시됨
- 32개 이름의 이해·구분·오해 데이터가 존재함
- 실패 시 이전 manifest로 rollback 가능함
- 고객 화면에는 승인된 범위만 표시되고 연구 원문·운영 진단·비공개 신호가 유출되지 않음

완료는 `검사가 완벽하다`는 선언이 아니다. 같은 계약으로 새 표본과 새 release를 계속 검토할 수 있는 상태를 의미한다.
