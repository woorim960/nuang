# 뉴앙 밸런스게임 사용자 경험 개편 기획서

## 1. 목표

- 주제를 찾고 방을 만드는 과정의 역할을 화면 단위로 분리한다.
- 좌우 50:50 선택의 즉시성은 유지하면서 뉴앙의 보랏빛과 따뜻한 색감을 살린다.
- 마지막 선택 뒤 결과 준비 또는 결과 리포트로 반드시 흐름이 이어지게 한다.
- 매 선택과 화면 이동에서 불필요한 전체 데이터 조회를 줄여 체감 지연을 낮춘다.
- 모바일 360px부터 데스크톱까지 같은 정보 우선순위와 접근성을 유지한다.

## 2. 최종 정보 구조

1. `/assessments/together/balance-game`
   - 서비스 가치 제안
   - 참여 코드 입장
   - `전체 / 지금 많이 하는 / 취향 / 관계 / 재미` 주제 탐색
2. `/assessments/together/balance-game/setup?pack={slug}`
   - 선택한 주제 확인
   - 닉네임, 인원, 문항 수, 참여 방식, 방 이름 설정
   - 방 생성 및 초대 준비 화면으로 이동
3. `/assessments/together/balance-game/rooms/{code}`
   - 초대, 참여, 게임 시작
   - 좌우 50:50 문항 선택
4. `/assessments/together/balance-game/rooms/{code}/result`
   - 다른 참여자를 기다리는 결과 준비 상태
   - 그룹 점수, 일치/갈림 문항, 1:1 비교, 공유가 포함된 결과 리포트

기존 `?pack={slug}` 진입 링크는 별도 방 설정 화면으로 리다이렉트해 호환성을 유지한다.

## 3. UX 원칙

- **한 화면, 한 결정:** 메인은 주제 선택, 설정 화면은 방 구성, 러너는 현재 문항에만 집중한다.
- **설명보다 반응:** 선택 즉시 색과 깊이가 변하고 다음 문항으로 넘어간다. 저장은 백그라운드에서 진행한다.
- **기다림도 다음 단계:** 마지막 선택 뒤에는 빈 정지 상태 대신 결과 준비 화면과 현재 참여 현황을 보여준다.
- **성숙한 표현:** 장식용 아이콘과 작은 카드를 반복하지 않는다. 큰 타이포그래피, 여백, 색의 대비로 위계를 만든다.
- **결과는 대화의 시작:** 점수만 강조하지 않고 함께 맞은 선택과 갈린 선택을 먼저 읽을 수 있게 한다.

## 4. 시각 언어

- 기본 바탕은 회색 대신 아주 옅은 라벤더와 크림 톤을 사용한다.
- 좌측 선택은 보라/라벤더, 우측 선택은 코랄/피치 계열로 구분한다.
- 선택 전에는 두 영역의 무게를 같게 유지하고, 선택 순간에만 채도·테두리·깊이가 짧게 변한다.
- 캐릭터나 유아적인 장식 삽화는 사용하지 않는다. 필요한 장식은 CSS 기반의 추상 그라디언트와 선으로 제한한다.
- `prefers-reduced-motion`에서는 전환 애니메이션을 제거한다.

## 5. 상태와 예외

- 방 생성: 중복 제출 방지, 로그인 필요 상태에서 입력 초안 보존, 실패 시 같은 요청 ID로 재시도한다.
- 문항 저장: 빠른 연속 탭을 잠그고 낙관적으로 다음 문항을 보여준다. 실패한 문항으로 돌아가 명시적으로 재시도할 수 있다.
- 마지막 문항: 모든 저장이 끝나면 완료 API를 한 번만 호출하고 결과 경로로 전환한다.
- 결과 대기: 두 명 미만 완료 시 결과 경로에서 초대와 참여 진행률을 제공한다.
- 만료/퇴장/권한 오류: 재시도 가능 여부와 다음 행동을 함께 제시한다.

## 6. 성능 기준

- 메인 주제 목록은 서버 콘텐츠 조회 결과를 짧게 캐시한다.
- 동적 방 경로에는 즉시 보이는 로딩 셸을 제공한다.
- 문항 저장 응답은 전체 방 상태 대신 저장 확인 정보만 반환한다.
- 활성 플레이 중에는 불필요한 5초 전체 상태 폴링을 중단하고, 대기·결과 화면에서만 폴링한다.
- QR 라이브러리는 사용자가 요청할 때만 동적 로드한다.

## 7. 완료 조건

- 카테고리 문구가 정확히 `전체 / 지금 많이 하는 / 취향 / 관계 / 재미`로 표시된다.
- 주제 카드 선택 시 모달이 아니라 별도 방 설정 경로로 이동한다.
- 최종 선택 완료 후 URL이 결과 경로로 바뀌며 대기 또는 결과 리포트가 표시된다.
- 저장 실패, 완료 실패, 새로고침 복구 테스트가 통과한다.
- 모바일/데스크톱에서 가로 스크롤 없이 모든 주요 조작의 터치 영역이 44px 이상이다.
- 타입 검사, 린트, 관련 단위 테스트, 빌드, 브라우저 사용자 흐름 검증을 통과한다.
