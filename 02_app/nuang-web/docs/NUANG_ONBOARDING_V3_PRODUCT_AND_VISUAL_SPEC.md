# 뉴앙 첫 진입 온보딩 V3 제품·비주얼 기획서

- 문서 상태: 구현 기준 확정
- 기준일: 2026-08-03
- 대상 화면: `/`, `/home`, `/onboarding`
- 대체 문서: `NUANG_CODED_ONBOARDING_V2_PRODUCT_SPEC.md`
- 한 문장 목표: 처음 온 사용자가 15~20초 안에 `다섯 글자 뉴앙코드로 나와 서로를 더 자세히 이해하는 성향 놀이터`라는 가치를 이해하고 바로 검사를 시작하게 한다.

## 1. 현행 진단

현행 V2는 가로 넘침을 막았지만 고객이 기대하는 일러스트 온보딩에는 미치지 못한다.

1. 네 화면 모두 같은 정면 3D 캐릭터를 재사용해 장면마다 행동과 감정이 달라 보이지 않는다.
2. 캐릭터 동작은 짧은 위치 이동뿐이라 실제 행동이 아니라 같은 피규어를 옮겨 놓은 인상이다.
3. 큰 기능 카드와 보드가 캐릭터보다 강해 첫인상이 앱 가이드보다 대시보드에 가깝다.
4. 첫 화면이 뉴앙의 차별점보다 `성향 검사·함께하기·성향지도` 메뉴를 먼저 설명한다.
5. 그림보다 카피가 먼저 나와 첫 3초의 시각적 후킹이 약하다.
6. 낮은 화면에서 모든 요소를 같은 비율로 압축해 넘치지는 않아도 캐릭터와 여백의 균형이 무너진다.
7. 완료 판정이 가이드 버전과 결합돼 있어 버전을 올리면 기존 사용자가 다시 자동 진입할 위험이 있다.

## 2. 제품 원칙

### 2.1 반드시 전달할 가치

- 뉴앙은 성향 검사가 중심인 서비스다.
- 네 글자 유형만으로 아쉬웠던 부분을 다섯 가지 성향의 조합으로 더 자세히 살펴본다.
- 코드만 보여주지 않고 생각·감정·관계·생활 속 모습을 이해하기 쉽게 설명한다.
- 친구·연인·가족과 결과를 비교해 비슷한 점과 서로 배려할 점을 찾을 수 있다.
- 첫 검사는 로그인 없이 짧게 시작할 수 있다.

### 2.2 표현 원칙

- `MBTI보다 과학적으로 우수하다`처럼 별도 검증이 필요한 우월 표현은 사용하지 않는다.
- 대신 `네 글자만으로는 아쉬웠던 나`, `한 가지 유형보다 자세하게`처럼 고객이 바로 이해하는 언어를 사용한다.
- `빠른 코어`, `방향점수`, `signal`, `공식 코드 릴리스` 같은 내부 용어를 고객 화면에 노출하지 않는다.
- 문장은 제목 2줄, 설명 2~3줄 안에 이해되게 쓴다.
- 그림 안에는 텍스트와 가짜 점수·가짜 리포트 수치를 넣지 않는다.

## 3. 확정 정보 구조

네 장으로 유지한다. 다섯 장 이상은 검사 진입을 늦추고, 세 장 이하는 자기이해와 관계 가치를 함께 설명하기 어렵다.

### G01 — 첫 5초 후킹

- 눈썹말: `성향 놀이터, 뉴앙`
- 제목: `나를 이해하고,\n서로를 이해하는 시작`
- 설명: `네 글자만으로는 아쉬웠던 나를, 다섯 글자 뉴앙코드로 더 자세히 알아봐요.`
- 기억할 말: `뉴앙은 나와 서로를 더 잘 이해하는 곳이다.`
- 일러스트: 보라 캐릭터가 한 가지 모양의 틀에서 힘차게 뛰어나오고 다섯 색 성향 조각이 펼쳐진다.
- 포즈: 몸을 앞으로 기울인 도약, 한 팔은 환영하듯 위로, 양다리는 서로 다른 높이.
- 장면 모션: 틀 열림 → 캐릭터 도약 → 다섯 조각 펼침 → 최종 포즈 정지.

### G02 — 검사와 결과의 깊이

- 눈썹말: `한 가지 유형보다 자세하게`
- 제목: `생각·감정·관계 속\n내 모습을 한눈에`
- 설명: `다섯 가지 성향을 조합해 내 코드를 만들고, 생활에서 드러나는 특징까지 알려드려요.`
- 기억할 말: `코드만 주는 검사가 아니라 실제 내 모습을 설명해준다.`
- 일러스트: 캐릭터가 몸을 기울여 돋보기로 다섯 성향 조각을 살펴보고, 조각이 하나의 결과 티켓으로 모인다.
- 포즈: 옆으로 숙인 탐색 자세, 한 손은 돋보기, 다른 손은 결과를 가리킨다.
- 장면 모션: 돋보기 탐색 → 다섯 조각 순차 점등 → 결과 티켓 펼침 → 정지.

### G03 — 관계 가치

- 눈썹말: `다름을 알면 오해가 줄어요`
- 제목: `가까운 사람과\n더 잘 지내는 방법`
- 설명: `친구·연인·가족과 결과를 비교해, 잘 맞는 점과 서로 배려할 점을 알아봐요.`
- 기억할 말: `다름을 틀림으로 보지 않고 관계에 활용할 수 있다.`
- 일러스트: 보라·초록 캐릭터가 양쪽에서 다리 조각을 들고 만나 연결한 뒤 하이파이브한다.
- 포즈: 두 캐릭터 모두 측면 보행 자세, 서로 다른 팔·다리 실루엣.
- 장면 모션: 양쪽에서 접근 → 조각 연결 → 짧은 하이파이브 → 정지.
- 금지: 가짜 궁합 점수, 우열 표현, 한 캐릭터가 다른 캐릭터를 끌고 가는 모습.

### G04 — 즉시 행동

- 눈썹말: `첫 결과까지 약 3~5분`
- 제목: `가볍게 답하고,\n내 첫 결과를 확인해요`
- 설명: `로그인 없이 바로 시작할 수 있어요. 로그인하면 다른 기기에서도 결과를 이어볼 수 있어요.`
- CTA: `내 뉴앙코드 알아보기`
- 기억할 말: `지금 부담 없이 시작할 수 있다.`
- 일러스트: 캐릭터가 달려와 커다란 선택 버튼을 누르면 다섯 칸 코드 티켓이 열린다.
- 포즈: 한 다리를 든 달리기 자세, 몸은 전진 방향으로 기울고 한 손은 선택 버튼을 누른다.
- 장면 모션: 짧은 달리기 → 선택 → 코드 티켓과 축하 조각 등장 → 정지.
- 운영 조건: 실제 모바일 완료시간 p90이 5분을 넘으면 시간 표현을 `짧은 검사로`로 교체한다.

첫 세 장의 주 버튼은 모두 `다음`으로 통일한다. 마지막 장에서만 가치 중심 CTA를 사용한다.

## 4. 일러스트 시스템

### 4.1 스타일

- 전용 2D 에디토리얼 일러스트를 장면별로 새로 제작한다.
- 뉴앙 정체성인 보라색, 불꽃 모양 머리, 둥근 몸, 큰 눈과 볼을 유지한다.
- 기존 3D 피규어 광택 대신 부드러운 평면색과 약한 종이 질감, 2단계 음영을 사용한다.
- 진한 검정 윤곽 대신 보라 계열의 부드러운 외곽선을 쓴다.
- 네 장의 몸 기울기, 팔·다리, 표정, 소품, 실루엣이 모두 달라야 한다.
- 장면별 투명 WebP를 사용하고, 실제 글자·버튼·진행 상태는 HTML/CSS로 유지한다.
- 원본 PNG와 서비스용 WebP를 분리 보관한다.

### 4.2 자산 규격

- 원본: 1536×1536px 이상 PNG, 크로마키 제거 후 alpha 보존
- 서비스용: 긴 변 1100~1300px WebP, 목표 300KB 이하, 품질 86~90
- 캐릭터와 주요 소품은 모든 방향에서 최소 8% 안전 여백 확보
- 그림 안 텍스트, 워터마크, 프레임, 바닥 그림자, 복잡한 배경 금지
- 모바일 CSS crop에서도 얼굴·손·행동 소품이 잘리지 않아야 한다.

### 4.3 모션

- 자산 자체는 장면별 최종 포즈를 가진다.
- CSS는 자산 전체의 단발성 이동·회전과 코드형 보조 소품의 순차 모션만 담당한다.
- 한 장면의 주요 동시 모션은 3개 이하, 500~800ms 안에 끝낸다.
- 반복 부유 애니메이션은 사용하지 않는다. 캐릭터가 계속 떠 있는 느낌을 없앤다.
- `prefers-reduced-motion: reduce`에서는 즉시 최종 상태를 보여준다.
- transform과 opacity만 사용하고 넓은 blur/filter 애니메이션은 피한다.

## 5. 모바일 레이아웃

```text
safe area
NUANG                             건너뛰기
━━━━  ━━━━  ━━━━  ━━━━
[장면별 일러스트: 화면 높이의 약 38~46%]
눈썹말
제목 2줄
설명 2~3줄
[이전] [다음 / 내 뉴앙코드 알아보기]
bottom safe area
```

- 전체: `100dvh`, 상단·본문·CTA의 3행 구조
- 본문: 일러스트가 먼저, 카피가 다음에 온다.
- CTA는 별도 하단 행에 두어 일반 모바일에서는 처음부터 보인다.
- 콘텐츠 최대 폭 480px
- 320px 좌우 여백 16px, 360px 이상 20px, 430px 이상 24px
- 320×568 일러스트 164~190px
- 360×640 일러스트 205~235px
- 390×844 일러스트 270~310px
- 700px 미만에서는 장식과 일러스트를 먼저 줄이고 제목은 26px 이상 유지한다.
- 높은 화면에서도 일러스트는 320px 이상 무한 확대하지 않는다.
- 200% 글자 확대에서는 본문만 세로 스크롤되고 CTA와 겹치지 않는다.
- 가로 화면은 일러스트와 카피를 2열로 바꾸되 CTA는 오른쪽 카피 아래에 둔다.
- 터치 영역 최소 44×44px, 주 CTA 52~56px
- `env(safe-area-inset-top/bottom)`을 반영한다.

## 6. 최초 진입 전용 계약

### 6.1 자동 진입

자동 온보딩은 `/` 또는 일반 `/home` 진입에서 영구 최초 노출 기록이 없을 때만 발생한다.

다음 deep link는 온보딩이 가로막지 않는다.

- 공유 피드·결과·밸런스게임 방
- 로그인/OAuth 복귀 주소
- 정책·도움말·공개 프로필
- 그 밖의 의미 있는 직접 주소

### 6.2 최초 노출과 완료 판정

- 첫 화면이 안정적으로 렌더링되면 즉시 `firstSeenAt`을 기록한다.
- 사용자가 G01~G03에서 이탈해도 다음 일반 진입에서 자동으로 다시 표시하지 않는다.
- `건너뛰기`와 마지막 CTA를 누르면 `completedAt`을 별도로 기록한다.
- 최초 노출 기록과 완료 기록은 분석·운영을 위해 구분하지만, 둘 다 자동 재진입을 만들지 않는다.
- 노출·완료·재진입 정책에 대한 경고 문구는 사용자에게 노출하지 않는다.

### 6.3 영구 상태와 버전

- 영구 최초 노출 여부, 완료 여부, 마지막으로 본 가이드 버전을 분리한다.
- 기존 `nuang:onboarding:guide-v1`의 유효 완료 기록은 영구 최초 노출과 완료로 인정한다.
- V3 출시 때문에 기존 사용자에게 온보딩을 다시 자동 노출하지 않는다.
- 익명 최초 노출과 완료는 브라우저에 먼저 저장한다.
- 로그인 사용자는 계정에도 최초 노출·완료 시각을 저장해 다른 기기에서 재노출을 막는다.
- 익명 상태에서 본 뒤 로그인하면 브라우저의 최초 노출·완료 상태를 계정에 병합한다.
- 서버 저장 실패는 홈이나 검사 진입을 막지 않는다.

### 6.4 앱 내 접근 경로

- 앱 메뉴·마이·설정·도움말에 `온보딩 다시 보기` 링크를 만들지 않는다.
- `/onboarding`을 주소창에 직접 입력하는 것은 허용한다.
- 직접 다시 봐도 영구 완료 상태는 초기화하지 않는다.
- 과거 문서의 `뉴앙 가이드 다시 보기` 제안은 폐기한다.

## 7. 접근성

- `전체 4개 중 N번째` 위치를 제공한다.
- 활성 장면만 화면 읽기와 포커스 순서에 포함한다.
- 스와이프 외에 이전·다음·진행 버튼·키보드 방향키를 지원한다.
- 진행 상태는 `aria-current="step"`으로도 전달한다.
- 장면 전환 뒤 포커스를 임의 이동하지 않는다.
- 장식 일러스트는 `aria-hidden="true"`, 의미는 제목과 설명이 전달한다.
- 색만으로 코드를 설명하지 않는다.
- 텍스트와 CTA는 WCAG AA 대비를 목표로 한다.

## 8. 구현 Gate

### Gate A — 후킹과 카피

- 첫 장에서 성향 검사·다섯 글자·나와 관계 이해 중 두 가지 이상을 5초 안에 이해할 수 있다.
- 내부 용어와 과장된 우월 표현이 없다.
- 제목 2줄, 설명 3줄 이내를 기본 화면에서 유지한다.

### Gate B — 일러스트

- 네 장 모두 다른 포즈와 행동의 독립 일러스트를 사용한다.
- 온보딩 코드에서 기존 정면 `NuangCharacter` 참조가 0건이다.
- 같은 그림에 CSS 위치만 바꾼 장면이 없다.
- 반복적으로 가만히 떠 있는 캐릭터 모션이 없다.

### Gate C — 모바일

- 320×568, 360×640, 375×667, 390×844, 430×932, 844×390을 점검한다.
- horizontal overflow와 CTA 가림이 0이다.
- 브라우저 확대·글자 확대 200%에서도 진행할 수 있다.
- iOS/Android safe area와 주소창 높이 변화에서 버튼이 잘리지 않는다.

### Gate D — 진입과 완료

- 기존 v1 완료 사용자가 V3 출시 뒤 자동 온보딩을 다시 보지 않는다.
- 로그인 계정은 다른 기기에서도 최초 노출·완료 상태를 복원한다.
- 첫 화면만 본 뒤 이탈한 사용자도 다음 일반 진입에서 자동 재노출되지 않는다.
- 직접 `/onboarding` 접근은 가능하다.
- 앱 내 온보딩 링크는 `rg` 기준 0건이다.
- 저장 실패가 홈·검사 이동을 막지 않는다.

### Gate E — 품질

- reduced-motion에서 반복 모션 0
- 빠른 연속 탭·스와이프에도 한 장씩 이동
- 새로고침·뒤로가기·중도 이탈·건너뛰기·마지막 CTA 회귀 점검
- 컴포넌트·저장·진입·계정 동기화 테스트 통과
- TypeScript, ESLint, production build 통과

## 9. 완료 정의

처음 온 사용자가 뉴앙의 차별점과 관계 가치를 즉시 이해하고, 서로 다른 행동의 네 캐릭터 일러스트를 자연스럽게 따라가며 검사를 시작할 수 있어야 한다. 기존 완료 사용자는 다시 자동 진입하지 않고, 앱 내부에는 온보딩 재접근 링크가 없어야 한다.
