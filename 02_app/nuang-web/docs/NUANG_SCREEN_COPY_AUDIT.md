# 뉴앙 전체 화면 설명 문구 감사

- 기준일: 2026-07-23
- 대상: `src/app/**/page.tsx`의 실제 앱 라우트 53개
- 제외: Route Handler/API, 와이어프레임, 정적 미리보기 HTML
- 목적: 설명을 읽어야만 사용할 수 있는 화면을 없애고, 구조·이름·상태·행동만으로 이해되는 UI를 만든다.

| ------------------- | ------------------------------------------------------------- | --------- |

상태는 문구 감사의 진행 상태이며 기능 완성도를 뜻하지 않는다.

## 2. 문구를 없애는 기준

다음 문구는 기본적으로 제거하거나 UI 구조로 대체한다.

1. 화면 제목을 다시 풀어 쓴 소개 문장
   - 예: `성향지도` 아래의 “나와 궁금한 사람의 성향을 한곳에서 알아봐요.”
2. 버튼을 보면 알 수 있는 동작 설명
   - 예: `글쓰기` 옆의 “글과 사진을 한곳에서 나눠요.”
3. 같은 화면 안에서 제목·태그·본문으로 반복되는 정보
   - 예: `추천`, `추천 피드`, `추천한 이유`가 연속해서 반복되는 구조
4. 선택지나 콘텐츠를 보면 바로 알 수 있는 사용법
   - 예: “하나를 고르면 결과를 볼 수 있어요.”
5. 고객의 다음 결정에 영향을 주지 않는 홍보성·분위기성 문장
6. 개발 단계, 내부 명칭, 베타·예비·연구 중 같은 구현 상태 설명
7. 매번 노출할 필요가 없는 긴 설명
   - 최초 1회 도움말, 정보 버튼, 펼침 영역처럼 필요할 때만 확인하게 바꾼다.

문구를 삭제한 자리는 장식으로 채우지 않는다. 다음 수단 중 가장 짧은 것으로 의미를 전달한다.

- 익숙한 화면 제목과 행동 이름
- 선택된 탭·필터·버튼의 시각적 상태
- 정보의 우선순위를 보여주는 간격과 묶음
- 값·진행률·대상 코드처럼 실제 결정에 필요한 데이터
- 빈 상태에서 바로 실행할 수 있는 한 개의 주요 행동

## 3. 반드시 유지하는 설명

다음 정보는 짧게 다듬을 수 있지만 의미를 제거하면 안 된다.

| 상황                    | 유지해야 하는 내용                                               | 노출 방식                         |
| ----------------------- | ---------------------------------------------------------------- | --------------------------------- |
| 오류·오프라인·저장 실패 | 무엇이 실패했는지, 현재 데이터가 안전한지, 다시 할 행동          | 오류가 발생한 시점에만 표시       |
| 빈 상태                 | 비어 있는 이유와 첫 행동                                         | 한 문장과 주요 버튼 1개           |
| 로그인·권한             | 로그인이 필요한 이유, 다음에 돌아올 위치                         | 행동 직전 또는 로그인 화면        |
| 개인정보·공개 범위      | 누구에게 무엇이 보이는지, 변경 결과                              | 저장 또는 공개 직전               |
| 차단·신고·삭제·로그아웃 | 실행 결과와 되돌릴 수 있는지                                     | 확인 단계                         |
| 검사 정확도             | 답변 기준 기간, 평소 모습 기준, 문항을 판단하기 어려울 때의 처리 | 검사 시작과 필요한 문항에서만 1회 |
| 결과 해석               | 점수·코드가 의미하는 범위와 다음 검사 필요 여부                  | 결과를 오해할 가능성이 있는 위치  |
| 안전·위기·의학적 주제   | 검사가 진단이 아니라는 경계, 즉시 도움받을 곳, 개인정보 처리     | 도움 화면과 민감 검사 진입부      |
| 법정 고지               | 이용약관·개인정보 처리방침의 필수 내용                           | 원문 보존, 목차와 가독성만 개선   |
| 뉴앙 고유 개념          | 처음 접하는 용어의 최소 정의                                     | 최초 1회 또는 정보 버튼           |
| 접근성                  | 아이콘의 목적, 선택·확장 상태, 오류 연결                         | 시각 설명 대신 `aria-*`로 유지    |

특히 검사 화면은 “설명이 적다”보다 “응답 기준이 흔들리지 않는다”가 우선이다. 다만 동일 안내를 문항마다 반복하지 않고 시작 화면, 상황 라벨, 판단 어려움 확장 영역으로 분리한다.

## 5. 화면별 감사 완료 조건

모든 화면은 다음 조건을 기준으로 감사를 완료했다.

- 상단에는 화면을 식별하는 제목과 필요한 행동만 남아 있다.
- 화면 제목을 다시 설명하는 부제나 소개 카드가 없다.
- 첫 화면에서 사용자가 해야 할 가장 중요한 행동이 한 개로 보인다.
- 같은 의미가 제목, 태그, 카드, 버튼에서 반복되지 않는다.
- 도움 문구는 실제 선택·입력·오류가 발생하는 위치에 붙어 있다.
- 낯선 뉴앙 용어가 아니라면 사용법 설명 없이도 조작할 수 있다.
- 삭제·공개·공유·검사 정확도·안전과 관련된 필수 설명은 남아 있다.
- 빈 상태, 실패 상태, 권한 부족 상태에서 다음 행동을 알 수 있다.
- 시각 문구를 줄여도 스크린 리더용 이름과 상태는 유지된다.
- 320px 너비와 큰 글자 설정에서도 핵심 행동과 상태가 잘리지 않는다.

## 6. 적용 순서

1. 주요 탭 첫 화면: 홈 → 검사 → 커뮤니티 → 성향지도 → 마이
2. 각 탭의 가장 자주 쓰는 다음 화면: 검사 응답, 게시물 작성·상세, 지도 상세, 프로필 편집
3. 결과·비교·공유 화면
4. 검색·알림·기록·설정 화면
5. 로그인·공개 범위·차단·신고·오류 상태
6. 공개 연구 참여 화면
7. 내부관리 화면

각 단계에서는 문구 삭제 후 레이아웃을 다시 확인한다. 문장을 지운 빈자리를 다른 설명 카드로 채우지 않고, 콘텐츠와 주요 행동이 자연스럽게 올라오도록 간격과 묶음을 조정한다.
