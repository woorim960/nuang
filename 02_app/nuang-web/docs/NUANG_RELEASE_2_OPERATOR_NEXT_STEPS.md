# 뉴앙 Release 2 운영자 다음 단계

- 문서 버전: 1.1
- 기준일: 2026-08-01
- 대상: 개발 지식이 없어도 Release 2를 운영해야 하는 관리자
- 현재 상태: 데이터베이스 적용과 운영센터 연결 확인 완료

---

## 1. 지금 어디까지 끝났나요?

다음 준비는 끝났다.

- 사용자가 결과 리포트 문장을 평가할 수 있는 저장소
- 결과가 완성됐을 때의 문장과 버전을 기억하는 기능
- 코어·정밀 결과에 충분한 생활·관계·강점·오해 설명을 제공하는 V3 공통 리포트
- 과거 결과에 없는 점수는 만들지 않고 현재 공개 코드 가이드를 별도 층으로 제공하는 기능
- 운영센터의 문장별 적합도 집계 화면
- 승인된 문장만 고객에게 보여주는 안전장치
- 320px·390px 모바일 결과 화면 점검
- 전체 1,669개 자동 테스트와 프로덕션 빌드

운영센터에 `아직 모인 결과 문장 의견이 없습니다`라고 표시되는 것이 현재의 정상 상태다. 오류가 아니라 수집할 첫 의견을 기다리는 상태다.

---

## 2. 가장 가까운 다음 단계

순서는 `운영 배포 → 새 검사 1회 → 피드백 1건 → 운영센터·메일 확인 → 실제 수집 시작`이다.

### 1단계. Release 2를 운영에 배포하기

이 작업은 Codex가 수행할 수 있다. 운영자는 배포를 지시하고, 배포가 끝났다는 보고를 확인한다.

아직 배포 전에는 실제 고객이 새 피드백 기능을 볼 수 없다. 데이터베이스만 먼저 적용된 현재 상태는 안전하며, 기존 앱 기능에는 영향을 주지 않는다.

### 2단계. 운영 서비스에서 새 결과 하나 만들기

배포가 끝나면 운영자 계정으로 다음을 한 번만 수행한다.

1. 뉴앙에 로그인한다.
2. 코어 검사 또는 정밀 검사를 새로 완료한다.
3. 결과를 계정에 저장한다.
4. 결과 리포트의 `자연스럽게 잘하는 것 → 과해지면 생기는 일 → 조금 더 편해지는 방법`을 확인한다.
5. 생활·관계·강점·오해 section 뒤에 성향지도 연결이 나오는지 확인한다.

완료 snapshot 저장 검증은 **배포 후 새로 완료한 결과**로 한다. 예전 결과는 저장되지 않은 점수나 개인화 문장을 만들지 않지만, 유효한 뉴앙 코드에는 현재 고객에게 공개 중인 일반 가이드를 별도 콘텐츠 층으로 제공한다.

### 3단계. 문장 피드백 한 건 보내기

새 결과 리포트에서 다음 중 하나를 선택한다.

- `나와 비슷해요`
- `상황에 따라 달라요`
- `나와 달라요`

두 번째나 세 번째를 선택하면 이유를 하나 고를 수 있다. 이유 입력은 선택 사항이다.

### 4단계. 운영센터에서 확인하기

운영센터의 `고객 의견 → 결과 리포트 문장 품질`로 이동한다. 바로가기 주소는 `/admin/feedback#core-result-quality`다.

다음을 확인한다.

- 방금 제출한 의견이 보이는가
- 뉴앙 코드와 검사 종류가 맞는가
- 평가한 section과 content version이 표시되는가
- 상태 변경 버튼이 정상 작동하는가
- 운영 기록에 관리자 변경 이력이 남는가

### 5단계. 알림 메일 확인하기

현재 메일 발송에 필요한 값은 fallback을 포함해 구성돼 있다. 첫 피드백 제출 뒤 관리자 이메일의 받은편지함과 스팸함을 확인한다.

메일이 오지 않아도 피드백 저장은 취소되지 않는다. 저장과 알림은 분리돼 있으므로, 운영센터에 의견이 있다면 데이터는 안전하게 접수된 것이다.

## 3. 운영자가 지금 해야 하는 일

### 바로 해야 하는 일

- [ ] Codex에게 `Release 2 운영 배포해줘`라고 요청
- [ ] 배포 후 코어 또는 정밀 검사 새 결과 1건 생성
- [ ] 문장 피드백 1건 제출
- [ ] 운영센터 접수 확인
- [ ] 관리자 알림 메일 도착 확인

여기까지 통과하면 실제 사용자 수집을 시작할 수 있다.

### 사용자가 모이기 시작한 뒤 할 일

- 일주일에 한 번 운영센터의 높은 우선순위 문장 확인
- `나와 달라요` 이유가 같은 문장에 반복되는지 확인
- 문장을 바로 수정하지 말고 content version별 표본을 보존
- 수정 후보는 전문가 검토 후 새 version으로 발행
- 새 version과 이전 version의 반응을 섞어 계산하지 않기
- 수정·발행 순서는 운영센터 `성향 콘텐츠 → 운영 가이드`를 따르기

### 실제 연구 분석 전에 결정할 일

다음은 운영 책임자가 결정해야 하며 Codex가 임의로 정할 수 없다.

- 외부 성격심리·심리측정 전문가와 자격 기준
- 연구 데이터 보관 기간과 접근 담당자
- 선택적으로 받을 연령대·성별 등의 범위
- 비교에 사용할 한국어 척도와 상업적 사용 허가
- 재검사 안내 빈도와 보상 여부
- 먼저 검토할 P0 canonical 문장 순서

## 4. 숫자는 이렇게 읽으면 됩니다

| 표본 상태                            | 운영자가 할 일                                                |
| ------------------------------------ | ------------------------------------------------------------- |
| 1~9건                                | 수집만 계속한다. 문장을 좋다·나쁘다고 결론 내리지 않는다.     |
| 10~19건                              | 같은 불일치 이유가 반복되는지 사람이 확인한다.                |
| 20건 이상이며 `나와 달라요` 25% 이상 | 높은 우선순위로 올리고 문장과 적용 조건을 검토한다.           |
| 문장·코드·version별 100건 이상       | 전문가 승격·수정 검토에 사용할 수 있다. 자동 발행하지 않는다. |

이 비율은 전체 검사의 신뢰도를 뜻하지 않는다. 특정 문장이 특정 결과 사용자에게 얼마나 잘 맞았는지를 보는 운영 신호다.

심리측정 분석은 별도로 다음 순서로 진행한다.

1. 유효 완료 200건: 데이터 연결과 누락 확인
2. 정밀 완료 1,000건 이상: 1차 구조 탐색
3. 이후 비중복 1,000건 이상: 독립 확인
4. 같은 release 재검사 300쌍 이상: 시간 안정성과 측정오차 확인
5. 충분한 집단 표본: 연령·성별 등의 DIF·측정 동등성 확인

이 숫자를 넘었다고 자동으로 `검증 완료`가 되는 것은 아니다. 신뢰구간, 문항 분포, 모형 적합도와 전문가 판단을 함께 본다.

---

## 5. 지금 하지 않아도 되는 일

- 사용자를 위한 별도의 파일럿 검사 화면 만들기
- 모든 검사 뒤에 긴 리뷰 설문 붙이기
- 승인되지 않은 canonical 문장을 수동으로 고객 화면에 입력하기
- 표본이 적은 비율을 검사 정확도처럼 홍보하기
- 예전 결과의 측정값을 현재 문장으로 다시 만들거나 재채점하기
- 운영센터 DB 행을 직접 수정하기

검사를 이용하는 자연스러운 흐름에서 데이터가 쌓이게 두고, 운영센터에서 version별로 검토하면 된다.
