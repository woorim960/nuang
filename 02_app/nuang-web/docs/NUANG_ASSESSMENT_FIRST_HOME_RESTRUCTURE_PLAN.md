## 0. 이번 개편의 결정 요약

현재 `/home` 개인화 대시보드를 종료하고, `/assessments`의 검사 허브를 제품의 새 홈으로 재설계한다.

개편 후 하단 메뉴는 다음 네 개만 사용한다.

| 순서 | 메뉴     | 경로    | 역할                                                  |
| ---: | -------- | ------- | ----------------------------------------------------- |
|    1 | 홈       | `/home` | 검사와 함께하기를 통해 뉴앙의 핵심 가치를 시작하는 곳 |
|    2 | 커뮤니티 | `/feed` | 다른 사람의 생각을 읽고 반응하며 관계를 넓히는 곳     |
|    3 | 성향지도 | `/map`  | 32개 성향 세계와 내 코드를 탐색하는 곳                |
|    4 | 마이     | `/my`   | 내 성향, 리포트, 공개 범위, 계정을 관리하는 곳        |

`검사`라는 별도 최상위 메뉴는 없어진다. 검사 콘텐츠가 사라지는 것이 아니라 홈의 주인공이 된다.

커뮤니티 탭의 떠 있는 원형 버튼, 큰 전용 아이콘, 위로 들린 배치는 제거한다. 네 메뉴 모두 같은 크기·위치·선 굵기의 아이콘과 라벨을 사용하고 현재 탭만 색과 글자 굵기로 구분한다.

## 1. 왜 이 구조가 뉴앙에 유리한가

### 1.1 현재의 고객 문제

현재 제품에는 성격이 다른 두 개의 시작점이 있다.

- `/home`: 검사 상태, 커뮤니티 투표, 프로필 발견, 대화 미리보기가 섞인 개인화 대시보드
- `/assessments`: 코어 검사, 주제 검사, 함께하기, 연구소를 모은 검사 허브

첫 방문자는 홈을 보고도 뉴앙이 무엇을 가장 잘하는 서비스인지 한 문장으로 설명하기 어렵다. 반대로 검사 탭에서는 뉴앙의 핵심 자산이 잘 보이지만, 다섯 개 탭 중 두 번째 기능처럼 취급된다.

현재 구조의 구현 근거:

- `src/features/home/HomeDashboard.tsx`
- `src/features/assessment/AssessmentHub.tsx`
- `src/components/layout/BottomNavigation.tsx`
- `src/features/onboarding/onboarding-storage.ts`

### 1.2 새 홈이 답해야 하는 질문

사용자는 스크롤 단계마다 다음 질문의 답을 얻어야 한다.

| 인지 시간  | 사용자의 질문             | 새 홈의 답                                               |
| ---------- | ------------------------- | -------------------------------------------------------- |
| 0~3초      | 뉴앙은 무슨 앱이지?       | 나와 서로의 성향을 검사하고 함께 즐기는 성향 놀이터      |
| 3~10초     | 지금 무엇을 하면 되지?    | 내 상태에 맞는 검사 하나를 바로 시작하거나 이어가기      |
| 10~30초    | 계속 할 것이 있나?        | 생활 주제 검사, 함께하기 게임, 가벼운 연구소가 계속 열림 |
| 첫 완료 후 | 결과는 어디에 쓰지?       | 내 성향을 이해하고, 성향지도·커뮤니티·함께하기로 확장    |
| 재방문 시  | 오늘 다시 올 이유가 있나? | 이어갈 검사, 새 주제, 함께할 게임 중 하나가 갱신됨       |

### 1.3 제품 포지셔닝 문장

새 홈은 다음 메시지를 시각적으로 증명해야 한다.

> 나를 이해하고, 서로를 이해하는 성향 놀이터

`성향 검사 서비스`만 강조하면 일회성 도구처럼 보이고, `SNS`만 강조하면 일반 커뮤니티와 구별되지 않는다. 홈에서는 아래 세 경험을 하나의 흐름으로 보여준다.

```text
나를 이해하기
→ 결과를 생활 언어로 읽기
→ 함께 고르고 비교하며 서로를 이해하기
→ 커뮤니티에서 다양한 생각을 만나기
```

## 2. 새 정보구조

### 2.1 최상위 구조

```text
홈
├─ 오늘의 시작: 개인 상태별 주 행동
├─ 추천
├─ 나 알아보기
│  ├─ 첫 성향 검사
│  ├─ 정밀 성향 검사
│  └─ 생활 주제 검사
├─ 함께하기
│  ├─ 밸런스 게임
│  └─ 친구 성향 맞히기
├─ 연구소
└─ 내 검사 기록

커뮤니티
├─ 추천 피드
├─ 성향 놀이터

└─ 글·질문·투표
```

### 2.2 경계 원칙

- 홈은 성향 경험을 시작하는 곳이지 모든 기능의 메뉴판이 아니다.
- 커뮤니티 게시글 미리보기는 새 홈의 기본 섹션에서 제거한다.
- `서로를 이해하기`는 홈의 함께하기 콘텐츠로 보여주고, 일반 피드를 홈에 복제하지 않는다.
- 성향지도와 마이로 가는 반복 바로가기 카드는 만들지 않는다.
- 검사 응답·결과를 보는 도중에는 광고나 커뮤니티 추천으로 흐름을 끊지 않는다.
- 핵심 성향 검사와 정밀 코어는 계속 무료로 제공한다.

## 3. 경로 전환 계약

### 3.1 canonical 경로

| 현재                       | 개편 후                | 처리                |
| -------------------------- | ---------------------- | ------------------- |
| `/`                        | 온보딩 완료 시 `/home` | 유지                |
| `/home`                    | 새 검사 중심 홈        | 콘텐츠 전면 교체    |
| `/assessments`             | `/home`                | 호환 redirect       |
| `/assessments/[slug]`      | 동일                   | 검사 상세 경로 유지 |
| `/assessments/topics/**`   | 동일                   | 주제 검사 경로 유지 |
| `/assessments/together/**` | 동일                   | 함께하기 경로 유지  |
| `/labs/**`                 | 동일                   | 연구소 경로 유지    |

`/assessments` index만 닫고 하위 경로는 유지한다. 1차 배포에서는 임시 redirect로 로그와 유입을 관찰하고, 외부 링크와 내부 링크 이전이 확인되면 영구 redirect로 바꾼다.

### 3.2 반드시 함께 이전할 의존성

단순히 두 페이지를 교체하면 아래 흐름이 손상될 수 있다.

1. 검사 시작·완료 후 `returnTo=/assessments`로 돌아오는 링크
2. 마이·결과·공유·도움 화면의 `검사 둘러보기` 링크
3. 온보딩 완료 목적지와 첫 성향 검사 완료 목적지
4. 기존 홈 투표에서 로그인한 뒤 `/home?resumeFeed=poll...`로 복귀하는 흐름
5. `from=home`으로 기록된 커뮤니티 통계·뒤로가기 링크
6. 홈 전용 분석 이벤트와 피드 미리보기 서버 조회

이전 규칙:

- 검사 허브로 돌아오는 의도는 모두 `/home`으로 바꾼다.
- `/home?resumeFeed=poll&pollId={uuid}&optionId={uuid}&auth=connected` 레거시 요청은 네 필드만 whitelist해 같은 쿼리의 `/feed`로 redirect한다.
- `/feed`는 기본 목록에 해당 투표가 없더라도 `pollId`를 읽어 재개할 투표를 payload에 포함하고, 기존 `FeedPollCard`가 투표를 저장한 뒤 query 없는 `/feed`로 정리한다.
- 새 로그인 복귀 URL은 처음부터 `/feed`를 사용하고 `/home` bridge는 이전 버전 링크에만 적용한다.
- `from=home`은 새 홈에서 실제 커뮤니티 진입이 발생할 때만 사용한다.
- 이전 버전 링크가 한 번에 끊기지 않도록 최소 한 릴리스 동안 호환 테스트를 유지한다.

목적별 복귀 경로:

| 출발 화면                    | canonical 복귀               |
| ---------------------------- | ---------------------------- |
| 코어 검사·코어 결과          | `/home`                      |
| 주제 검사·주제 결과          | `/home?view=self`            |
| 연구소·연구소 결과           | `/home?view=lab`             |
| 밸런스 게임·친구 성향 맞히기 | `/home?view=together`        |
| 공유 결과의 다른 검사 보기   | 원래 검사 종류에 맞는 `view` |
| 커뮤니티의 내 코드 확인하기  | `/home`                      |

`precision-entry.ts` 같은 안전한 return destination 파서는 레거시 `/assessments` 입력을 계속 허용하되, 새 링크를 생성할 때는 위 canonical 경로로 정규화한다.

온보딩 계약:

- `/home`과 `/assessments` index는 온보딩 미완료 시 기존처럼 `/onboarding`으로 이동한다.
- 특정 검사, 결과 공유, 연구소, 함께하기 방처럼 목적이 분명한 하위 deep link는 온보딩으로 가로채지 않는다.
- `/assessments` 북마크에서 `/home`으로 온 사용자는 동일한 홈 gate를 적용받는다.

### 4.2 상단 헤더

- 좌측: `NUANG` 워드마크와 `홈`
- 우측: `내 기록`
- 알림은 커뮤니티 안에서 찾을 수 있으므로 홈의 첫 기능과 경쟁시키지 않는다.
- 높이 56px + safe area, 반투명 흰색, 1px 하단선

### 4.3 브랜드 약속 영역

홈이 실제 렌더링되는 모든 상태에서 슬로건을 볼 수 있어야 한다. 온보딩 미완료는 홈 상태가 아니라 `EntryGate` 전환 상태로 따로 검증한다. 슬로건 영역은 큰 광고형 히어로가 아니라 첫 화면의 짧고 명료한 서문으로 사용한다.

- eyebrow: `성향으로 나와 우리를 발견하는 곳`
- 유일한 h1: `나를 이해하고, 서로를 이해하는 성향 놀이터`
- 설명: `생활 속 나를 발견하고, 함께 고르며 서로를 알아가요.`

브랜드 약속은 텍스트 중심으로 최대 160px 안에 배치하고 캐릭터는 아래 상태별 핵심 경험에서만 사용한다. 헤더의 `홈`은 일반 텍스트, 상태별 핵심 제목은 h2로 둔다.

### 4.4 상태별 핵심 경험

`GlobalHomeJourney`는 브랜드 약속 바로 아래, 탐색 탭 위에 모든 탭과 무관하게 단 한 번만 표시한다. 첫 viewport에서 가장 강한 행동은 항상 하나이며 이 영역의 최대 높이는 일반 글자 크기에서 260px이다.

| 우선순위 | 사용자 상태                    | 제목 예시                                  | 주 행동                 |
| -------: | ------------------------------ | ------------------------------------------ | ----------------------- |
|        1 | 진행 중인 정밀 코어가 있음     | `답하던 곳부터 이어가요`                   | `정밀 검사 이어하기`    |
|        2 | 진행 중인 첫 코어가 있음       | `답하던 곳부터 이어가요`                   | `첫 검사 이어하기`      |
|        3 | 정밀 코어 완료                 | `내 성향을 다시 읽어볼까요?`               | `내 성향 결과 보기`     |
|        4 | 첫 코어만 완료                 | `내 모습을 조금 더 자세히 알아볼 차례예요` | `정밀 검사 시작하기`    |
|        5 | 코어 결과가 없음               | `빠르게 뉴앙 코드 알아보기`       | `첫 성향 검사 시작하기` |
|        6 | 결과 열람 상태가 확인된 재방문 | `오늘은 생활 속 다른 모습을 발견해봐요`    | 편집 추천 주제 검사     |

개인 추천 모델이 없는 상태에서 `당신에게 꼭 맞는 검사`처럼 과장하지 않는다. 편집 추천은 `오늘의 추천`, 실제 결과 기반 추천은 근거가 준비된 뒤 `내 결과를 바탕으로 추천`으로 구분한다.

현재 결과 데이터에는 고객이 결과를 충분히 읽었는지 판단할 신뢰 가능한 열람 상태가 없다. 1차 구현은 정밀 결과가 있으면 결과 보기를 유지한다. 이후 `resultViewedAt` 또는 동등한 명시적 이벤트가 준비됐을 때만 편집 추천을 상단 주 행동으로 승격한다.

현재 `AssessmentHomeCoreSection`은 완료 결과를 진행 중 검사보다 먼저 반환하므로 그대로 재사용하지 않는다. 위 우선순위를 순수 selector와 단위 테스트로 새로 고정한다. 1차의 `진행 중`은 저장 계약이 있는 코어 검사만 뜻한다. 주제 검사·연구소·밸런스 게임 복귀는 각각 신뢰 가능한 진행 저장 계약이 생긴 뒤 별도 확장한다.

표의 6번은 1차 selector에 동시에 적용하는 순위가 아니라 `resultViewedAt`이 생긴 뒤의 후속 교체 규칙이다. 해당 이벤트가 준비되면 완료 결과를 이미 확인한 재방문자에 한해 3·4번 결과 CTA 대신 6번 편집 추천을 적용한다.

### 4.5 홈 탐색 탭

현재 검사 허브의 네 분류를 유지하되 고객 언어를 홈 맥락에 맞춘다.

| 탭          | 의미                         | 기본 콘텐츠                    |
| ----------- | ---------------------------- | ------------------------------ |
| 추천        | 지금 바로 시작하기 좋은 조합 | 선별 주제 + 함께하기 + 연구소  |
| 나 알아보기 | 내 성향을 깊고 다양하게 확인 | 공개 주제 검사                 |
| 함께하기    | 사람들과 고르고 비교         | 밸런스 게임 + 친구 성향 맞히기 |
| 연구소      | 가볍고 뜻밖의 재미           | 별난 성향 연구소               |

탭은 50px 높이의 sticky underline 형식을 유지한다. 필터가 바뀌어도 스크롤이 갑자기 상단으로 튀거나 광고가 콘텐츠 사이로 이동하지 않아야 한다.

탭 상태는 React 메모리에만 두지 않고 URL과 동기화한다.

- 추천: `/home`
- 나 알아보기: `/home?view=self`
- 함께하기: `/home?view=together`
- 연구소: `/home?view=lab`

이 계약으로 새로고침, 공유, 브라우저 뒤로가기, 검사 완료 후 특정 분류 복귀를 보존한다. 허용하지 않은 `view` 값은 추천으로 안전하게 정규화한다.

고객이 탭을 선택할 때는 `router.push(..., { scroll: false })`로 history를 보존하고, 허용하지 않은 `view`를 canonical `/home`으로 정리할 때만 replace한다. 탭 변경 후 초점을 강제로 옮기지 않고 짧은 polite live region으로 패널 변경을 알린다. sticky dock의 top은 `calc(56px + env(safe-area-inset-top))`이다.

### 4.6 콘텐츠 위계

추천 탭의 기본 순서:

1. 공개 주제 검사 추천
2. 함께하기 대표 콘텐츠
3. 가벼운 연구소 콘텐츠
4. 검사 품질 피드백·도움 같은 보조 기능

`나 알아보기`, `함께하기`, `연구소` 탭에서는 해당 목적의 콘텐츠만 보인다. 다른 하단 메뉴로 이동시키는 기능 카드를 섞지 않는다.

## 5. 광고 배너 설계 — 후속 수익화 참고

이 장은 현재 구현 계약이 아니다. 사용자가 수익화 구현을 별도로 요청하고 광고·개인정보·운영 정책을 다시 승인하기 전까지 모든 슬롯은 DOM과 데이터 조회에서 제외한다.

### 5.1 향후 홈 광고 인벤토리

| 슬롯 ID               | 위치                                                 | 초기 상태       | 목적                    |
| --------------------- | ---------------------------------------------------- | --------------- | ----------------------- |
| `HOME_INLINE_01`      | 추천 탭에서 전역 코어·주제·함께하기 가치가 노출된 뒤 | 1차 기반 구현   | 가장 안전한 기본 배너   |
| `HOME_INLINE_02`      | 추천 탭의 연구소와 보조 콘텐츠가 모두 끝난 뒤        | DOM 미연결 잠금 | 긴 세션의 추가 인벤토리 |
| `HOME_SPONSORED_PACK` | 함께하기 일반 목록과 분리된 협업 band                | 별도 계약 후    | 브랜드 콘텐츠           |

### 5.2 배너 UI 계약

- 430px 앱 쉘 안에서 좌우 16px 여백을 사용한다.
- 반응형 배너의 예약 영역은 약 320×100 기준, 최대 너비는 본문 폭이다.
- 일반 배너는 상단에 한국어 `광고`를 항상 표시한다.
- 협업 팩은 `광고 · 브랜드명과 함께 만든 팩`처럼 경제적 이해관계와 제작 주체를 함께 표시한다.
- 뉴앙 콘텐츠 카드처럼 위장하지 않는다.
- 광고 위아래에 최소 16px의 비클릭 여백과 경계선을 둔다.
- 직접 등록 광고는 서버가 첫 HTML 전에 `filled/no-fill/blocked/consent_required`를 결정한다.
- `filled`일 때만 처음부터 약 100px의 고정 슬롯을 렌더하고, 나머지 상태는 처음부터 DOM을 만들지 않는다.
- 향후 클라이언트 광고에서 이미 공간을 예약했다면 no-fill 시 접지 않고 검수된 house creative로 교체한다.
- 비운영 placeholder는 개발 플래그에서만 보이며 고객 빌드에는 빈 박스를 노출하지 않는다.
- 홈 한 방문의 초기 빈도는 최대 1회로 시작한다.
- 1차 실제 송출은 제3자 프로그램매틱 SDK보다 운영자가 검수한 직접 등록 소재를 우선한다.
- 광고에는 광고주·광고 이유 확인, 숨기기, 부적절 광고 신고를 제공한다.
- 숨긴 캠페인은 같은 세션에서 재노출하지 않고, 신고한 소재는 운영 검토 전 재노출 제한 대상으로 기록한다.
- `HOME_INLINE_02`는 첫 슬롯과 실제 세로 거리가 480px 이상이고 사이에 유기적 콘텐츠 두 묶음 이상이 있으며, 한 세션 1회 제한을 푸는 별도 실험이 승인된 경우에만 연결한다.
- 빈 상태·오프라인·광고 동의 미확정 세션에서는 두 번째 슬롯을 열지 않는다.

광고 접근성:

- `<aside aria-label="광고">`
- 시각적 `광고` 라벨 최소 13px, neutral 500 이상
- 링크 이름: `광고주명, 광고 제목, 외부 사이트로 이동`
- 소재 전체를 중첩 버튼으로 만들지 않음
- 자동재생, 강제 focus, 주기적 live region 금지
- 숨기기·신고와 광고 iframe 뒤에도 정상적인 키보드 순서를 유지

### 5.3 절대 광고를 넣지 않는 곳

- 브랜드 슬로건과 첫 primary CTA 사이
- 검사 소개의 시작 CTA 바로 위·아래
- 검사 문항 선택 화면
- 밸런스 게임 선택·대기·결과 흐름
- 성향 결과의 핵심 해석과 개선 조언 사이
- 로그인·동의·공개 범위·계정 삭제 화면
- 오류·빈 상태·도움 연결 화면
- 하단 탭바 바로 위에 붙는 sticky banner

Google의 공식 배너 가이드도 게임 플레이 화면, 다음 버튼, 메뉴바 등 상호작용 요소 주변 배치를 피하고 광고 공간을 미리 확보하도록 권고한다. 구현 시 [배너 배치 가이드](https://support.google.com/admob/answer/6128877)와 [권장 배너 구현](https://support.google.com/admob/answer/6275335)을 release gate로 사용한다.

### 5.4 광고 개인화 원칙

1차 광고는 문맥 기반으로만 운영한다.

- 허용: 현재 화면의 넓은 콘텐츠 분류, 언어, 기기 폭
- 금지: 직접 문항 응답, 점수, 뉴앙 코드, 성향 프로필, 관계 결과, 민감 주제 결과
- 연령을 확인하지 못한 사용자는 일반 연령용 광고만 제공한다.
- 19세 이상 인증이 필요한 업종은 인증되지 않은 홈에 노출하지 않는다.
- 광고 네트워크에 전달되는 필드와 보존 기간을 별도 데이터 계약으로 잠근다.

## 7. 문구 체계

### 7.1 고정 언어

- 서비스: `성향 놀이터`
- 핵심 가치: `나를 이해하기`, `서로를 이해하기`
- 코어 검사: `첫 성향 검사`, `정밀 성향 검사`
- 생활형 검사: `주제 검사`를 내부 분류로만 쓰고 화면에서는 실제 질문형 제목을 우선
- 함께하기: `같이 고르고 서로를 알아봐요`
- 연구소: `가볍게 발견하는 뜻밖의 나`

### 7.2 피할 표현

- `당신을 정확히 분석합니다`
- `완벽한 궁합`
- `유료 검사가 더 정확합니다`
- `광고 추천을 위해 성향을 활용합니다`
- 기능명만 나열한 `검사 / 코드 / 비교 / 피드`
- 첫 화면에서 내부 용어인 lifecycle, evidence, pilot을 노출하는 문구

## 8. 상태·접근성·반응형

### 8.1 필수 상태와 복구

- 온보딩 미완료의 EntryGate 전환
- 첫 방문·결과 없음
- 빠른/정밀 검사 진행 중
- 빠른 결과만 있음
- 정밀 결과 있음
- 최근 결과 있음
- 콘텐츠 조회 실패
- 로컬 오프라인
- 광고 loading / filled / no-fill / blocked
- 탭별 빈 콘텐츠

상태별 행동:

- 탭 콘텐츠 없음: `새로운 검사를 준비하고 있어요` + `추천으로 돌아가기`
- 콘텐츠 조회 실패: 전역 코어 여정은 유지하고 해당 패널에만 `다시 불러오기`
- 오프라인: 로컬 코어 검사·결과는 유지하고 서버 전용 콘텐츠만 비활성
- 광고 no-fill/blocked/동의 미확정: 고객에게 오류 문구 없이 최초 렌더부터 미노출
- 오류·빈 상태: 광고 미노출

### 8.2 접근성

- 모든 홈 상태에서 슬로건을 유일한 h1으로 사용한다.
- 상태별 핵심 제목과 탭 패널의 첫 섹션은 h2, 하위 목록 제목은 h3를 사용한다.
- 카테고리 탭은 `tablist`, `tab`, `tabpanel` 관계를 유지한다.
- 광고는 콘텐츠 landmark와 분리하고 이름을 `광고`로 제공한다.
- 광고 iframe이 탭 순서를 독점하지 않도록 공급자 구현을 검수한다.
- 하단 메뉴는 `aria-current=page`를 사용한다.
- 200% 텍스트 확대, reduced motion, 키보드 탐색을 지원한다.
- 상태 카드 skeleton은 실제 카드와 같은 최소 높이를 사용하고, 슬로건과 탐색 탭은 초기 HTML에 유지한다.

### 8.3 검증 폭

- 320×568
- 360×667
- 390×664
- 390×844
- 430×740
- 768px 이상 중앙 430px 쉘

390×664에서 상단 inset 47px·하단 inset 34px을 가정해도 슬로건과 primary CTA 전체가 하단 탭 위 16px 안쪽에 보여야 한다. 320×568에서는 슬로건과 상태 제목이 보이고 CTA는 한 번의 짧은 스크롤 안에 도달해야 한다.

- accidental click 의심률
- 광고 차단·신고·불쾌 업종 피드백
- 광고 포함 세션과 미포함 세션의 검사 완주율
- CLS와 홈 p75 LCP

초기 중단 기준:

- 홈 → 검사 시작률이 대조군보다 상대 3% 이상 하락
- 검사 완주율이 2%p 이상 하락
- 광고 오인율 10% 초과
- 신뢰·도움됨 평가가 사전 기준보다 지속 하락
- 정책 위반, 금지 업종, 성향 데이터 유출은 1건 즉시 중단

표본 수와 사전 정의한 신뢰구간을 충족하기 전에는 광고 실험을 성공으로 판정하지 않는다. 광고 CTR만으로 배치를 성공 판정하지 않으며 보호 지표가 악화되면 수익이 발생해도 슬롯을 닫는다.

### 9.3 분석 금지 속성

- 직접 응답
- 원점수
- 뉴앙 코드 전체 또는 자리별 값
- 상대와의 비교 결과
- 민감 검사 주제
- 공개되지 않은 사용자 식별자

### 9.4 홈 이벤트·유입 계약

기존 홈과 검사 허브의 이벤트 이름을 무작정 합치지 않고 새 홈 목적에 맞게 다시 정의한다.

- 공통 필드: `home_version`, `view`, `content_type`, `content_id`, `position`, `entry_source`
- 핵심 이벤트: `home_viewed`, `home_primary_clicked`, `home_view_changed`, `home_content_started`, `home_together_started`
- `entry_source`는 `direct`, `onboarding`, `legacy_assessments`, `result_return`, `share`, `community`처럼 사전 허용값만 사용한다.
- 원문 referrer, 검색어, 검사 응답, 뉴앙 코드는 이벤트에 넣지 않는다.
- 같은 행동을 새 이름과 레거시 이름으로 이중 집계하지 않는다.
- `/assessments` redirect 유입은 별도 값으로 측정해 북마크·외부 링크 이전 완료 시점을 판단한다.

제품 피드백은 콘텐츠 클릭과 섞지 않는다. `ProductFeedbackForm.inferArea`에서 새 `/home`은 계속 `home`으로 분류하되, 운영센터에서는 `content_type`으로 코어·주제·함께하기·연구소 의견을 나눈다. `도움됐어요/아쉬워요` 같은 선택 뒤에만 선택형 이유를 열고, 자유 입력은 개인정보 주의 문구와 보존 정책이 준비된 경우에만 받는다.

### 9.5 검색·공유 메타데이터 계약

- `/home`의 제목과 설명은 슬로건과 `성향 검사·함께하기` 가치를 반영한다.
- `/assessments` index는 중복 색인 대상이 되지 않도록 canonical을 `/home`으로 통일한다.
- 개별 검사·결과·함께하기 공유 링크의 기존 Open Graph 메타데이터는 유지한다.
- 홈 공유 이미지는 광고나 특정 결과를 암시하지 않고 뉴앙 브랜드 약속만 전달한다.
- 검색·공유 미리보기에서도 `정확한 성격 판정`, `완벽한 궁합` 같은 과장 표현을 쓰지 않는다.

- 하단 메뉴가 홈·커뮤니티·성향지도·마이 순서의 4개다.

- 기존 홈 투표 OAuth 복귀가 유실되지 않는다.

### UI/UX

- 320~430px에서 가로 스크롤과 탭 라벨 잘림이 없다.
- 기본 글자 크기에서는 탭 라벨 한 줄, 200% 확대에서는 최대 두 줄과 탐색 탭 내부 스크롤을 허용한다.
- 홈 첫 화면의 primary action은 하나다.
- 광고가 첫 CTA, 내비게이션, 문항, 결과 해석과 인접하지 않는다.

- 홈의 목표 성능은 모바일 p75 LCP 2.5초 이하, CLS 0.1 이하다.

### 신뢰

- 무료 핵심 검사와 성향 결과를 광고나 결제벽으로 막지 않는다.
- 광고 요청·분석 이벤트에 성향 응답·코드·점수·관계 결과를 포함하지 않는다.
- 스폰서 콘텐츠는 일반 검사와 명확히 구분한다.
- 광고 숨기기·신고·광고주 확인과 재노출 제한이 동작한다.
