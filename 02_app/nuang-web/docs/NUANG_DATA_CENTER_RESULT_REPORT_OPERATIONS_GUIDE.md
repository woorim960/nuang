# 뉴앙 데이터센터·결과 리포트 운영 가이드

- 문서 버전: 1.0
- 기준일: 2026-08-01
- 대상: 성향 문항·코드 해설·결과 문장을 관리하는 운영자
- 운영 화면: `성향 콘텐츠 → 운영 가이드` (`/admin/content?view=guide`)
- 연결 문서: `NUANG_CORE_RESULT_REPORT_V3_PRODUCT_SPEC.md`, `NUANG_RELEASE_2_REAL_DATA_BUILD_GUIDE.md`

---

## 1. 운영자가 기억할 한 문장

**사용자 반응을 모아 수정 후보를 찾되, 기존 결과를 덮어쓰지 않고 새 버전을 검토·승인한 뒤 발행한다.**

자동 집계는 검토 순서를 정해준다. 문장을 자동으로 고치거나 발행하지 않는다.

---

## 2. 결과 리포트에 들어가는 데이터

| 데이터                | 결과에서 하는 일                               | 운영 규칙                                                          |
| --------------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| 완료 당시 측정값      | 다섯 글자와 정밀 세부 모습                     | 없는 값을 만들거나 과거 결과를 재채점하지 않는다.                  |
| 고객 공개 코드 가이드 | 생활·관계·일·회복·강점·오해 설명               | 수정할 때 기존 원문을 덮어쓰지 않고 새 `guide version`을 만든다.   |
| 결과 excerpt manifest | 가이드에서 리포트에 보여줄 완결 문단 선택      | 코어 20%, 정밀 25%, 최소 2,000자와 주제 균형 검사를 통과해야 한다. |
| 승인 canonical        | 더 정밀한 핵심 해석·과사용 비용·작은 행동 실험 | 근거와 전문 검토를 통과한 `customer_approved`만 결과에 추가한다.   |
| 사용자 품질 신호      | 문항 이해도와 결과 문장 적합도                 | 코드·section·content version별로 나누어 본다.                      |

과거 결과는 저장된 측정 사실을 그대로 유지한다. 완료 snapshot이 없는 유효한 5글자 코드는 현재 공개 가이드로 충분한 일반 해설을 제공하되, 없는 점수나 개인화 문장은 만들지 않는다.

---

## 3. 운영센터에서 보는 순서

### 매주 한 번

1. `고객 의견 → 검사 품질 자동 검수`에서 이해하기 어려운 문항을 확인한다.
2. `고객 의견 → 결과 리포트 문장 품질`에서 불일치가 반복되는 문장을 확인한다.
3. `검사 연구`에서 표본과 원 문항을 함께 보고 유지·검토 판단을 남긴다.
4. `성향 콘텐츠 → 문구 검토`에서 수정 후보의 전문 검토 상태를 확인한다.
5. 모든 검토가 끝난 새 버전만 `성향 콘텐츠 → 게시 버전`에서 발행한다.

긴급 오류가 없으면 매일 볼 필요는 없다. 개인정보 노출, snapshot 불일치, 잘못된 출처가 발견되면 즉시 노출을 멈추고 이전 승인본으로 되돌린다.

---

## 4. 숫자를 보고 판단하는 기준

| 같은 코드·section·version의 표본     | 운영자가 할 일                                                     |
| ------------------------------------ | ------------------------------------------------------------------ |
| 1~9명                                | 결론을 내리지 않고 수집을 계속한다.                                |
| 10~19명                              | 같은 불일치 이유가 반복되는지만 읽어본다.                          |
| 20명 이상이며 `나와 달라요` 25% 이상 | 높은 우선순위로 올리고 문장 범위·상황 조건·쉬운 표현을 검토한다.   |
| 100명 이상                           | 전문가 수정·제한 노출 후보로 검토할 수 있다. 자동 발행하지 않는다. |

`상황에 따라 달라요`가 많으면 틀린 문장이라고 바로 판단하지 않는다. 적용 상황이 너무 넓은지, 반례나 조건이 빠졌는지 먼저 확인한다. 공유율과 문장 적합도도 서로 다른 지표로 본다.

---

## 5. 문장을 수정할 때의 순서

1. **대상 고정:** 코드, section, content key, 현재 version을 기록한다.
2. **원인 확인:** 문구 어려움, 설명이 너무 넓음, 상황 차이, 중요 내용 누락 중 무엇이 반복되는지 본다.
3. **근거 확인:** 측정 범위와 원 연구가 수정 문장을 허용하는지 확인한다.
4. **새 버전 작성:** 게시 중인 문장을 직접 고치지 않는다.
5. **전문 검토:** 심리학, 성향검사, 쉬운 한국어, 서비스 안전을 모두 확인한다.
6. **결과 계약 검사:** 32개 코드의 코어·정밀 excerpt, 공개 범위, snapshot 복원을 검사한다.
7. **승인·발행:** 운영 책임자가 새 manifest를 승인한 뒤 게시한다.
8. **발행 후 관찰:** 이전 version과 새 version의 반응을 섞지 않고 비교한다.

운영센터의 네 분야는 고객용 문구 발행의 기본 검토다. 새로운 canonical을 처음 발행할 때는 Release 2 가이드에 정한 연구방법·제품 콘텐츠·데이터 품질 검토까지 추가로 완료한다.

---

## 6. 결과 리포트에서 우선 관리할 세 부분

사용자에게 피드백을 자주 요구하지 않도록 다음 세 부분만 우선 관리한다.

1. `profile_overview`: 자연스럽게 잘하는 것 → 과해지면 생기는 일 → 편해지는 방법
2. `strength_and_overuse`: 강점·과사용 비용·균형·성장
3. `misread_and_conversation`: 오해받는 모습·실제 의도·잘 통하는 말

생활·관계·일·회복 본문도 같은 가이드 version과 excerpt manifest에 포함되지만, 별도 피드백 버튼을 계속 늘리지 않는다. 반복되는 `중요한 내용 누락`은 해당 코드 가이드 전체를 검토할 신호로 사용한다.

---

## 7. 발행 전 필수 확인

- [ ] 기존 guide·canonical·manifest version이 불변 아카이브에 남아 있다.
- [ ] 근거 출처와 적용 코드·축·facet·상황이 추적 가능하다.
- [ ] 심리학·성향검사·쉬운 한국어·서비스 안전 검토가 모두 끝났다.
- [ ] 좋은 점만 말하지 않고 과사용 비용과 조정 방법이 함께 있다.
- [ ] 진단, 능력, 도덕성, 연애·업무 성공을 단정하지 않는다.
- [ ] 코어 20%, 정밀 25%, 최소 2,000자, 한 주제 30% 이하를 통과한다.
- [ ] 강점과 성장 전체 및 오해와 대화의 모든 소주제가 결과에 남는다.
- [ ] 공개·공유 화면에 개인 점수와 owner-only 문장이 노출되지 않는다.
- [ ] 완료 snapshot이 정확한 guide version과 excerpt digest로 다시 열린다.
- [ ] 문제가 생기면 이전 승인본으로 되돌릴 수 있다.

---

## 8. 하지 않는 일

- DB에서 게시 중인 문장을 직접 수정하지 않는다.
- 표본이 적은 비율만 보고 문항·문장을 삭제하지 않는다.
- 적합도나 공유율을 검사 전체의 정확도로 홍보하지 않는다.
- 생성형 모델이 만든 문장을 검토 없이 고객에게 공개하지 않는다.
- 현재 문장으로 과거 측정값을 다시 만들거나 재채점하지 않는다.
- 이전 version의 사용자 반응과 새 version의 반응을 합쳐 계산하지 않는다.

---

## 9. Release 2의 완료 의미

Release 2는 데이터가 한 번 채워지면 끝나는 작업이 아니다. 아래 순환을 같은 규칙으로 계속 실행할 수 있으면 운영 가능한 상태다.

`수집 → version별 집계 → 수정 후보 → 전문가 검토 → 새 버전 발행 → snapshot·공개 범위 확인 → 다시 관찰`

실제 심리측정 분석의 표본·전문가·연구 설계와 canonical 구축 기준은 `NUANG_RELEASE_2_REAL_DATA_BUILD_GUIDE.md`를 따른다.
