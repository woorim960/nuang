# 뉴앙 성향지도 문장 검수·베타 공개 운영 기획

- 기준일: 2026-08-06
- 적용 범위: 32개 뉴앙 코드의 고객용 상세 성향지도 전체
- 목표: 베타에서는 사람 전문가 검수와 같은 역할·순서·판정 기준을 AI 검수로 먼저 수행하고, MVP 전에는 관리자가 같은 문장 재고를 사람 검수로 승인한 뒤 새 버전을 배포한다.
- 원칙: AI 검수와 사람 검수를 같은 것으로 표시하지 않는다. 베타 AI 승인과 MVP 사람 승인을 별도 상태와 감사 기록으로 남긴다.

## 1. 구현 전 상태와 해결할 문제

현재 코드에는 32개 성향별 장문 가이드가 있고, 각 가이드는 15개 장과 관계·일·회복·대화·근거 등의 세부 섹션을 포함한다. 연구 데이터센터 v2.3의 구조·재조합·자동 품질 검사는 완료됐지만, 독립적인 사람 검수와 고객 공개 승인은 완료되지 않은 상태다.

고객 화면은 이 경계를 지키기 위해 상세 가이드 허용 목록을 비워 두었고, 현재는 다섯 글자 설명만 보여 준다. 기존 운영센터의 성향 콘텐츠 검토는 짧은 `content_atom`과 네 역할 검토를 지원하지만, 장문 가이드에서 실제로 보이는 다음 문구를 전부 추적하지는 않는다.

- 상단 대표 설명
- 장 제목·요약·확인 질문
- 섹션 제목
- 각 본문 문장
- 근거 자료 제목·설명

따라서 장문 가이드에 특화된 문장 재고, 일곱 역할 검수, 프로필 승인, 릴리스 승인, 배포·롤백 체계를 추가해야 한다.

### 구현 전 전수 감사 결과

- 32개 유형·480개 장·1,944개 섹션·3,945개 문단이 존재한다.
- 본문 문장은 약 9,280개이고, 제목·요약·질문·근거 설명까지 합치면 검수 단위가 1만 개를 넘는다.
- 데이터센터 연구 마스터는 완료됐지만 고객 공개 검증, 독립 7역할 사람 검수, 실제 사용자 이해도 검증은 0건이다.
- 현재 고위험 맥락 문장에는 출처 독립성·정확한 장면 근거가 부족한 항목이 많아, 기존 원고를 그대로 일괄 승인할 수 없다.
- 생성기가 중복 문장을 숨기려고 장·섹션 이름을 접두어로 붙인 문장이 있고, 능력처럼 들리는 `힘이 있어요` 표현과 훈계형 `좋아요` 표현이 과도하게 반복된다.
- 상세 성향지도는 가려져 있지만 결과 리포트 일부 경로가 연구용 원고 조회 함수를 사용해 승인 정책을 우회할 수 있다.
- 기존 관리자 DB 승인과 코드의 고객 공개 허용 목록이 연결되지 않아, 운영센터에서 게시해도 실제 상세 화면이 바뀌지 않는다.

이 감사 결과는 아래 재설계 기준을 이미 충족한다. 따라서 구현은 기존 장문을 그대로 승인하는 작업이 아니라, 고객용 가이드 생성 규칙과 공개 경계를 먼저 고친 뒤 새 문장 해시로 AI 베타 검수를 다시 수행하는 순서로 진행한다.

## 2. 검수 단위와 식별 방법

고객에게 보이는 문자열을 다음 단위로 분해한다.

1. `hero_summary`: 상단 대표 설명
2. `chapter_title`: 장 제목
3. `chapter_summary`: 장 요약
4. `check_question`: 사용자가 경험을 돌아보는 질문
5. `section_title`: 섹션 제목
6. `paragraph_sentence`: 본문을 한국어 문장 종결 기준으로 나눈 문장
7. `reference_title`: 근거 자료 제목
8. `reference_description`: 근거 자료 설명

각 단위는 `코드/가이드 버전/장/섹션/문단/문장 위치`로 만든 안정적인 키와 원문 해시를 갖는다. 원문이 바뀌면 기존 승인은 자동으로 승계하지 않고 새 해시의 재검토 대상으로 돌린다.

## 3. 사람 검수와 같은 일곱 역할

| 역할                 | 확인할 내용                                                                           | 통과할 수 없는 예                                 |
| -------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 성격심리 연구자      | 다섯 성향 방향과 문장이 맞고, 성향을 고정된 정체성처럼 말하지 않는가                  | 코드와 반대되는 행동 설명, 본질·운명 단정         |
| 심리측정 연구자      | 검사로 확인한 범위를 넘어 능력·성공·관계 결과를 예측하지 않는가                       | “이 유형은 일을 더 잘한다”                        |
| 연구방법 검토자      | 주장 수준에 맞는 연구 근거와 데이터 계보가 있고, 공통 설명과 유형별 설명을 구분했는가 | 근거 없는 인과관계, 표본 밖 일반화                |
| 쉬운 한국어 편집자   | 배경지식 없이 한 번 읽고 이해할 수 있고, 번역체·추상어·AI투가 없는가                  | 내부 용어, 모호한 “이러한 경향”, 지나치게 긴 문장 |
| 안전·개인정보 검토자 | 진단·낙인·우열·민감정보 추론·상대방 마음 단정이 없는가                                | 정상/비정상, 장애 추정, 상대의 속마음 확정        |
| 제품 콘텐츠 디자이너 | 해당 장과 섹션에서 사용자가 기대하는 질문에 답하고, 반복 없이 다음 행동을 돕는가      | 제목과 무관한 설명, 같은 조언 반복                |
| 데이터 품질 검토자   | 32개 코드와 모든 장·섹션이 빠짐없이 연결되고, 키·버전·해시·근거 링크가 유효한가       | 누락, 중복 키, 깨진 참조, 이전 원문 승인 재사용   |

## 4. 문장·프로필·릴리스 게이트

### 문장 게이트

한 문장은 일곱 역할이 모두 `승인`이어야 통과한다. 한 역할이라도 `수정 필요` 또는 `반려`이면 해당 문장은 공개 후보가 될 수 없다.

### 프로필 게이트

한 코드의 대표 설명, 15개 장, 모든 섹션과 문장이 빠짐없이 존재하고 모든 문장 게이트가 통과해야 프로필을 승인한다. 유형별 문장이 다른 코드와 사실상 같은 표현만 반복하면 구별성 검토를 다시 연다.

### 릴리스 게이트

32개 프로필이 모두 승인되고, 공개 금지 표현·누락·중복·깨진 근거·버전 불일치가 0건이어야 릴리스를 승인한다. 배포는 승인과 별도 동작으로 두며, 배포 직전 영향 범위와 롤백 버전을 다시 보여 준다.

## 5. 베타 AI 검수와 MVP 사람 검수의 분리

| 단계        | 베타                                   | MVP                                         |
| ----------- | -------------------------------------- | ------------------------------------------- |
| 검토자 종류 | 일곱 역할 AI 검토                      | 역할별 사람 검토자                          |
| 판정 기록   | 역할·규칙 버전·원문 해시·발견 사항     | 담당자·역할·메모·시간·원문 해시             |
| 공개 조건   | AI 일곱 역할 전부 통과 + 자동 회귀검사 | 사람 일곱 역할 전부 통과 + 관리자 최종 승인 |
| 화면 표시   | `베타 AI 검수 완료`                    | `사람 검수 완료`                            |
| 승인 승계   | 사람 승인으로 간주하지 않음            | 같은 해시에서만 유효                        |

AI가 통과시킨 결과도 사람 검수 대기열에서는 미검수로 남는다. 따라서 베타 공개가 MVP 사람 검수의 증거로 잘못 쓰이지 않는다.

## 6. 문제 심각도와 재설계 기준

- `P0 공개 차단`: 진단·낙인·우열, 코드 반대 설명, 개인정보 추론, 근거 없는 위험 조언, 내부 연구 문구 노출
- `P1 수정 후 재검토`: 과잉 일반화, 다른 유형과 구별되지 않는 설명, 긴 문장, 반복, 근거 수준보다 강한 주장
- `P2 편집 개선`: 어색한 말투, 제목과 본문의 작은 불일치, 읽기 흐름 문제

다음 중 하나라도 해당하면 일부 문장 수정으로 끝내지 않고 데이터센터 재설계를 연다.

1. P0가 여러 코드나 여러 장에서 반복된다.
2. 한 성향 방향의 정의와 실제 문장 사이 모순이 반복된다.
3. 유형 간 구별성 검사를 대규모로 통과하지 못한다.
4. 관계·일·감정 설명이 현재 근거보다 넓은 주장을 지속해서 만든다.
5. 출처의 원문과 데이터 계보를 추적할 수 없는 문장이 다수 발견된다.

재설계 시에는 기존 v2.3을 덮어쓰지 않고 새 연구 버전을 만든다. 축 정의, 세부 성향, 32개 조합, 장면별 주장, 독립 근거, 반례와 한계를 순서대로 다시 연결한다.

## 8. 데이터와 감사 기록

새 검수 저장소는 다음을 기록한다.

- 릴리스 ID·검수 규칙 버전·원문 전체 다이제스트
- 프로필별 가이드 버전·문장 수·콘텐츠 다이제스트
- 문장 키·원문 해시·위치·검토 역할
- AI/사람 구분·결정·근거·수정 요청·검토자·시간
- 프로필 승인·릴리스 승인·배포·롤백 기록
- 모든 관리자 변경의 원자적 감사 로그

클라이언트가 검토 위치나 원문을 임의로 바꾸지 못하도록 서버는 문장 키를 현재 코드 재고와 다시 대조하고, 저장할 원문·해시는 서버가 결정한다.

## 9. 베타 공개 구현 원칙

1. 32개 가이드 전체를 문장 재고로 만든다.
2. 일곱 역할 AI 검수기를 모든 문장에 실행한다.
3. 실패 문장을 수정하고 같은 해시 기준으로 전 역할을 다시 실행한다.
4. 프로필·전체 릴리스 게이트가 모두 통과한 경우에만 베타 허용 목록을 만든다.
5. 고객 `/map/[code]`에서 15개 장의 상세 성향지도를 다시 노출한다.
6. 검사 결과 리포트와 성향지도 연결도 같은 베타 승인 가이드만 사용한다.
7. AI 승인 상태는 운영센터에서 읽을 수 있지만 사람 승인으로 표시하지 않는다.

## 10. 검증 계획

- 32개 코드가 정확히 한 번씩 존재하는지 검사
- 각 코드가 15개 장과 계약상 필수 슬롯을 모두 갖는지 검사
- 모든 사용자 노출 문자열이 문장 재고에 포함되는지 검사
- 모든 문장이 일곱 역할 결정을 갖는지 검사
- 실패 문장이 있으면 공개 허용 목록 생성을 차단하는지 검사
- 원문 한 글자 변경 시 사람 승인과 AI 승인 다이제스트가 만료되는지 검사
- 관리자 권한·요청 출처·입력 스키마·감사 로그 검사
- 페이지 필터·상태·문장별 조치와 모바일 레이아웃 검사
- 32개 상세 성향지도 노출과 15개 장 이동·피드백 회귀검사
- 타입·lint·전체 단위 테스트·프로덕션 빌드 검사

## 11. 완료 조건

- 운영센터에서 32개 코드의 모든 고객 노출 문장을 빠짐없이 찾을 수 있다.
- 각 문장에 AI 일곱 역할 결과와 사람 일곱 역할 상태가 분리되어 보인다.
- 관리자는 문장별 결정을 저장하고, 프로필과 릴리스를 순서대로 승인·배포할 수 있다.
- AI 베타 검수에서 P0·P1 미해결 항목이 0건이다.
- 베타 공개 게이트가 통과한 32개 상세 가이드가 고객 성향지도에 실제로 노출된다.
- 사람 검수 전이라는 사실과 향후 MVP 승인 절차가 운영센터에 명확하게 안내된다.

- 실제 화면 문자열을 13,440개 검수 단위로 분해했고, 모든 단위에 안정 키·16자리 원문 해시·근거 링크·일곱 역할 결정을 만들었다.
- 중복을 숨기기 위해 장·섹션 이름을 문장 앞에 강제로 붙이던 변형을 제거했다.
- `힘이 있어요`, 실력·관계 결과처럼 읽힐 수 있는 공통 생성 문장을 조건부 생활 설명으로 고쳤다.
- 모든 프로필의 15개 장, 모든 문장, 일곱 역할 자동 검수가 통과했고 미해결 P0·P1은 0건이다.
- AI 베타 승인 32개만 고객용 상세 가이드 조회 함수가 반환하며, 연구용 원고 조회 함수는 관리자·보관 경로에만 남겼다.

### 운영센터

- `/admin/content/trait-map`에 32개 프로필, 15개 장, 문장 페이지, AI 판단, 사람 검토 상태를 한 화면에서 확인하는 전용 작업대를 추가했다.
- 사람은 문장마다 일곱 역할 중 하나를 선택해 `승인`, `보류`, `수정 요청`과 메모를 저장할 수 있다.
- 한 프로필의 `문장 수 × 7역할`이 전부 승인되기 전에는 프로필 최종 승인이 거절된다.
- 32개 프로필의 사람 최종 승인이 전부 끝나기 전에는 MVP 사람 검수본 배포가 거절된다.
- 베타 AI 승인, MVP 사람 승인, 실제 배포를 별도 상태로 저장하고 모든 변경을 관리자 감사 로그에 남긴다.
- 원문 전체·프로필·문장 해시를 서버에서 현재 코드와 다시 대조하므로, 원문이 바뀐 뒤 오래된 화면에서 승인을 재사용할 수 없다.

### 고객 화면·검증

- `/map/[code]`에서 32개 프로필 모두 기존 상세 템플릿의 15개 장을 노출한다.
- 상세 화면 상단에 검사 응답 범위와 베타 해석의 한계를 일상 언어로 안내한다.
- 결과 리포트, 새 결과 스냅샷, 공개 결과, 성향지도 피드백도 같은 고객 승인 가이드만 사용하도록 우회 경로를 제거했다.
- 타입 검사, 검수·계약·보관·운영센터·상세 UI 관련 자동화 테스트를 통과했다.
- 인앱 브라우저의 데스크톱·390px 모바일 화면에서 운영 작업대의 스크롤과 문장 검수 배치를 확인했다.
- 고객용 390px 화면에서 상세 템플릿, 베타 안내, 15개 장 노출과 브라우저 오류 0건을 확인했다.
- 전체 자동화 테스트 2,276개가 통과했고 실패는 0건이다.
- ESLint, 릴리스 기능 목록 검증, Next.js 프로덕션 빌드가 모두 통과했다.

### 사람이 이어서 할 일

1. `202608060001_trait_map_sentence_review_operations.sql`을 운영 DB에 적용한다.
2. 운영센터의 `성향 콘텐츠 > 상세 문장 검수`에서 역할별 사람 검토를 시작한다.
3. 프로필마다 모든 문장·일곱 역할을 승인한 뒤 `프로필 최종 승인`을 누른다.
4. 32개가 끝나면 `MVP 사람 검수본 배포`를 눌러 사람 검수 상태를 정식 배포 기록으로 남긴다.

베타 상세 성향지도는 AI 검수본으로 이미 노출되며, 위 사람 절차는 베타 공개를 다시 숨기기 위한 조건이 아니라 MVP 사람 검수 완료 상태로 승격하기 위한 절차다.

## 13. 실제 고객 화면 기반 인라인 편집 확장

운영자는 별도 입력 폼과 고객 화면을 번갈아 보지 않아도 된다. `/admin/content/trait-map`의 `보이는 화면에서 바로 고쳐요` 영역은 고객 `/map/[code]`와 같은 `TraitMapDetailTemplate`을 사용한다.

- 제목·요약·섹션 제목·본문의 개별 문장·확인 질문·근거 문구에 편집 위치를 표시한다.
- 문장을 누르면 그 자리가 textarea와 저장 도구로 바뀌며, 취소하면 원래 고객 UI로 돌아간다.
- `저장하고 베타 반영`은 현재 원문 해시를 서버에서 재확인하고, 전체 가이드 계약과 일곱 역할 AI 검수를 다시 실행한다.
- 문장 분리·추가로 위치 키가 흔들리는 편집, 과장·낙인·관계 결과 단정, 계약 길이 위반은 저장 전에 차단하고 역할별 이유를 편집 위치에 보여준다.
- 통과한 수정본만 `guide_content_revision`의 새 불변 이력으로 저장하고 같은 문장의 이전 수정본을 supersede한다.
- 저장과 동시에 해당 문장의 사람 승인 일곱 개, 프로필 최종 승인, 기존 MVP 사람 검수 배포 상태를 무효화한다.
- `/map/[code]`는 활성 수정본을 서버에서 조립해 보여주며, 편집 저장 후 캐시를 무효화하므로 다음 고객 요청부터 같은 문장을 표시한다.
- 편집 저장소를 읽지 못하거나 수정본 조립에 실패하면 일부 문구를 섞지 않고 마지막 코드 검수본으로 안전하게 되돌아간다.
- 데스크톱은 실제 모바일 폭의 스크롤 가능한 고객 화면으로, 모바일 운영센터는 화면 전체 폭의 동일 컴포넌트로 편집한다.

DB 적용 순서는 `202608060001_trait_map_sentence_review_operations.sql` 다음 `202608060002_trait_map_inline_content_editing.sql`이다.
