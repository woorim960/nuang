# 뉴앙 공개 문장 검수 커버리지 감사

- 기준일: 2026-08-05
- 범위: 코어검사, 주제검사, 별난 성향 연구소, 밸런스게임, 친구 성향 맞히기, 32개 성향지도
- 판정: **구조·안전 자동 검사와 내부 AI 사전 검토는 존재하지만, 실제 사용자·독립 전문가 검증까지 모두 완료된 상태는 아님**

## 1. 감사 방법과 운영 소스

런타임에서 실제 사용하는 코드 레지스트리를 직접 집계했다. Assessment Studio가 운영 DB 문서로 코드 콘텐츠를 덮어쓸 수 있어 운영 DB도 읽기 전용으로 확인했다.

2026-08-05 시점의 `assessment_content_entry`에는 삭제·보관된 운영 인수 테스트 항목 1건만 있고, 게시 중인 DB override는 0건이다. 따라서 현재 고객에게 노출되는 검사 콘텐츠는 코드 fallback과 일치한다.

아래 수치는 문장이 아닌 ID·버전·채점 키를 제외하고, 사용자가 실제로 읽는 콘텐츠의 규모를 집계한 것이다. 성향지도는 장·섹션·문단 구조가 명확해 별도로 집계했다.

## 3. 현재 검수 증거의 정확한 의미

### 코어검사

현재 AI 사전 검토 패킷은 입력 hash와 일치하고 재현 검사를 통과한다. 그러나 결과는 `completed_with_blockers`, `humanGateEffect: none`이다.

- 60개 기본 문항: `PASS_TO_COGNITIVE` 49, `COPY_REVISE` 7, `HOLD_FOR_ACCESS` 2, `HOLD_FOR_RISK_REVIEW` 1, `CONSTRUCT_REWRITE` 1
- 빠른 검사 22개에 비통과 문항 7개 포함
- 적응형 문항의 중립·판단 어려움 선택 부재는 접근성 blocker
- 실제 외부 M04 리뷰어 R01~R08은 모두 `NOT_ASSIGNED`
- 내부 AI roster는 R01–R06 완료, R07–R08 미배정

따라서 이 패킷은 운영자가 베타 위험을 알고 관찰하기 위한 사전 검토이지, 전문가·사용자 타당화가 아니다.

### 주제검사

`NUANG_TOPIC_ASSESSMENT_PRODUCTION_STANDARD.md`는 역할 분리, 쉬운 한국어, 이중 질문·문화·접근성 검토를 요구한다. 현재 테스트는 문항 수, 상황·척도 연결, 리포트 깊이, `claimId`, 근거 링크, 금지 내부 표현, 1,250개 점수 조합의 제목 패턴을 확인한다.

그러나 공개 6종별 검토자 명단, 문장별 판정, 수정·재승인 기록은 없다. 자동 계약 통과를 “모든 사용자가 한 번에 이해했다”는 증거로 보면 안 된다.

### 밸런스게임

312개 문항은 중복 ID·prompt·선택지 쌍, 모바일 길이, 안전성, 팩·채점 의미, 버전 fingerprint 검사를 통과한다. 카탈로그와 런타임의 팩별 수량·버전도 일치한다.

다만 문서의 `출시 전 콘텐츠 검수 완료`는 검토자 신원·역할·날짜·문항별 판정 원장이 없어 사용자 유형별 언어 검증 완료를 의미하지 않는다.

### 별난 성향 연구소·친구 성향 맞히기

연구소 manifest의 상태는 `provisional_internal`이다. 대화·충전 검사는 `internal_qa`, 갈등 회복은 `safety_copy_required`이다. 테스트는 seed 일치, 길이, 금지 임상어, 결과 도달 가능성을 확인한다. 친구 성향 맞히기는 안정적인 초대 ID·결과 분기 계약은 있지만 문장별 역할 검수 원장은 없다.

### 32개 성향지도

데이터센터 v2.3의 구조·계보·재현성 원장은 완료됐다. 그러나 고객 발행 검증은 0/5다.

1. 독립 7역할 검토: 0
2. 인지 면담·이해도: 0
3. 상황 직접·정량 타당도: 0
4. 32개 별칭 사용자 검증: 0
5. 고객 표면별 명시적 발행 승인: 0

외부 검토자 6석은 모두 `not_recruited`이고, 운영 `research_trait_map_section_feedback`의 응답도 0건이다. 기존 `current_customer_guide`는 미승인 연구 원장과 별도로 장문을 노출하는 경로였다. 이번 수정에서 32개 성향지도 상세 화면은 다섯 축에서 직접 확인되는 짧은 설명으로 전환했다. 이미 완료한 결과 리포트는 검사 당시 문구와 버전 복원 계약을 깨지 않기 위해 보존하며, 후보 모형이라는 한계 안내를 함께 보여준다. 따라서 연구 원장의 재현 통과를 고객 문장 승인으로 잘못 해석하지 않는다.

## 4. 영구 공개 언어 게이트

이번 감사에서 다음 코드 게이트를 추가했다.

- 재사용 검사기: `src/features/copy/public-language-validation.ts`
- 문항·선택지에는 연구/운영 내부 용어뿐 아니라 `OTT`, `KTX`, `오픈런`, `포토스팟`, `글램핑`, `풀빌라`, `e스포츠`, `도슨트`, `플로깅`, `티키타카`, `실용템`, `BGM`, `VR`, `팝업스토어`처럼 배경지식이 필요한 외래어·유행어도 차단한다. 같은 뜻의 쉬운 일상 표현으로 바꿔야 발행할 수 있다.
- Assessment Studio 통합: `src/features/admin/assessment-studio-validation.ts`
- 회귀 검사: `src/features/copy/public-language-validation.test.ts`, `src/features/admin/assessment-studio-validation.test.ts`, `src/features/admin/assessment-studio-sources.test.ts`

게이트는 다음 문제를 `blocker`로 만든다.

- `{{치환값}}`, `TODO`, `TBD`, `문항 1`, `선택 A` 등 임시·placeholder 문구
- `payload`, `schema`, `claimId`, `구성개념`, `심리측정`, `인지 인터뷰`, `내부 검토 상태` 등 운영·연구 전문용어
- `그것은?`처럼 대상을 알 수 없는 단독 조각
- `…때문에`, `…지만` 처럼 앞뒤 없이 뜻이 끝나지 않는 문장
- 80자를 넘는 문항, 30자를 넘는 선택지

단, 실제 선택지와 항상 함께 보여주는 “중요한 이야기가 생기면 나는 보통”같은 선택형 stem은 해당 표면만 명시적으로 `allowChoiceCompletion`을 사용한다. 이 예외에서도 placeholder·전문용어·모호성·길이 검사는 계속 적용된다.

게이트는 제목·캡션·설명부터 문항 상황·본문·선택지, 주제검사 결과 척도의 label·copy·strength·watch·action, 연구소 결과 프로필, 친구 게임 초대·빈 상태·결과 문구까지 검사한다.

Assessment Studio는 저장 시 문제 목록을 반환하고, `submit_review`와 `publish`에서 blocker가 하나라도 있으면 중단한다. 또한 런타임 resolver도 DB release에 blocker가 있으면 해당 override를 사용하지 않는다. 따라서 관리자가 DB 문서를 추가해도 일반 게시 API와 고객 런타임 모두에서 이 언어 게이트를 우회할 수 없다.

## 5. 전체 재검수 순서

### 1단계. 런타임 문장 잠금

코드와 활성 DB release를 실제 resolver로 읽어 모든 노출 문장에 `contentKey`, 표면, route, 상태, 소스, release, hash를 붙인다. 질문만이 아니라 결과 분기, 동점·경계·응답 부족, 공유, 빈 상태까지 포함한다.

### 2단계. 자동 사전 검사

영구 언어 게이트와 기존 구조·중복·안전 검사를 먼저 수행한다. 선행사 없는 지시어, 이중 질문, 다중 부정, 지나친 추상명사·비유, 응답 선택지 겹침, 교차 유형의 template 반복도 별도 레포트로 남긴다.

### 3단계. 구성개념을 숨긴 사용자 검수

검토자에게 코드 문자, 의도한 척도, 채점 방향을 보여주지 않는다. 각 문장을 읽고 다음을 독립적으로 판정한다.

- 한 번에 이해했는가
- 자기 말로 바꾸어도 같은 뜻인가
- 배경지식 없이 답할 수 있는가
- 실제 사람이 쓰는 말처럼 들리는가
- 특정 답을 착하거나 성숙한 답으로 유도하는가
- AI 템플릿, 과도한 위로, 공허한 추상화로 느껴지는가
- 불편, 낙인, 단정 오해가 있는가

관점은 첫 이용자, 14~18세, 일반 성인, 40세 이상, 낮은 배경지식·문해력, 한국어 제2언어, 신경다양성·접근성으로 나눈다.

### 4단계. 의도를 공개한 연구·안전 검수

다음 역할이 작성 의도와 채점 방향을 열고 검토한다.

| 역할           | 필수 판정                                                            |
| -------------- | -------------------------------------------------------------------- |
| 성격심리       | 의도한 경향과 문장의 실제 의미가 같은가                              |
| 심리측정       | 한 문항이 한 가지 반응만 묻고, 척도·기간·방향이 맞는가               |
| 쉬운 한국어    | 번역체·전문용어·모호한 지시어 없이 일상 언어로 읽히는가              |
| 문화·공정성    | 교육, 직업, 경제력, 성별, 관계 상태가 성향 점수로 바뀐 위험이 없는가 |
| 청소년·접근성  | 전 연령과 다양한 인지·소통 방식에서 답할 수 있는가                   |
| 임상·관계 안전 | 진단, 위험 예측, 낙인, 폭력·통제의 성향화를 막는가                   |
| 제품 UX        | 실제 화면 문맥에서 빠르게 읽고 답·행동할 수 있는가                   |

### 5단계. 독립 재판정

작성자는 자신의 문장을 최종 승인하지 않는다. blocker는 반드시 수정하고, major는 해결하거나 발행 제외 이유를 원장에 남긴다. 의미가 바뀐 모든 문장은 사용자 관점과 연구자 관점 모두에서 새 hash로 재검수한다.

### 6단계. 실제 화면 검수

320px, 390px, 768px, desktop, 큰 글자, 스크린리더에서 482개 고유 문항과 32개 성향지도·15장을 실제 DOM으로 열어 확인한다. 결과는 대표, 동점, 경계, 응답 부족 분기를 모두 포함한다.

### 7단계. 버전·발행 잠금

승인한 정확한 문장 hash만 운영 manifest에 넣는다. 승인 원장에 없는 새 문장이나 바뀐 문장은 CI와 Assessment Studio 게시에서 차단한다. 운영 문장은 직접 덮어쓰지 않고 새 release로만 바꾼다.

### 8단계. 운영 관찰과 재검수

`나와 잘 맞는다`와 `문장을 이해했다`를 같은 질문으로 취급하지 않는다. 버전별로 이해 오류, 다르게 느낀 비율, `판단 어려움`, 이탈, AI 느낌, 접근성 문제를 따로 집계하고 임계를 넘으면 자동으로 재검수 큐를 연다.

## 6. 베타 내부 승인 기준

다음을 모두 만족해야 하나의 `contentKey + version + hash`를 베타 공개 가능으로 판정한다.

- 자동 blocker 0개
- 미해결 major 0개
- 사용자 관점 2개 이상의 독립 PASS
- 연구·안전 관점 2개 이상의 독립 PASS
- 문장 단독 이해도 4/5 이상
- 진단·우열·능력·도덕·관계 결정론 오해 0건
- 교차 유형 정규화 반복은 `공통 축 설명`처럼 의미적 재사용 이유가 기록된 allowlist만 허용
- 모바일·큰 글자·스크린리더 누락·overflow 0건
- 승인 manifest hash와 실제 runtime hash 일치

## 7. AI 검수와 사람 검증의 경계

AI 에이전트는 여러 사용자·연구자 관점을 분리해 일관된 체크리스트로 문장 전체를 빠짐없이 점검하고, 오탈·반복·위험 표현·구성개념 이탈 후보를 찾는 데 적합하다. 이번 운영 게이트와 내부 승인 원장은 AI 검수를 재현 가능하게 만드는 장치다.

그러나 AI는 실제 청소년, 낮은 문해력의 사용자, 다른 문화·생활 조건을 가진 사람이 문장을 어떻게 이해하고 답을 찾는지를 관찰할 수 없다. 또한 자격이 확인된 독립 성격심리·심리측정·임상 전문가의 승인을 대체하지 못한다.

따라서 내부 AI 역할 검수를 `AI 베타 사전 검토`로 명시하고, `실제 사용자 인지 검증`, `독립 전문가 승인`, `정량 타당화`와 상태를 섬세하게 분리한다. AI 통과 기록을 `사람 검증 완료`로 표현하지 않는다.
