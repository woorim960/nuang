적용 채널: 대한민국 이메일 전용

## 1. 출시 목표

뉴앙 회원이 명확히 선택한 경우에만 새 검사, 함께하기, 이벤트와 제휴 소식을 이메일로 보낸다. 수신자는 이메일 안에서 로그인 없이 쉽게 철회할 수 있고, 운영자는 대상 원문 연락처를 내려받지 않은 채 캠페인을 작성·검토·테스트·예약·중지할 수 있어야 한다.

SMS와 앱 푸시는 Release 1 범위에서 발송·대상 계산을 모두 잠근다. 각 채널의 별도 동의와 수신거부 체계를 구현한 뒤 별도 Release로 연다.

## 4. 법적·고객보호 Gate

모든 광고 이메일은 코드가 강제로 다음을 보장한다.

1. 제목이 `(광고)`로 시작한다.
2. 전송자 `뉴앙`과 고객 문의 이메일·연락처를 본문 하단에 표시한다.
3. 로그인 없는 수신거부 링크를 본문과 텍스트 메일에 제공한다.
4. `List-Unsubscribe`와 `List-Unsubscribe-Post: List-Unsubscribe=One-Click` 헤더를 제공한다.
5. 수신거부는 동의 현재값 철회와 이메일 suppression을 한 트랜잭션에서 처리한다.
6. 스팸 신고와 영구 반송은 Resend webhook으로 suppression에 즉시 반영한다.
7. 발송 직전에 계정 활성, 최신 동의, 이메일 인증, suppression, 병합·충돌 상태를 다시 확인한다.
8. 대한민국 시간 08:00 이상 21:00 미만에만 실제 발송한다.
9. Resend idempotency key와 DB claim으로 중복 발송을 방지한다.
10. 2년 주기 수신동의 확인 안내를 자동 예약하고 발송 이력을 남긴다.

법률전문가의 사전 승인 자체는 제품 활성화의 필수 조건으로 두지 않는다. 최신 KISA 안내와 현행 법령을 구현 Gate로 사용하며, 법령이나 서비스 대상 국가가 바뀌면 발송을 다시 잠그고 검토한다.

## 5. 캠페인 상태

```text
draft → approved → queued → sending → completed
                  ↘ paused ↔ queued
draft/approved/queued/paused → cancelled
sending → completed | failed | paused
```

- `draft`: 자유롭게 수정 가능
- `approved`: 운영자가 미리보기와 테스트 메일을 확인한 상태
- `queued`: 대상이 서버에서 고정되고 예약을 기다리는 상태
- `sending`: 일부 또는 전체 발송 진행 중
- `paused`: 신규 claim 중단, 이미 공급자에 접수된 메일은 취소 대상이 아님
- `completed`: 모든 대상이 최종 상태
- `cancelled`: 미발송 대상 취소
- `failed`: 시스템 오류로 운영자 조치 필요

승인 이후 본문을 수정하면 다시 `draft`가 되고 재승인이 필요하다.

## 6. 캠페인 콘텐츠 계약

운영자가 임의 HTML을 넣지 않는다. 다음 구조화 필드만 입력한다.

- 내부 캠페인명
- 제목
- 상단 짧은 문구
- 본문 제목
- 본문(일반 텍스트, 줄바꿈 허용)
- CTA 라벨과 `https://nuang.app` 내부 URL

서버 템플릿이 HTML escaping, `(광고)` 제목, 발신 정보와 수신거부를 강제한다. CTA는 `nuang.app`과 허용된 서브도메인 외 주소를 거부한다.

## 7. 대상과 개인정보

- 운영센터에는 발송 가능 인원과 상태별 수량만 표시한다.
- 원문 이메일 CSV 내보내기는 제공하지 않는다.
- 캠페인 대상은 계정 ID로만 고정한다.
- 이메일 암호문은 발송 직전에 서버에서만 복호화한다.
- 브라우저 payload와 관리자 HTML에 원문 이메일을 포함하지 않는다.
- 테스트 메일은 현재 인증된 운영자 이메일로만 보낸다.

## 9. 자동 작업

- Supabase Cron이 매분 마케팅 이메일 outbox drain을 호출한다.
- claim은 예약 시각, 발송 시간대, 캠페인 상태와 재시도 시각을 DB에서 검사한다.
- 실패 재시도는 1분, 5분, 30분, 2시간 뒤에 수행하고 최대 5회로 제한한다.
- 매일 03:31 KST에 2년 주기 수신동의 확인 대상을 준비한다.
- 환경 변수나 DB가 준비되지 않으면 fail-closed로 한 건도 발송하지 않는다.
