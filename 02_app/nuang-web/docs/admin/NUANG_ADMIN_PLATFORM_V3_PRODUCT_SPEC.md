# 뉴앙 운영센터 V3 — 전문 관리자 플랫폼 전면 개편 기획서

- 문서 상태: 구현 기준선
- 작성일: 2026-08-01
- 적용 범위: `/admin` 전체와 관리자 전용 API·운영 문서
- 원칙: 실제 데이터와 현재 권한 계약만 사용하며, 준비되지 않은 기능을 동작하는 것처럼 표시하지 않는다.

## 1. 개편 목표

뉴앙 운영센터는 고객용 앱의 확장 화면이 아니라 서비스 운영자가 판단하고 조치하고 기록을 남기는 업무 시스템이어야 한다. 이번 개편의 목표는 다음 네 가지다.

1. 첫 화면부터 소비자 앱과 구분되는 전문 운영 도구의 인상을 만든다.
2. 운영자가 지금 처리할 업무, 서비스 상태, 최근 변경을 10초 안에 파악하게 한다.
3. 회원·커뮤니티·검사·콘텐츠·고객 의견·이벤트·시스템을 하나의 업무 언어로 연결한다.
4. 권한, 감사 기록, 실패 복구, 데이터 신선도와 같은 운영 안전장치를 화면 구조에 반영한다.

## 2. 현재 운영센터 감사 결과

### 2.1 잘 갖춰진 기반

- 관리자 이메일 허용 목록과 서버 전용 관리자 컨텍스트가 있다.
- 회원 정지·복구, 커뮤니티 조치, 연구 결정, 콘텐츠 검토, 고객 의견 상태 변경에 원자적 서버 작업과 감사 기록이 연결돼 있다.
- 신고·외부 링크·공식 투표·오늘의 질문·검사 품질·결과 문장 피드백을 운영 화면에서 확인할 수 있다.
- 환경 변수, 데이터베이스, RPC, 저장소 연결을 시스템 화면에서 점검한다.
- 감사 기록 CSV 내보내기와 민감정보 키 제외 처리가 있다.
- 데스크톱 사이드바와 모바일 전체 메뉴가 이미 분리돼 있다.

### 2.2 UI/UX 문제

| 문제 | 현재 영향 | V3 개선 원칙 |
| --- | --- | --- |
| 앱과 같은 밝은 보라색 면, 원형 아이콘, 큰 둥근 카드 | 업무 도구보다 아기자기한 소비자 앱으로 인식됨 | 차콜·슬레이트 기반 셸, 흰 작업면, 작은 곡률, 얇은 경계선 |
| 화면마다 제목·상태·필터의 구조가 조금씩 다름 | 정보 탐색 속도 저하 | 공통 페이지 헤더·패널·상태 배지·표 형식 통일 |
| 카드가 많고 행 밀도가 낮음 | 많은 데이터를 비교하기 어려움 | 데스크톱은 표·행 중심, 모바일만 카드형 행 사용 |
| 현재 위치는 보이지만 상위 업무 영역이 약함 | 메뉴 관계를 다시 해석해야 함 | 상단에 업무 그룹 → 현재 메뉴 계층 표시 |
| 메뉴 이동은 사이드바에만 의존 | 반복 업무 시 이동 비용 증가 | `⌘K / Ctrl+K` 빠른 이동 메뉴 추가 |
| 활성·경고 색상이 브랜드 색과 섞임 | 상태 의미가 모호해짐 | 브랜드색은 선택·주요 작업, 의미색은 상태에만 사용 |
| 데이터 기준 시각이 보이지 않음 | 숫자의 신선도 판단이 어려움 | 운영 개요에 기준 시각 표시 |

### 2.3 기능 공백

#### P0 — 이번 V3에서 구현

- 전체 관리자 메뉴 빠른 이동과 키보드 검색
- 고객 의견·결과 문장 품질·검사 품질을 포함한 통합 업무 대기열
- 최근 7일 신규 회원과 미처리 품질 업무를 포함한 운영 지표 재구성
- 데이터 기준 시각과 부분 장애 상태의 명확한 표시
- 모든 관리자 화면에 적용되는 전문 관리자 시각 체계
- 데스크톱 1480px 작업 영역과 모바일 무가로스크롤 계약
- 공통 포커스, 호버, 상태, 빈 화면, 오류 화면 규칙

#### P1 — 데이터·권한 스키마와 함께 다음 릴리스에서 구현

- 역할 기반 접근 제어: 최고 관리자, 안전 운영자, 콘텐츠 편집자, 연구 검토자, 게시 승인자, 읽기 전용
- 업무 담당자, 우선순위, 마감 시각, SLA 초과 알림
- 목록 서버 페이지네이션, 복합 필터, 저장된 보기, 일괄 작업
- 콘텐츠 버전 비교, 변경 전후 diff, 예약 발행 실패 재시도, 롤백
- 운영 기록의 기간·관리자·업무·결과 필터와 변경 전후 비교
- 장애·점검 공지, 배치 작업·웹훅·메일 발송 실패 큐
- 기능 플래그와 릴리스 상태 관리
- 광고 문의·캠페인·소재·슬롯·성과·정책 검수 관리
- 개인정보 열람·정정·삭제 요청과 보존 기간 작업 큐

#### P2 — 트래픽과 운영팀 확장 후 구현

- 다중 운영자 승인과 직무 분리
- 이상 징후 자동 탐지와 추천 우선순위
- KPI 추세, 코호트, 릴리스 주석, 비교 기간
- 운영자 개인 작업함과 교대 인수인계
- 광고 인벤토리 예측과 캠페인 정산

### 2.4 임의로 채우지 않을 데이터

다음은 현재 저장소에 신뢰 가능한 원천 데이터가 없어 숫자나 상태를 만들어 표시하지 않는다.

- 운영자 역할과 세부 권한
- 담당자·마감 시각·SLA
- 광고 문의·광고 캠페인·정산
- 장애·배치 작업·메일 실패 이력
- DAU·유지율·검사 전환율 시계열
- 개인정보 요청 처리 상태

각 기능은 전용 테이블, 감사 이벤트, 권한 정책, 보존 기간이 준비된 뒤 연다.

## 3. 운영자 핵심 업무

### 3.1 서비스 운영자

- 신규 회원과 주요 활동 변화를 확인한다.
- 신고, 게시물 대기, 고객 불편을 우선순위대로 처리한다.
- 이벤트 응모·추첨·당첨자 연락을 관리한다.
- 서비스 장애나 필수 설정 누락을 확인한다.

### 3.2 콘텐츠·검사 운영자

- 문항 이해 어려움과 결과 적합도 신호를 버전별로 살핀다.
- 결과 리포트 문장의 불일치 신호를 검토한다.
- 성향지도 콘텐츠 릴리스와 검토 상태를 관리한다.
- 근거·검토·승인·발행 순서를 운영 가이드에 맞춰 수행한다.

### 3.3 안전·감사 담당자

- 회원과 콘텐츠 조치가 근거와 함께 기록됐는지 확인한다.
- 외부 링크, 신고, 반복 작성 위험을 검토한다.
- 관리자 조치의 대상·결과·시각을 검색하고 내보낸다.

## 4. 정보 구조

### 서비스 운영

1. 운영 개요 — 업무 대기열, 지표, 이벤트, 최근 활동, 부분 장애
2. 회원 관리 — 검색, 상태, 공개 프로필, 계정 조치
3. 커뮤니티 — 신고, 게시물, 외부 링크, 공식 콘텐츠
4. 고객 의견 — 제품 의견, 검사 품질, 결과 문장 품질
5. 이벤트 — 캠페인, 응모, 추첨, 연락

### 품질 관리

6. 검사 연구 — 문항 위험 신호, 연구 결과, 운영 결정
7. 성향 콘텐츠 — 릴리스, 원자 콘텐츠, 전문 검토, 운영 가이드

### 거버넌스

8. 운영 기록 — 관리자 조치, 대상, 메타데이터, CSV
9. 시스템 상태 — 환경, DB, 저장소, RPC, 필수·보완 구분

`운영 설정`보다 `거버넌스`가 감사와 시스템 안전의 성격을 더 정확히 전달하므로 V3에서 명칭을 변경한다.

## 5. V3 시각 시스템

### 5.1 톤

- 배경: 차가운 회색 작업 배경
- 사이드바: 딥 네이비·차콜
- 작업면: 순백색 또는 아주 옅은 슬레이트
- 주요 작업: 절제된 인디고
- 성공: 짙은 초록
- 주의: 앰버
- 위험: 적색
- 정보: 청색

보라색 장식 면, 그라데이션 아바타, 큰 원형 배지, 과도한 그림자를 제거한다. 색은 장식이 아니라 상태와 선택을 전달한다.

### 5.2 형태

- 기본 패널 곡률: 8px
- 입력·버튼 곡률: 6px
- 상태 배지 곡률: 4px
- 아이콘 배경은 필요한 경우에만 6px 사각형으로 사용
- 데스크톱 목록은 행·구분선·정렬된 숫자 열을 우선
- 그림자는 떠 있는 메뉴와 확인창에만 사용

### 5.3 타이포그래피

- 페이지 제목은 크기보다 무게와 간격으로 위계를 만든다.
- 영문 라벨은 장식 문구가 아니라 시스템 영역 식별자로만 사용한다.
- 숫자는 tabular numeral을 사용한다.
- 본문은 13~14px, 표 보조 정보는 12px를 기본으로 한다.

## 6. 공통 셸

### 6.1 데스크톱

- 248px 고정 사이드바
- 64px 상단 도구 막대
- 최대 1480px 작업 영역
- 사이드바 상단: `NUANG / OPERATIONS CONSOLE`
- 운영자 세션은 카드가 아닌 작은 계정 행으로 표시
- 활성 메뉴는 어두운 선택 면과 3px 왼쪽 표시선 사용
- 상단 왼쪽: `업무 그룹 / 현재 메뉴`
- 상단 오른쪽: 빠른 이동, 인증 상태, 서비스 화면

### 6.2 모바일

- 짙은 단일 헤더로 고객 앱과 즉시 구분
- 현재 메뉴와 전체 메뉴를 두 줄로 중복 표시하지 않음
- 메뉴는 전체 화면에 가까운 드롭다운으로 제공
- 모든 주요 작업은 44px 이상
- 표는 핵심 열만 남긴 카드형 행으로 변환
- 가로 스크롤 없이 검토와 상태 변경 가능

### 6.3 빠른 이동

- 상단 버튼 또는 `⌘K / Ctrl+K`로 연다.
- 메뉴 이름, 그룹, 업무 키워드로 필터한다.
- 현재 메뉴를 표시한다.
- Escape로 닫고 배경 스크롤을 막는다.
- 실제 데이터 검색과 혼동하지 않도록 `메뉴 및 업무 이동`으로 명명한다.

## 7. 운영 개요

### 7.1 헤더

- 제목: 운영 개요
- 상태: 처리 대기 건수 또는 정상
- 데이터 기준 시각
- 부분 장애가 있으면 정상 상태 문구 대신 연결 확인 필요를 우선 표시

### 7.2 통합 업무 대기열

우선순위 순서:

1. 신고 검토
2. 게시물 상태 확인
3. 검사 품질 우선 검수
4. 결과 문장 검토
5. 고객 의견 확인
6. 연구 문항 검토
7. 성향 콘텐츠 현황

`null`은 0이 아니라 `연결 확인`으로 표시한다. 건수가 0이면 완료 상태로 보이되 목록에서 제거하지 않아 운영 범위를 알 수 있게 한다.

### 7.3 핵심 지표

- 활성 회원
- 최근 7일 신규 회원
- 커뮤니티 대기
- 품질·고객 의견 대기
- 완료된 연구
- 이벤트 응모

현재 값만 제공하며 추세 데이터가 없으면 상승·하락 화살표를 만들지 않는다.

### 7.4 운영 상태

- 이벤트 진행 상태
- 최근 관리자 활동 5건
- 불러오지 못한 모듈
- 데이터 기준 시각

## 8. 메뉴별 UX 기준

### 회원 관리

- 검색과 상태 필터를 한 줄 도구 막대로 제공
- 회원 행은 이름·코드·상태·가입일·최근 활동을 비교 가능하게 정렬
- 상세 화면에서 계정 상태, 공개 프로필, 연락처 보유 여부, 조치 이력을 분리
- 정지·복구는 대상과 영향을 확인하는 확인창을 유지

### 커뮤니티

- 신고, 게시물, 외부 링크, 공식 콘텐츠를 상위 보기로 분리
- 대기 건수를 보기 라벨에 표시할 수 있도록 후속 데이터 계약 준비
- 조치 버튼은 상태·이유·결과를 명확히 표시
- 공식 콘텐츠 편집과 실제 피드 미리보기의 시각 언어를 분리

### 고객 의견

- 검사 품질 → 결과 문장 품질 → 제품 의견 순으로 운영 위험을 정렬
- 문항·문장 품질은 표본과 비율을 함께 표시
- 표본 부족과 우선 검수를 같은 색으로 표시하지 않음
- 상태 변경 후 감사 기록과 알림 결과를 분리해 안내

### 이벤트

- 캠페인 상태, 응모, 추첨, 연락을 단계별로 표시
- 추첨처럼 되돌리기 어려운 작업은 전용 확인창과 감사 기록 필수
- 개인정보 노출을 최소화하고 연락 상태 중심으로 운영

### 검사 연구·성향 콘텐츠

- 연구 데이터와 고객 공개 콘텐츠의 상태를 명확히 분리
- 검토 필요, 변경 요청, 승인, 발행 상태를 같은 언어로 통일
- 운영 가이드를 콘텐츠 메뉴 안에서 계속 접근 가능하게 유지
- 결과 문장 품질에서 콘텐츠 수정 후보로 이어지는 연결은 P1 작업 흐름으로 확장

### 운영 기록

- 기본은 최근순 타임라인이 아닌 밀도 높은 행 목록
- 검색, CSV, 민감 키 제외를 유지
- 기간·관리자·업무·결과 필터와 변경 전후 diff는 P1

### 시스템 상태

- `정상 / 운영 보완 / 출시 필수`를 색과 문구로 동시에 구분
- 키나 환경 변수 값 자체는 노출하지 않고 설정 여부만 표시
- 점검 시각과 다시 확인 기능을 유지

## 9. 상태와 오류 규칙

- 로딩: 화면 전체 캐릭터 대신 작은 중립형 진행 표시
- 빈 상태: 정상적으로 0건인지 저장소가 없는지 구분
- 부분 장애: 가능한 데이터는 유지하고 불가 모듈만 명시
- 저장 중: 버튼 중복 클릭 차단
- 저장 성공: 변경 결과와 다음 상태를 안내
- 저장 실패: 저장되지 않았음을 분명히 말하고 재시도 제공
- 위험 작업: 대상, 영향, 되돌리기 가능 여부, 감사 기록을 확인창에 표시

## 10. 보안·접근성 기준

- 모든 관리자 페이지 `noindex, nofollow`
- 서버에서 관리자 컨텍스트 재검증
- 서비스 역할 키와 민감 설정값은 DOM에 노출하지 않음
- 아이콘 단독 버튼은 접근 가능한 이름 제공
- 키보드만으로 메뉴, 필터, 확인창, 빠른 이동 사용 가능
- 포커스 표시 대비 3:1 이상
- 의미색에만 의존하지 않고 텍스트 상태 병기
- 모바일 44px 터치 대상
- 감사 메타데이터에서 연락처·토큰·암호화 키 제외

## 12. 구현 결과 기록

### 12.1 완료된 P0

- 공통 메뉴 원천을 admin-navigation.ts로 통합하고 사이드바·모바일 메뉴·빠른 이동이 같은 정보를 사용하도록 구성했다.
- 데스크톱 운영 셸을 248px 딥 네이비 사이드바, 64px 상단 도구 막대, 최대 1480px 작업 영역으로 개편했다.
- 운영 개요에 신고, 게시물, 검사 품질, 결과 문장, 고객 의견, 연구, 콘텐츠를 포함한 통합 작업 큐를 연결했다.
- 활성 회원, 최근 7일 신규 회원, 커뮤니티 대기, 품질·의견 대기, 완료 연구, 이벤트 응모 지표를 실제 집계값으로 제공한다.
- 집계 기준 시각과 부분 연결 실패를 정상 상태와 구분해 표시한다.
- 회원·연구·콘텐츠·이벤트·시스템·운영 기록의 패널, 입력, 버튼, 상태 표시를 관리자 시각 규칙에 맞췄다.
- 빠른 이동은 검색, 현재 메뉴 표시, Escape 닫기, 배경 스크롤 잠금, 포커스 복귀와 순환을 지원한다.

### 12.2 검증 결과

- 관리자 관련 테스트: 6개 파일, 12개 테스트 통과
- 전체 회귀 테스트: 366개 파일, 1,673개 테스트 통과
- TypeScript 타입 검사 통과
- ESLint 경고·오류 없이 통과
- Next.js 운영 빌드 통과
- 변경 파일 공백·충돌 검사 통과
- 라이브 화면 자동 점검은 앱 내 브라우저의 localhost URL 정책으로 실행하지 못했으며, 우회 자동화는 사용하지 않았다.

### 12.3 다음 릴리스로 남긴 실제 공백

P1·P2 항목은 화면만 만들어 동작하는 것처럼 보이지 않게 유지했다. 역할·담당자·SLA·광고 운영·개인정보 요청·장애 작업 큐를 구현하려면 2.3절에 정의한 전용 데이터와 권한 계약이 먼저 필요하다.

## 13. 완료 기준

1. 관리자 화면이 고객 앱과 즉시 구분된다.
2. 운영자는 첫 화면에서 대기 업무와 서비스 데이터 상태를 10초 안에 파악한다.
3. 모든 메뉴는 동일한 색상, 패널, 상태, 포커스 체계를 사용한다.
4. 데스크톱은 데이터 비교에 충분한 밀도를 가지며 모바일은 가로 스크롤 없이 핵심 작업을 수행한다.
5. 준비되지 않은 권한·광고·SLA·추세 데이터는 가짜 값이나 장식 그래프로 표시하지 않는다.
6. 기존의 관리자 조치, 감사 기록, 데이터센터 운영 가이드가 손상되지 않는다.
