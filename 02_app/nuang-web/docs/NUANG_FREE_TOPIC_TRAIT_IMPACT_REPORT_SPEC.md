# 뉴앙 주제검사 성향 반영 리포트 기획서

- 문서 상태: 구현 기준 확정
- 작성일: 2026-08-03
- 적용 범위: 정식 주제검사 결과 리포트, 다른 기기 결과 조회, 공개 원본 리포트, 검사 스튜디오 미리보기
- 제외 범위: 별난 연구, 함께하기, 밸런스 게임

## 1. 목표

주제검사를 마친 사용자가 이번 답변이 현재 뉴앙 코드와 다섯 가지 성향 설명에 어떤 내용을 더했는지 바로 이해하게 한다.

이 기능은 사람의 성격이 실제로 변한 비율을 측정하는 기능이 아니다. 같은 계산 시각에서 검사 직전과 직후의 뉴앙 성향 추정값을 비교하여, **이번 답변을 추가한 뒤 뉴앙이 이해한 사용자의 모습이 얼마나 조정됐는지** 설명하는 기능이다.

핵심 수용 기준은 다음과 같다.

1. 정확히 달라진 값이 없으면 반드시 `이번에는 달라진 부분이 없어요`라고 알린다.
2. 0과 아주 작은 차이를 구분한다.
3. 코드 글자가 그대로인 점수 조정과 실제 코드 글자 변경을 구분한다.
4. 비교할 코어 결과가 없는 상태, 동기화 전 상태, 과거 변화 기록이 없는 상태를 0 변화로 표시하지 않는다.
5. 완료 당시 전후 값을 결과와 함께 동결하여 나중의 검사나 채점 변경이 과거 설명을 바꾸지 않게 한다.
6. 별난 연구와 함께하기 결과는 뉴앙 코드에 반영하지 않는다.

## 2. 사용자에게 보여줄 개념

### 2.1 사용 용어

- 섹션 작은 제목: `이번 검사와 내 뉴앙코드`
- 설명: `이번 답이 지금까지 쌓인 내 성향 설명에 어떤 내용을 더했는지 보여드려요.`
- 변화가 있을 때의 안내: `이번 답을 더해 뉴앙이 이해한 내 모습이 조금 조정된 거예요. 성격이 갑자기 바뀌었다는 뜻은 아니에요.`
- 변화 없음·코어 없음·유효 근거 부족·최신 결과 아님은 실제 계산 상태에 맞는 별도 안내를 사용한다.

### 2.2 사용하지 않을 표현

- 성향이 N% 바뀌었어요
- 정확도가 N% 올랐어요
- 진짜 I가 됐어요
- 성격이 개선됐어요 / 나빠졌어요
- 통계적으로 의미 있는 변화예요

현재 계산에는 표준오차와 신뢰구간이 없으므로 변화율, 정확도 상승률, 통계적 유의성처럼 읽히는 표현을 사용하지 않는다.

## 3. 리포트 정보 구조

카드는 주제검사 자체 결과를 먼저 읽을 수 있도록 `행동별 결과` 또는 `도움별 결과` 다음에 둔다. 현재의 `검사 당시 뉴앙 코드` 해석보다 앞에 배치한다.

모바일 카드 순서는 다음과 같다.

1. `이번 검사와 내 뉴앙코드`
2. 상태 배지
3. 핵심 제목 한 문장
4. 쉬운 설명 한두 문장
5. 실제 코드 글자가 변경된 경우에만 이전 코드 → 현재 코드
6. 영향을 받은 성향 방향 최대 3개
7. 나머지 항목 요약
8. 계산을 오해하지 않도록 돕는 공통 안내

코드는 다섯 칸 동일 너비 그리드로 표시한다. 색상만으로 변경 여부를 알리지 않고 `G에서 A로 달라졌어요`처럼 완전한 문장을 함께 제공한다.

## 4. 상태와 최종 문구

### 4.1 변화 없음

- 조건: 영향을 받은 모든 축의 전후 차이가 부동소수 허용 범위 0.05점 이내이고 코드가 같다.
- 배지: `변화 없음`
- 제목: `이번에는 달라진 부분이 없어요`
- 설명: `이번 답은 지금까지 나타난 성향 흐름과 비슷했어요. 현재 뉴앙코드는 그대로예요.`

### 4.2 아주 작은 조정

- 조건: 가장 큰 절대 차이가 0.05점 초과, 3점 미만이고 코드가 같다.
- 배지: `조금 반영됐어요`
- 제목: `뉴앙코드는 그대로예요`
- 설명: 방향 사전의 쉬운 표현을 사용해 `이번 답에서는 상대의 마음을 살피는 모습이 아주 조금 더 나타났어요.`처럼 쓴다.

### 4.3 더 뚜렷해짐

- 조건: 코드 글자는 같고 중심에서의 거리가 전보다 커졌다.
- 배지: `더 또렷해졌어요`
- 제목: `한 가지 모습이 더 뚜렷해졌어요`
- 설명: `뉴앙코드는 그대로지만 이 부분을 더 분명하게 설명할 수 있게 됐어요.`

### 4.4 두 방향의 차이가 줄어듦

- 조건: 코드 글자는 같고 점수가 50점 중심에 가까워졌다.
- 배지: `두 모습이 함께 보여요`
- 제목: `두 모습의 차이가 줄었어요`
- 설명: `상황에 따라 두 방향의 모습이 함께 나타날 수 있어요. 현재 뉴앙코드는 그대로예요.`

### 4.5 반대쪽 특징이 보였지만 코드 유지

- 조건: 원점수 방향은 반대가 되었지만 누적 근거 안정화 규칙으로 현재 글자를 유지했다.
- 배지: `코드 유지`
- 제목: `반대쪽 모습도 함께 보였어요`
- 설명: `이번 답에서는 반대쪽 모습도 나타났지만, 지금까지 쌓인 결과를 함께 보면 현재 코드를 유지하는 편이 더 자연스러워요.`

### 4.6 코드 글자 변경

- 조건: 전후 코드의 한 자리 이상이 실제로 다르다.
- 배지: `코드가 조정됐어요`
- 제목: 한 자리면 `뉴앙코드 한 글자가 달라졌어요`, 여러 자리면 `뉴앙코드 N글자가 달라졌어요`
- 설명: `관계를 바라보는 자리의 G가 A로 달라졌어요. 지금까지 쌓인 답을 함께 보니 A 쪽 모습이 더 뚜렷하게 나타났다는 뜻이에요.`

### 4.7 비교할 코어 결과 없음

- 배지: `비교 준비 중`
- 제목: `아직 비교할 뉴앙코드가 없어요`
- 설명: `코어 검사를 마치면 이번 답도 함께 살펴 내 뉴앙코드를 만들어요.`

### 4.8 유효한 성향 근거 없음

- 배지: `이번 결과만 확인`
- 제목: `이번 검사에서는 코드에 반영할 내용이 충분하지 않았어요`
- 설명: `검사 결과는 그대로 볼 수 있고, 현재 뉴앙코드는 달라지지 않았어요.`

### 4.9 로컬 저장·서버 반영 중

- 제목: `이번 답을 내 코드에 더하고 있어요`
- 설명: `잠시 후 이번 검사로 달라진 부분을 보여드릴게요.`
- 이 상태를 변화 없음으로 대체하지 않는다.

### 4.10 비로그인

- 제목: `로그인하면 내 코드에 이어서 반영해요`
- 설명: `검사 결과는 이 기기에 저장되어 있어요.`

### 4.11 과거 변화 스냅샷 없음

과거 결과를 현재 프로필에서 역산하지 않는다. 기존의 `검사 당시 뉴앙 코드`만 보여주고 변화 카드는 생략한다.

### 4.12 같은 주제 재검사

- 변화가 있으면 `지난번 같은 주제 결과를 이번 답으로 바꿔 반영했어요.`라고 알린다.
- 변화가 없으면 `지난번 같은 주제 결과와 비슷한 흐름이에요.`라고 알린다.
- 이전 결과와 이번 결과를 단순 점수 순위로 비교하지 않고, 현재 대표 프로필에서 이전 최신 결과를 이번 결과로 교체한 전후만 설명한다.

### 4.13 더 최신인 같은 주제 결과가 있음

- 제목: `더 최근의 같은 주제 결과를 반영하고 있어요`
- 설명: 결과는 보관하지만 현재 뉴앙코드에는 가장 최근에 완료한 같은 주제 결과를 사용한다.

## 5. 계산 정책

### 5.1 비교 기준

1. 서버에서 사용자의 최신 코어 결과와 주제별 최신 결과를 한 번 읽는다.
2. 서버 시각 `calculatedAt`을 한 번만 만든다.
3. 기존 자료만으로 `before`를 계산한다.
4. 서버가 다시 채점한 이번 주제 결과를 메모리에 추가해 같은 시각으로 `after`를 계산한다.
5. 같은 주제 재검사는 현재 엔진의 규칙대로 이전 최신 결과를 새 결과로 교체한다.
6. 새 결과보다 완료 시각이 더 늦은 동일 주제 결과가 이미 있다면 새 결과는 현재 대표 코드에 선택되지 않은 상태로 기록한다.

### 5.2 변화량

- 축별 변화량: `after.score - before.score`
- 저장 정밀도: 소수 첫째 자리
- 변화 없음 허용 범위: 절대값 0.05점 이하
- 작은 조정: 0.05점 초과 3점 미만
- 눈에 띄는 조정: 3점 이상 7점 미만
- 비교적 큰 조정: 7점 이상
- 코드 글자가 달라졌다면 점수 구간보다 코드 변경 상태를 우선한다.

3점 경계는 기존 동적 성향 계산의 `minMeaningfulDelta`와 맞춘 제품 표시 정책이다. 임상적 또는 통계적 유의성 기준으로 설명하지 않는다.

### 5.3 방향 설명

방향 이름과 설명은 별도 사전을 만들지 않고 `candidate-profile-names.ts`의 `candidateAxisCopy`와 `getCandidateDirectionCopy()`를 단일 출처로 사용한다.

## 6. 결과 동결 계약

`assessment.free_topic_result.evidence_payload`에 `traitImpactSnapshot`을 저장한다. JSONB 필드를 사용하므로 이 릴리스에는 별도 마이그레이션이 필요 없다.

```ts
type TopicTraitImpactSnapshot = {
  version: "topic-trait-impact.v1";
  calculatedAt: string;
  state:
    | "ready"
    | "no_baseline"
    | "insufficient_evidence"
    | "not_selected_as_latest";
  degree: "none" | "small" | "clear" | "large" | "code_changed";
  isRetest: boolean;
  before: TraitProfileSnapshot | null;
  after: TraitProfileSnapshot | null;
  affectedDomains: TopicTraitDomainImpact[];
  codeChanged: boolean;
};
```

전후 프로필은 코드, 프로필 이름, 다섯 영역의 점수, 글자, 원점수 글자, 경계 여부, 근거 가중치, 근거 수를 보존한다.

클라이언트가 보낸 변화값은 신뢰하지 않는다. 답변을 서버에서 다시 채점하고 서버가 전후 스냅샷을 만든다.

## 7. 저장 안정성

1. 서버가 결과 UUID를 insert 전에 생성한다.
2. 메모리 계산의 resultId와 DB id에 같은 UUID를 사용한다.
3. 완성된 변화 스냅샷과 최종 리포트를 최초 insert에 함께 넣어 반쪽 결과를 만들지 않는다.
4. 같은 after 프로필을 `scoring.account_trait_profile`에 저장한다.
5. 프로필 저장 실패 시 200을 반환하지 않고 503으로 재시도를 유도한다.
6. 동일 localResultId 재시도의 23505 경로에서는 기존 결과를 중복 생성하지 않고 현재 프로필을 권위 데이터로 다시 계산해 수선한다.
7. 결과 스냅샷은 이후 삭제나 재검사로 바꾸지 않는다.

완전한 계정 단위 직렬화는 향후 revision/CAS 또는 advisory-lock RPC로 확장한다. 이번 릴리스에서는 완성 스냅샷 단일 insert와 재시도 수선으로 사용자 결과의 영구 미완성을 막는다.

## 8. API·표시 연결 범위

- `StoredFreeTopicResult` 결과 계약
- POST/GET `/api/free-topic-results`
- 로컬 결과의 서버 canonical 결과 교체
- 다른 기기 결과 조회
- `FreeTopicResultView`
- 공개 프로필 원본 주제 리포트
- 검사 스튜디오 실제 고객 리포트 미리보기

운영센터 미리보기는 실제 고객 카드 컴포넌트를 재사용하고 계정 데이터를 읽거나 수정하지 않는 고정 스냅샷을 사용한다.

## 9. 모바일·접근성 기준

- 320px부터 가로 스크롤 없음
- 카드 좌우 여백 최소 16px, 가능하면 20px
- 본문 15~16px 이상, 줄간격 1.55 이상
- 터치 대상 최소 44×44px
- 고정 높이 사용 금지
- 코드 다섯 자리는 `repeat(5, minmax(0, 1fr))`
- 상승·하락을 초록·빨강으로 구분하지 않음
- 색상 외에 완전한 상태 문장 제공
- 화면 낭독기용 라벨에 이전 코드, 현재 코드, 바뀐 자리 포함
- `prefers-reduced-motion`에서 전환 애니메이션 제거
- 동기화 후 카드 갱신은 `aria-live="polite"`

## 10. 필수 검증

### 순수 계산

- 정확히 0과 0.1 차이 구분
- 저장 정밀도에 맞춘 2.9와 3.0 경계
- 같은 글자를 유지하며 더 뚜렷해짐
- 중심에 가까워짐
- 반대 원점수가 보이지만 안정화로 코드 유지
- 실제 코드 한 자리 변경
- 여러 자리 변경 정렬
- 코어 결과 없음
- 유효 근거 부족
- 같은 주제 재검사 교체
- 더 최신인 동일 주제 결과가 이미 있는 경우
- before/after 계산 시각 동일

### 저장·조회

- 클라이언트 조작 변화값 무시
- 최초 insert에 완성 스냅샷 저장
- `profile_code_at_completion === after.code`
- 프로필 저장 실패 시 503
- 중복 재시도에서 프로필 수선
- 다른 기기 GET에서 동일 스냅샷 재현
- 과거 스냅샷 없는 결과 임의 재해석 금지

### 화면

- 비로그인·동기화 중·변화 없음·코어 없음이 서로 다른 문구
- 로그인 필요 상태에는 로그인 동선, 연결 실패 상태에는 실제 재시도 버튼 제공
- 320px 모바일과 긴 한글 문장
- 실제 앱과 검사 스튜디오가 같은 카드 사용
