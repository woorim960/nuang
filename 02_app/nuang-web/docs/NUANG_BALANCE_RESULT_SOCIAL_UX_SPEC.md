# 뉴앙 밸런스게임 결과 소셜 UX 개편 기획서

> 상태: 사용자 검토·승인 대기
> 범위: `/assessments/together/balance-game/rooms/{code}/result`
> 원칙: 이 문서가 승인되기 전에는 UI, API, 데이터, 일러스트를 구현하지 않는다.

## 1. 한 줄 정의

결과 페이지를 점수를 확인하고 끝내는 화면에서, **사람을 고르고 서로의 같은 선택과 다른 선택을 자연스럽게 이야기하는 관계 화면**으로 바꾼다.

## 2. 현행 화면 진단

현재 결과 화면에는 그룹 점수, 1:1 비교, 문항별 인원, 초대와 공유 기능이 이미 있다. 기능의 기반은 충분하지만 다음 문제가 있다.

- 1:1 비교 대상이 텍스트 행으로만 보여서 ‘사람을 선택한다’는 감각이 약하다.
- 참여자 프로필과 그룹의 관계가 첫 화면에서 보이지 않는다.
- 문항 선택 분포가 `2명 / 0명` 같은 숫자로만 보여 비율을 빠르게 읽기 어렵다.
- 그룹 결과와 1:1 결과가 별도 화면처럼 갈라져 비교 맥락이 끊긴다.
- 점수 주변 설명이 길고 추상적이다. 일부 문구는 실제 대화에서 잘 쓰지 않는 표현이다.
- 결과 화면만의 기억 요소가 없고, 기존 범용 아이콘이 섞여 있다.
- ‘관계를 발전시키는 다음 행동’은 일반적인 안내 문장 한 줄에 그쳐 실제 대화로 이어지기 어렵다.

## 3. 사용자 역할별 고민

| 사용자 | 원하는 것 | 불편하거나 걱정되는 것 | 설계 반영 |
| --- | --- | --- | --- |
| 방장 | 전체 분위기와 참여 상태를 빨리 파악하고 공유하고 싶다 | 관리 기능이 결과보다 앞에 나오면 흐름이 무거워진다 | `모두` 탭을 기본값으로 두고 초대·마감은 하단에 유지한다 |
| 친한 친구·연인 | 특정 사람과 어디가 같고 다른지 보고 대화를 이어가고 싶다 | 점수로 관계를 평가받는 느낌은 싫다 | 프로필 선택 → 같은 선택/다른 선택 → 대화 카드 순서로 보여준다 |
| 가벼운 초대 참여자 | 가입 없이 부담 없이 결과를 보고 싶다 | 계정·사진·공개 프로필이 뜻하지 않게 드러나는 것이 걱정된다 | 방 전용 아바타를 기본으로 쓰고 공개 프로필 연결은 별도 동의를 받는다 |
| 3~8명 그룹 | 누가 어느 답을 골랐는지 한눈에 보고 싶다 | 이름이 길게 늘어지고 숫자만으로는 분포를 읽기 어렵다 | 비율 게이지와 작은 아바타 묶음을 함께 제공한다 |
| 모션 민감·저사양 사용자 | 같은 정보를 안정적으로 읽고 싶다 | 계속 움직이는 물결과 캐릭터가 집중을 방해할 수 있다 | 정적 상태를 기본 정보로 완성하고 `prefers-reduced-motion`에서는 모든 반복 모션을 멈춘다 |
| 키보드·스크린리더 사용자 | 프로필과 비율을 시각 정보 없이도 이해하고 싶다 | 색, 물결, 얼굴만으로 상태를 구분할 수 없다 | 프로필은 탭 역할, 게이지는 정확한 값과 텍스트를 가진 `progressbar`로 제공한다 |

## 4. 통합 설계 원칙

1. **사람이 먼저 보인다.** 점수보다 함께한 사람과 선택 가능한 프로필을 먼저 인지하게 한다.
2. **전체와 1:1을 한 화면에서 오간다.** 페이지 이동 없이 프로필을 누르면 같은 위치의 내용이 해당 관계 기준으로 바뀐다.
3. **같음과 다름을 동등하게 다룬다.** 일치율을 관계 등급처럼 표현하거나 더 높은 점수를 좋은 관계로 해석하지 않는다.
4. **숫자는 바로 읽히게 한다.** 분포는 `선택 완료자 중 선택 인원`의 정확한 비율로 채운다.
5. **말은 짧고 일상적으로 쓴다.** 해석보다 사실, 설명보다 다음 행동을 보여준다.
6. **장식도 기능을 가진다.** 캐릭터는 현재 결과 상태를 안내하고, 물결은 비율을 보여주는 채움 안에서만 움직인다.
7. **공개는 선택이다.** 방 안의 닉네임·아바타와 공개 프로필 연결을 분리한다.

## 5. 최종 화면 구성

### 5.1 모바일 정보 구조

```text
┌─────────────────────────────────┐
│ ←                  우리의 선택  │
├─────────────────────────────────┤
│ [결과 전용 듀오 캐릭터 장면]     │
│ 8개 중 5개가 같아요              │
│ 63% · 2명 완료                   │
├─────────────────────────────────┤
│ 누구와 비교할까요?               │
│ [모두] [나] [하린] [우림] ...    │  ← 프로필 탭
├─────────────────────────────────┤
│ 나 + 하린                        │
│ 같은 선택 5  ·  다른 선택 3      │
│ [둘의 선택 자세히 보기]          │
├─────────────────────────────────┤
│ 같이 얘기해 볼 것                │
│ “왜 이 답을 골랐어?”             │
│ “같이 한다면 어떤 쪽이 좋아?”     │
├─────────────────────────────────┤
│ 모두의 선택                      │
│ 모두가 같은 답을 선택했어요       │
│ 질문                             │
│ 선택 A             2/2명         │
│ [~~~~~~~~ 100% 물결 게이지 ~~~~] │
│ 선택 B             0/2명         │
│ [_____________________________] │
│ [A를 고른 프로필 묶음]            │
├─────────────────────────────────┤
│ 서로 다른 선택                   │
│ 서로 왜 골랐는지 이야기해 보세요  │
│ ...                              │
├─────────────────────────────────┤
│ 초대 · 결과 이미지 공유           │
│ 점수 계산 · 참여자 관리(접기)      │
└─────────────────────────────────┘
```

### 5.2 상단 관계 요약

- 기존 원형 점수판 대신 결과 전용 듀오 캐릭터와 사실형 요약을 한 덩어리로 배치한다.
- 그룹 상태에서는 `8개 중 5개 답이 같아요`, 1:1 상태에서는 `하린과 8개 중 5개가 같아요`처럼 표시한다.
- `%`는 보조 수치로 유지하고 문항 개수 표현을 더 크게 보여준다.
- `좋고 나쁨이 아니라` 같은 방어적 설명은 삭제한다.
- 결과가 아직 확정되지 않았다면 `2명 결과 · 1명 기다리는 중`만 작게 표시한다.

### 5.3 참여자 프로필 선택기

- `모두`를 첫 탭으로 두고, 그 뒤에 `나`, 다른 참여자를 입장 순서대로 배치한다.
- 다른 사람을 누르면 그룹 결과 영역이 같은 위치에서 해당 참여자와의 1:1 결과로 전환된다.
- 각 프로필은 52~56px 방 전용 오리지널 아바타, 닉네임, 현재 선택 상태로 구성한다.
- 현재 선택된 사람은 색뿐 아니라 테두리, 크기 변화, `선택됨` 상태로 함께 구분한다.
- 최대 8명은 가로 스크롤로 처리하되, 선택된 프로필이 항상 보이게 한다.
- 익명·비회원도 같은 품질의 방 전용 아바타를 가진다.
- 공개 프로필 연결은 로그인 계정이며 공개 설정에 동의한 참여자에게만 `프로필 보기`로 노출한다. 계정 ID나 공개 여부를 추측할 수 있는 정보는 내려주지 않는다.

### 5.4 1:1 관계 패널

- 선택한 두 사람의 아바타를 겹치지 않고 나란히 보여준다.
- `같은 선택 5`, `다른 선택 3`을 우선 표시하고 퍼센트는 보조로 둔다.
- `둘의 선택 자세히 보기`를 누르면 현재의 전체/같은 선택/다른 선택 필터가 같은 페이지 안에서 펼쳐진다.
- 선택한 프로필이 바뀌어도 스크롤 위치는 유지한다.
- 점수에 따른 관계 등급, 궁합 판정, 단정적인 조언은 만들지 않는다.

### 5.5 같이 얘기해 볼 것

관계를 발전시키는 기능은 성격을 단정하는 해석이 아니라, 결과를 보고 바로 꺼낼 수 있는 짧은 질문으로 제공한다.

- 같은 선택이 많은 문항: `우리 둘 다 이걸 고른 이유는?`
- 서로 다른 문항: `왜 이 답을 골랐어?`
- 함께 행동으로 이어질 수 있는 문항: `같이 한다면 어떤 쪽이 좋아?`
- 한 번에 최대 2개만 보여 정보 과잉을 막는다.
- 질문은 저장된 문항과 결과 유형으로 결정하는 규칙 기반 문구다. 생성형 문장을 호출하지 않는다.
- `새 질문` 같은 반복 기능은 두지 않고, 사용자가 문항을 펼치면 그 문항에 맞는 한 문장만 제공한다.

## 6. 문항 비율 게이지

### 6.1 계산 기준

```text
게이지 비율 = 해당 선택 인원 ÷ 결과에 포함된 선택 완료 인원
```

- 분모는 방 정원이나 현재 입장 인원이 아니라 `result.completedParticipantCount`다.
- 아직 선택을 완료하지 않은 사람은 어느 선택에도 포함하지 않는다.
- 숫자는 `2/3명`처럼 분자와 분모를 항상 함께 표시한다.
- 0%는 빈 트랙, 100%는 가득 찬 트랙으로 정확히 표시한다. 장식 때문에 실제 비율을 왜곡하지 않는다.

### 6.2 시각 표현

- 트랙은 중립색, 채움은 뉴앙 포인트 보라색 한 색만 사용한다.
- 두 선택 모두 같은 포인트 컬러를 사용하고, 선택지 간 차이는 채움 길이와 텍스트로 읽는다.
- 채움 상단에만 낮은 높이의 물결을 둔다. 물결은 게이지의 끝점을 넘지 않는다.
- 물결은 6~8초에 한 번 이동하는 느린 반복 모션으로 한다. 숫자 변경 시에만 240ms로 길이가 갱신된다.
- `prefers-reduced-motion: reduce`에서는 물결을 정지된 곡선으로 바꾸고 길이 변화도 즉시 반영한다.
- 스크린리더에는 `메시지로 정리해서, 완료자 3명 중 2명, 67퍼센트`로 전달한다.
- 게이지 아래에는 선택한 참여자의 방 전용 아바타를 최대 5개까지 보여주고, 나머지는 `+2`로 합친다.

## 7. 결과 전용 캐릭터와 아이콘

### 7.1 캐릭터 방향

- 결과 페이지에서만 쓰는 오리지널 벡터 캐릭터 한 쌍을 직접 제작한다.
- 기본 형태는 둥근 덩어리 캐릭터가 아니라, 두 개의 유연한 리본·고리 형태가 서로 연결되는 모습으로 잡는다.
- 눈과 표정은 작고 절제해서 아동용 캐릭터처럼 보이지 않게 한다.
- 색은 뉴앙 보라 한 색과 중립색을 중심으로 사용한다.
- 사진형·3D 렌더·스톡 일러스트·외부 이모지·기존 아이콘 라이브러리는 사용하지 않는다.

### 7.2 필요한 장면

1. 그룹 결과: 여러 고리가 하나의 흐름을 만드는 장면
2. 1:1 비교: 두 캐릭터 사이가 얇은 선으로 연결되는 장면
3. 모두의 선택: 두 캐릭터가 같은 방향을 바라보는 장면
4. 서로 다른 선택: 서로 다른 방향을 보지만 가운데 연결은 유지되는 장면
5. 초대: 한 캐릭터가 빈 자리를 가리키는 장면

### 7.3 모션

- 기본은 4~6px 범위의 호흡, 고리의 느린 탄성, 연결선의 짧은 파동만 사용한다.
- 프로필 전환 시 선택된 캐릭터가 180ms 안에 살짝 가까워지는 반응을 준다.
- 화면 밖 캐릭터의 애니메이션은 정지한다.
- `prefers-reduced-motion`에서는 첫 프레임의 완성된 정적 일러스트를 보여준다.
- 자바스크립트 프레임 루프 없이 SVG와 CSS transform/opacity만 사용한다.

### 7.4 아이콘

- 결과 페이지에서 쓰는 뒤로가기, 펼치기, 공유, 프로필, 초대 아이콘을 동일한 20px 그리드의 오리지널 SVG로 직접 그린다.
- 결과 페이지 내부에서는 Lucide, 운영체제 이모지, 외부 SVG 패키지를 불러오지 않는다.
- 표준 기능의 형태는 익숙하게 유지하고 선 끝·각도·곡률만 뉴앙 캐릭터와 맞춘다.
- 의미가 있는 아이콘에는 텍스트 레이블을 함께 두고, 장식 아이콘은 보조 기술에서 숨긴다.

문구 작성 규칙:

- `통했어요`, `개성이에요`, `반가운`, `궁금한`처럼 결과를 과하게 감정화하는 표현을 반복하지 않는다.
- `~해드려요`, `좋고 나쁨이 아니라`처럼 서비스가 사용자를 설득하는 문장을 쓰지 않는다.
- 수치, 사람, 다음 행동을 먼저 말한다.
- 관계를 진단하거나 결과보다 큰 의미를 부여하지 않는다.

## 9. 데이터·개인정보 설계

### 9.1 현재 데이터로 가능한 것

- 1:1 점수와 문항별 같은 선택/다른 선택은 이미 제공된다.
- 문항별 선택 인원과 완료자 수가 있어 정확한 게이지를 만들 수 있다.
- 데이터베이스에는 참여자 `avatar_seed`와 저장 결과의 `otherAvatarSeed`가 이미 정의돼 있다.

### 9.2 구현 시 계약에 추가할 것

- `BalanceRoomParticipantView.avatarSeed`
- `BalancePairResultView.otherParticipantAvatarSeed`
- 공개 프로필 연결을 승인할 경우에만 개인정보 정책을 거친 `publicProfileRef`와 `canOpenPublicProfile`

방 전용 아바타는 `avatarSeed`를 오리지널 SVG의 형태·표정 조합으로 매핑한다. 닉네임만 같다고 같은 아바타를 만들지 않으며, 계정 ID는 클라이언트로 보내지 않는다.

### 9.3 공개 프로필 원칙

- 방 참여만으로 공개 프로필을 자동 연결하지 않는다.
- 공개 프로필 사진·페이지 연결은 계정 소유자의 기존 공개 설정과 별도 노출 동의를 모두 만족할 때만 제공한다.
- 차단 관계, 탈퇴·퇴장 상태, 비공개 전환을 서버에서 다시 확인한다.
- 공유 이미지에는 참여자 닉네임, 실제 프로필 사진, 개인별 답변을 기본적으로 넣지 않는다.

## 10. 구현 범위 제안

### 10.1 1차 구현 — 권장

- 전체/참여자 프로필 탭
- 방 전용 오리지널 SVG 아바타
- 같은 선택·다른 선택을 한 화면에서 전환
- 단일 포인트 컬러 물결 게이지
- 선택한 사람 아바타 묶음
- 일상어 문구 전면 교체
- 결과 전용 캐릭터 5장면과 오리지널 아이콘
- 정적 접근성 상태와 reduced-motion 지원
- 기존 공유·초대·마감 기능 재배치

이 범위는 기존 결과 데이터와 이미 존재하는 `avatar_seed`를 활용할 수 있어 별도의 소셜 관계 테이블 없이 진행할 수 있다.

### 10.2 2차 구현 — 별도 승인

- 동의한 참여자의 공개 프로필 보기
- 공개 프로필에서 해당 밸런스 결과로 돌아오는 연결
- 피드 공유 결과에서 참여자 프로필 선택 기능

이 범위는 개인정보 공개 정책, 차단 정책, 프로필 공개 상태를 함께 설계해야 하므로 1차 구현과 분리한다.

## 11. 성능·접근성 기준

- 캐릭터와 아이콘은 외부 요청이 없는 인라인 또는 로컬 SVG로 만들고 전체 추가 자산은 gzip 기준 20KB 이하를 목표로 한다.
- 반복 모션은 transform/opacity만 사용하고 화면 밖에서는 정지한다.
- 게이지 값은 DOM 텍스트와 `role="progressbar"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`를 함께 제공한다.
- 프로필 선택기는 `tablist / tab / tabpanel` 관계와 키보드 방향키 이동을 지원한다.
- 모든 프로필·버튼 터치 영역은 최소 44×44px로 한다.
- 색을 제거해도 선택 상태, 인원수, 게이지 값, 같은/다른 결과를 이해할 수 있어야 한다.
- 320×568, 360×740, 390×844, 430×932와 데스크톱 중앙 셸에서 가로 넘침이 없어야 한다.
- 2명, 3명, 8명, 미완료 참여자 포함, 0/100/50% 분포를 각각 검증한다.
- 공식 접근성 원칙에 따라 비필수 모션은 운영체제의 동작 줄이기 설정에서 정지한다.

## 12. 구현 순서

1. 승인된 문구와 정보 구조를 테스트 기준으로 고정한다.
2. API 계약에 아바타 시드와 개인정보 안전 필드를 추가한다.
3. 결과 전용 SVG 캐릭터·아바타·아이콘을 직접 제작한다.
4. 프로필 탭과 한 화면 1:1 비교 상태를 구현한다.
5. 비율 계산과 물결 게이지를 구현한다.
6. 대화 카드와 하단 공유·관리 영역을 재배치한다.
7. 단위 테스트, 타입 검사, 린트, 빌드 검증을 수행한다.
8. 실제 2/3/8명 데이터로 모바일 화면과 전체 사용자 흐름을 검수한다.
9. 개인정보·접근성·성능 검토 후 완료한다.

## 13. 완료 조건

- 결과 첫 화면에서 참여자 프로필과 `모두` 선택기가 바로 보인다.
- 프로필을 누르면 페이지 이동 없이 그 사람과의 비교 결과가 갱신된다.
- 모든 문항 선택지는 `선택 인원 / 완료 인원` 비율과 정확히 일치하는 게이지를 가진다.
- 게이지는 한 가지 포인트 컬러만 사용하며 정지 상태에서도 같은 정보를 전달한다.
- 결과 페이지의 캐릭터·아바타·콘텐츠 아이콘은 모두 직접 제작한 SVG다.
- 지정된 AI투 문구와 `좋고 나쁨이 아니라` 표현이 결과 화면에서 제거된다.
- 익명 참여자의 계정·공개 프로필이 노출되지 않는다.
- 기존 결과 공유, 피드 공유, 초대, 마감, 참여자 관리 기능이 그대로 동작한다.
- 관련 테스트와 브라우저 모바일 검증이 모두 통과한다.

## 14. 승인 요청 사항

아래 내용을 한 묶음으로 승인받은 뒤 1차 구현을 시작한다.

1. 기본 진입 상태는 `모두`, 다른 프로필 선택 시 같은 화면에서 1:1 결과 전환
2. 게이지 분모는 방 정원이 아니라 결과에 포함된 선택 완료자 수
3. 단일 뉴앙 보라색 물결 게이지와 reduced-motion 정적 대체
4. 절제된 리본·고리 형태의 결과 전용 캐릭터와 방 전용 아바타
5. 결과 페이지의 기존 외부 아이콘을 오리지널 SVG 아이콘으로 교체
6. 문구 개편안 전체 적용
7. 공개 프로필 연결은 2차 범위로 분리하고 별도 승인
