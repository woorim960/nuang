# 뉴앙 공통 UI 기준

이 문서는 실제 앱 화면의 타이포그래피와 콘텐츠 작성 원칙을 정의합니다. 와이어프레임은 적용 대상에서 제외합니다. 실제 앱의 시각 토큰은 `src/app/global-theme.css` 한 파일에서 관리합니다.

## 1. 타이포그래피 기준

Apple은 iOS 기본 본문을 17pt, 최소 크기를 11pt로 안내하며, Material 3은 본문을 16sp/24sp와 14sp/20sp 중심으로 구성합니다. 뉴앙은 두 체계의 공통 범위를 모바일 한글 UI에 맞춰 아래처럼 사용합니다.

| 용도      | 토큰                      |      크기 | 기본 사용처                      |
| --------- | ------------------------- | --------: | -------------------------------- |
| 캡션      | `--nu-text-caption`       |      13px | 시간, 수치 보조, 상태 메타데이터 |
| 라벨      | `--nu-text-label`         |      14px | 탭, 태그, 짧은 보조 버튼         |
| 작은 본문 | `--nu-text-body-sm`       |      15px | 프로필 메타, 짧은 보조 문장      |
| 콜아웃    | `--nu-text-callout`       |      16px | 게시글, 입력 라벨, 보조 행동     |
| 본문      | `--nu-text-body`          |      17px | 검사 안내, 상세 설명             |
| 강조 본문 | `--nu-text-body-lg`       |      18px | 핵심 질문, 읽기 중심 문장        |
| 제목      | `--nu-text-title-sm` 이상 | 19px 이상 | 화면·섹션 제목                   |

원칙은 다음과 같습니다.

- 핵심 콘텐츠 본문을 16px 미만으로 만들지 않습니다.
- 13~14px는 없어도 과업을 수행할 수 있는 메타데이터와 짧은 라벨에만 사용합니다.
- 긴 한글 본문은 줄간격 1.58~1.6을 사용합니다.
- 색상만으로 중요도를 표현하지 않고 크기, 굵기, 위치를 함께 사용합니다.
- 글자 크기는 화면별 값이 아니라 공통 토큰을 변경해 조정합니다.

참고: [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Material 3 typography](https://developer.android.com/develop/ui/compose/designsystems/material3)

## 2. 한 파일에서 관리하는 범위

`global-theme.css`는 다음을 담당합니다.

- 글꼴, 크기, 줄간격, 굵기
- 중립색, 브랜드색, 기능별 색상과 의미 기반 색상
- 화면 배경, 표면, 본문, 경계선, 포커스 색상
- 로그인 제공자 공식 색상
- 여백 기준, 화면 너비, 최소 터치 영역
- 모서리, 그림자, 전환 속도와 이징
- Tailwind 공통 유틸리티 연결

화면별 CSS 모듈에는 컴포넌트의 배치와 구조만 둡니다. 색상이나 글자 크기를 새로 만들 때는 먼저 `global-theme.css`에 의미 기반 토큰을 추가합니다.

`npm run theme:check`는 실제 앱에 직접 입력한 색상, 임의 글자 크기, 숫자 굵기가 다시 생기는 것을 차단합니다.

## 3. 설명 없이 이해되는 콘텐츠 원칙

화면 문구는 아래 순서로 검토합니다.

1. 배치나 컴포넌트 모양만으로 동작을 이해할 수 있는가?
2. 버튼 이름을 더 정확하게 바꾸면 설명을 없앨 수 있는가?
3. 선택한 뒤 결과를 바로 보여주면 사전 설명을 없앨 수 있는가?
4. 그래도 오류, 안전, 공개 범위처럼 결과에 영향을 주는 정보인가?

1~3으로 해결되면 설명 문구를 제거합니다. 4에 해당하는 문구만 행동 직전에 짧게 보여줍니다.

### 유지할 문구

- 입력 오류와 복구 방법
- 저장·업로드·공개 범위처럼 사용 결과가 달라지는 상태
- 검사 응답 기준처럼 결과의 정확도에 직접 영향을 주는 안내
- 빈 상태에서 다음 행동을 알려주는 문구

### 제거하거나 축약할 문구

- 바로 위 탭이나 제목을 다시 설명하는 문장
- 선택지 자체로 이해할 수 있는 투표 방법
- 동일한 추천 이유를 제목과 본문에서 반복하는 문구
- 아이콘 옆 이름과 펼친 영역 제목에서 반복되는 수치 단위
- 제품 내부 구조나 개발 상태를 설명하는 문구

## 4. 화면별 개편 순서

1. 공통 내비게이션과 헤더
2. 커뮤니티와 글쓰기
3. 검사 허브와 모든 검사 진행 화면
4. 성향지도 목록과 상세
5. 홈
6. 마이, 프로필, 설정, 인증
7. 결과 리포트, 비교, 공유 화면
8. 오류, 로딩, 빈 상태, 정책과 도움말

각 묶음은 `중복 제목 → 반복 설명 → 불필요한 사전 안내 → 중복 버튼 → 메타데이터` 순서로 정리합니다. 기능의 의미나 신뢰에 필요한 정보는 삭제하지 않고, 필요한 순간에만 노출되도록 옮깁니다.
