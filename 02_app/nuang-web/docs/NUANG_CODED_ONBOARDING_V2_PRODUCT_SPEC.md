# 뉴앙 코드형 온보딩 V2 기획서

> 문서 상태: V3로 대체됨. 현재 구현 기준은 `NUANG_ONBOARDING_V3_PRODUCT_AND_VISUAL_SPEC.md`를 따른다.

- 문서 상태: 구현 기준 확정
- 기준일: 2026-08-03
- 대상: `/onboarding`
- 핵심 방향: 고정 이미지 네 장을 제거하고, 실제 텍스트·UI·뉴앙 캐릭터로 반응형 장면을 구성한다.

## 1. 문제 정의

현행 온보딩은 2:3 비율의 합성 이미지 네 장에 텍스트가 포함되어 있다.

- 현재 화면에서 직접 쓰는 네 자산은 약 2.69MiB다.
- 첫 두 장 priority 자산만 약 2.08MiB다.
- 텍스트 크기와 줄바꿈이 이미지에 고정되어 작은 모바일, 큰 글자, 번역에 대응하지 못한다.
- 화면이 낮으면 이미지 자체를 축소해 중요한 카피가 작아진다.
- 스크린리더는 이미지 alt 전체를 한 번에 읽어 정보 구조를 이해하기 어렵다.
- 카피 한 줄을 바꾸기 위해 이미지를 다시 제작해야 한다.

## 2. 목표

1. 320px 폭과 낮은 모바일 화면에서도 제목·설명·버튼을 읽기 쉽게 유지한다.
2. 사용자가 첫 화면에서 뉴앙이 `성향 검사 + 서로 이해하기 + 함께 즐기기` 서비스임을 안다.
3. 네 장의 장면을 HTML/CSS와 기존 뉴앙 캐릭터 자산으로 새로 조합한다.
4. 장식은 동적으로 보이되 성능과 접근성을 해치지 않는다.
5. 마지막 장면에서 3~5분 빠른 코어 검사로 자연스럽게 이어진다.

## 3. 화면 구조

공통 구조는 다음 순서를 유지한다.

1. 상단: NUANG wordmark, `건너뛰기`
2. 진행: 현재 장면을 나타내는 4개 progress segment
3. 본문: 실제 HTML 카피
4. 코드형 일러스트 장면
5. 하단: `다음` 또는 마지막 CTA

좌우 스와이프와 키보드 방향키를 유지하되, 모든 장면에 명확한 버튼을 제공한다. 스와이프를 몰라도 진행할 수 있어야 한다.

## 4. 장면별 설계와 카피

### G01 — 서비스 정체성

- 눈썹말: `나를 이해하는 새로운 시작`
- 제목: `성향을 발견하고,\n함께 즐겨요`
- 설명: `검사하고 비교하며, 나와 가까운 사람을 더 쉽게 이해하는 성향 놀이터예요.`
- 장면: 중앙 purple 캐릭터 주위에 `성향 검사`, `함께하기`, `성향지도` 카드가 천천히 떠다닌다.
- 목적: 뉴앙이 단순 검사 사이트가 아니라 성향 기반 SNS임을 첫 장에서 전달한다.

### G02 — 뉴앙코드

- 눈썹말: `나를 읽는 다섯 글자`
- 제목: `답할수록\n내 성향이 선명해져요`
- 설명: `다섯 가지 방향을 조합해 나만의 뉴앙코드를 만들고, 일상과 관계에서 보이는 특징을 읽어드려요.`
- 장면: `E N A K Q` 타일이 순서대로 정렬되고, 선택된 타일 아래에 짧은 일상 태그가 나타난다.
- 주의: 특정 코드가 우월하거나 고정된 성격처럼 보이지 않게 한다.

### G03 — 서로 이해하기

- 눈썹말: `비슷함도 다름도 재미있게`
- 제목: `친구와 비교하면\n대화가 더 쉬워져요`
- 설명: `함께 검사하고 취향과 성향을 비교해, 잘 맞는 점과 서로 다른 점을 가볍게 확인해 보세요.`
- 장면: purple·forest 캐릭터 사이에 공통점 카드와 차이점 카드가 연결된다.
- 주의: 가짜 궁합 점수나 검증되지 않은 수치를 장식으로 쓰지 않는다.

### G04 — 첫 행동

- 눈썹말: `첫 결과까지 3~5분`
- 제목: `빠른 코어 검사로\n바로 시작해요`
- 설명: `로그인 전에도 답할 수 있어요. 완료한 결과는 로그인하면 안전하게 이어집니다.`
- 장면: 질문 카드 3개가 체크되고 진행 링이 완성되며 캐릭터가 앞으로 움직인다.
- CTA: `빠른 코어 검사 시작하기`

## 5. 코드형 일러스트 시스템

- 기존 `NuangCharacter`의 transparent WebP를 장식 캐릭터로 재사용한다.
- 새로운 장면 자체는 div, text, CSS shape, inline SVG progress로 만든다.
- 장면 컴포넌트는 `PlaygroundScene`, `CodeScene`, `TogetherScene`, `QuickStartScene`으로 분리한다.
- 캐릭터 이미지는 이미 사용 중인 캐시 자산만 사용하고 새로운 대형 합성 이미지를 만들지 않는다.
- 장식 요소는 `aria-hidden=true`, 실제 정보는 HTML 제목·설명에 둔다.

### 모션

- 장면 진입: opacity + 8px 이내 이동, 320~440ms
- 떠다니는 카드: 2~~4px, 3~~5초
- 코드 타일: 40ms 간격의 짧은 순차 등장
- 연결선: opacity 변화만 사용
- 진행 링: transform/opacity 중심
- `prefers-reduced-motion: reduce`에서는 모든 반복 모션을 끄고 즉시 최종 상태를 보여준다.

## 6. 반응형 규칙

### 320~374px

- 좌우 여백 16px
- 제목은 `clamp`로 최소 27px 확보
- 장면 높이는 230~280px 범위
- 보조 장식 수를 줄이고 CTA는 safe-area 위에 고정된 흐름으로 유지

### 375~520px

- 좌우 여백 20~24px
- 장면 높이 280~340px
- 카드 세 개와 두 캐릭터 장면을 온전히 표시

### 521px 이상

- 전체 폭 최대 520px
- 배경만 화면 전체로 확장하고 콘텐츠는 모바일 앱 비율을 유지
- 지나치게 큰 이미지나 데스크톱 전용 2열 구조를 만들지 않는다.

### 낮은 화면

- 높이 700px 미만에서는 장면을 먼저 축소하고 제목·설명·CTA 크기는 유지한다.
- 본문 전체가 화면을 넘으면 root 자체를 세로 스크롤할 수 있게 한다.
- `overflow:hidden`으로 CTA나 설명이 잘리지 않게 한다.

## 7. 진행·이탈 정책

- `다음`: 다음 장면으로 이동
- `이전`: 첫 장을 제외하고 보조 버튼으로 제공하거나 progress segment로 이동
- `건너뛰기`: 온보딩 완료를 저장하고 `/home`으로 이동
- 마지막 CTA: 온보딩 완료를 저장하고 빠른 코어 검사로 이동
- 브라우저 뒤로가기와 새로고침 뒤에도 기존 local completion 계약을 유지한다.
- 이미 완료한 사용자를 강제로 다시 온보딩에 보내지 않는다.

## 8. 접근성

- carousel region에 전체 장면 수와 현재 위치를 제공한다.
- 현재 장면 변경은 짧은 aria-live 문구로만 알린다.
- 제목은 장면별 heading으로 실제 DOM에 둔다.
- progress 버튼의 터치 영역은 최소 44px이되 시각 요소는 작게 유지한다.
- 키보드 좌·우 방향키, Tab, Enter/Space를 지원한다.
- 색만으로 장면이나 진행 상태를 전달하지 않는다.
- 본문 대비는 WCAG AA를 목표로 한다.

## 9. 성능 기준

- 네 개의 대형 온보딩 합성 이미지를 네트워크에서 요청하지 않는다.
- 기존 캐릭터는 실제 보이는 장면만 우선 로드한다.
- 장면 HTML은 초기 렌더에서 존재해 레이아웃 이동을 줄인다.
- blur, filter, box-shadow의 넓은 영역 애니메이션을 피한다.
- 360px 보급형 모바일 기준 스와이프와 버튼 전환이 끊기지 않아야 한다.

## 10. 제거 대상

새 컴포넌트와 테스트에서 참조가 0건임을 확인한 뒤 `public/assets/onboarding`에 있던 과거 합성 자산 12개를 삭제한다. 삭제한 개별 파일명은 Git 이력에서 확인할 수 있다.

기존 `OnboardingGuideCarousel`의 이미지 데이터 구조와 `next/image` import도 제거한다. 과거 기획 문서는 V2로 대체됐음을 상단에 표시한다.

## 11. 구현 Gate

### Gate A — 구조

- 네 장 모두 제목·설명·버튼이 실제 HTML이다.
- 대형 합성 온보딩 이미지 요청이 0건이다.
- 네 장의 목적과 CTA가 본 문서와 일치한다.

### Gate B — 반응형

- 320×568, 360×800, 390×844, 430×932에서 텍스트·장면·CTA가 겹치지 않는다.
- 200% 글자 확대에서도 진행과 CTA를 사용할 수 있다.
- 낮은 화면은 세로 스크롤로 모든 내용을 볼 수 있다.

### Gate C — 상호작용

- 다음·이전·progress·스와이프·방향키가 같은 active index를 사용한다.
- 건너뛰기는 `/home`, 마지막 CTA는 빠른 검사로 이동한다.
- completion 저장 실패가 검사 시작을 막지 않는다.

### Gate D — 접근성·모션

- 모든 조작이 키보드로 가능하다.
- 장식 캐릭터가 중복 낭독되지 않는다.
- reduced-motion에서 반복 모션이 없다.
- 현재 장면이 스크린리더에 과도하게 반복 안내되지 않는다.

### Gate E — 회귀 검증

- onboarding component/storage/entry gate 테스트 통과
- typecheck·lint·production build 통과
- 모바일 실제 렌더 스크린샷 검토
- 제거 자산 참조가 `rg` 기준 0건

## 12. 완료 정의

사진처럼 고정된 네 화면이 아니라, 모든 글을 읽고 확대할 수 있으며 화면 크기에 맞춰 재배치되는 네 개의 코드형 장면이 제공되고, 뉴앙의 정체성과 빠른 검사 진입이 첫 이용자에게 명확하게 전달될 때 완료로 본다.
