## 1. 한 문장 정의

> 짧게 한 판부터 오래 이어서까지, 우리가 어디서 통하고 어떻게 맞물리는지 계속 새롭게 발견하는 취향 게임

밸런스 게임은 관계의 좋고 나쁨을 판정하는 검사가 아니다. 장소, 음식, 이상형, 취미처럼 일상에서 바로 대화할 수 있는 취향을 비교하고, 잘 맞는 선택과 재미있게 갈리는 선택을 발견하게 하는 함께하기 경험이다. 장소·음식·취미는 같은 선택을 기준으로 `취향 싱크`를 계산하지만, 이상형·관계 역할은 같은 답이 많다고 무조건 높은 궁합으로 계산하지 않는다.

사용자 화면에서는 어렵게 설명하지 않고 결과의 실제 의미에 따라 `취향 싱크`, `이상형 취향`, `서로의 이상형 적중도`, `역할 호흡`을 구분해 사용한다.

## 2. 제품 경계와 용어

| 영역                 | 사용자 노출명 | 내부 권장 식별자              | 목적                                                   |
| -------------------- | ------------- | ----------------------------- | ------------------------------------------------------ |
| 커뮤니티             | 투표          | 기존 `balance_game` 유지      | 게시물 하나에 의견을 모으고 전체 비율을 확인           |
| 검사 > 함께하기      | 밸런스 게임   | `together_balance_game`       | 여러 문항을 함께 완료하고 사람별·그룹 취향 궁합을 비교 |
| 검사 > 함께하기 후속 | 오픈 밸런스   | `together_balance_open_crowd` | 피드에서 100명 이상이 참여하고 전체 선택 분포를 비교   |

다음 원칙을 고정한다.

- 기존 DB의 `balance_game`, `feed_poll`, `vote_poll`은 레거시 커뮤니티 계약으로 유지한다.
- 새 밸런스 게임은 기존 커뮤니티 투표 테이블과 채점 데이터를 재사용하지 않는다.
- 새 게임의 문항팩, 방, 참여자, 응답, 결과 스냅샷은 별도 도메인으로 관리한다.
- 하단 메뉴를 새로 만들지 않고 검사 탭 내부 `함께하기`에서 시작한다.
- 기존 뉴앙 코드 비교와 밸런스 게임 궁합은 서로 다른 제품이다.
- 2~8명 소규모 방과 100명 이상 오픈 밸런스는 결과 의미·권한·집계 방식이 다른 제품 모드다.
- 소규모 방이 정원을 넘었다고 오픈 밸런스로 자동 전환하지 않는다. 공개 범위와 결과 의미가 바뀌므로 생성 시 모드를 고정한다.

## 3. 핵심 사용자와 사용 장면

### 핵심 사용자

- 친구 둘이 서로의 취향을 가볍게 확인하고 싶은 경우
- 커플 또는 썸 관계에서 대화거리를 만들고 싶은 경우
- 3~8명의 친구 모임, 동아리, 가족, 여행 멤버가 공통 취향을 찾고 싶은 경우
- 온라인 커뮤니티에서 링크를 공유해 여러 사람과 빠르게 놀고 싶은 경우
- 피드에서 2~8명의 새 참여자를 모집해 가볍게 함께 해보고 싶은 경우

### 대표 사용 장면

- 여행 전에 장소 팩을 함께 하고 행선지 후보를 좁힌다.
- 배달 메뉴를 정하기 전에 음식 팩으로 공통 취향을 확인한다.
- 친구끼리 이상형·관계 취향의 공통점과 차이를 발견한다.
- 모임에서 QR을 띄우고 취미 팩에 참여한 뒤 결과를 함께 본다.
- 결과를 본 직후 같은 멤버로 다른 주제에 재도전한다.

## 4. 핵심 재미 루프

```text
주제팩 발견
→ 방 만들기
→ 링크·QR·코드로 초대
→ 각자 다른 사람의 답을 모른 채 선택
→ 두 명 이상 완료
→ 현재 결과 공개
→ 목표 인원 완료 또는 방장 마감
→ 최종 결과 공개
→ 나와 한 사람씩 1:1 비교
→ 갈린 선택으로 대화
→ 같은 멤버로 다른 팩 재대결
```

재미가 생기려면 다음 감정이 순서대로 이어져야 한다.

1. `나도 바로 골라보고 싶다.`
2. `상대는 무엇을 골랐을까?`
3. `생각보다 비슷하다 / 여기서는 완전히 다르다.`
4. `다른 주제도 해보고 싶다.`

답변 중 다른 참여자의 선택이나 현재 분포를 보여주지 않는다. 미리 보면 따라 고르게 되어 결과의 재미와 신뢰가 동시에 낮아진다.

## 5. 출시 형태

### MVP 기본 모드

- 비동기 소규모 방
- 방장 포함 목표 정원을 2~8명 중 선택
- `친구에게 초대`하는 비공개 방과 `피드에서 모집`하는 공개 모집방
- 팩마다 독립적인 대형 문항 풀 운영
- 8문항을 한 라운드로 구성
- `가볍게 8`, `제대로 16`, `길게 24`, `새 문항으로 계속` 중 선택
- 팩 성격에 따라 기본 길이를 12·16·20문항으로 다르게 설정
- 예상 시간 40초~5분
- 방 생성 즉시 공유 가능
- 2명 이상 완료하면 `현재 결과` 공개
- 목표 정원 전원 완료 또는 방장 마감 시 `최종 결과` 확정
- 늦게 참여한 사람이 완료할 때마다 새 결과 스냅샷 생성
- 비회원은 방 닉네임만으로 참여 가능
- 피드 모집방은 신고·차단·중복 참여 관리를 위해 로그인 참여를 기본으로 한다.
- 결과 저장을 원할 때 계정 연결 제안

문항 풀의 크기와 한 번에 푸는 문항 수를 구분한다. 음식 팩은 96개 이상의 문항 풀을 가질 수 있지만 한 판에서는 8·16·24개만 뽑는다. 짧은 첫 완주와 장기적인 새로움을 동시에 확보하기 위한 구조다.

긴 게임은 하나의 24문항 화면 흐름으로만 만들지 않는다. 8문항 라운드를 마칠 때마다 라운드 결과를 열고, 같은 멤버가 다음 8문항을 이어서 할 수 있게 한다. 누적 결과는 완료된 라운드만 사용하며 `24개 중 18개 일치`처럼 실제 비교 수를 항상 함께 보여준다.

### 후속 오픈 밸런스 모드

- 100명·1,000명·무제한 참여를 위한 피드 공개형 게임
- 사람별 1:1 결과와 `그룹 궁합` 대신 문항별 분포, `전체 취향 일치도`, `나는 전체와 얼마나 비슷했을까?`를 제공
- 모든 2인 조합을 생성하지 않고 문항별 A/B 집계로 결과 계산
- 참여자 전체 목록, 사람별 답, 임의의 두 사람 결과는 공개하지 않음
- 공식 팩부터 시작하고 사용자 제작 팩은 검수·신고 체계 이후 도입

오픈 밸런스는 소규모 방의 단순 확장이 아니다. 방장은 같은 팩으로 별도 오픈 게임을 생성하며 기존 참여자의 공개 동의와 결과 의미를 도중에 바꾸지 않는다.

### 후속 실시간 파티 모드

- 방장이 한 문항씩 진행
- 각 문항에서 `4/5명 선택 완료`만 표시
- 모두 고르면 분포를 동시에 공개
- 공개 순간에 이모지 반응
- 마지막 문항 뒤 전체 궁합 공개

실시간 동기화 비용과 대기 이탈을 고려해 MVP에서는 제외한다.

첫 화면에서 모든 팩을 평면적으로 나열하지 않는다. `지금 많이 하는`, `우리 취향`, `관계 케미`, `웃긴 선택`, `새로 나온` 선반으로 탐색한다.

공개 출시 1차 대표 팩:

1. 취향 종합전
2. 우리 어디갈까?
3. 우리 뭐 먹을까?
4. 우리 뭐할까?
5. 우리 뭐 볼까?
6. 끌리는 사람
7. 평생 하나만?
8. 웃긴 극한 선택

전체 콘텐츠 포트폴리오, 팩별 문항 풀 목표, 실제 후보 문항은 `docs/NUANG_TOGETHER_BALANCE_GAME_CONTENT_CATALOG.md`를 기준으로 한다.

카드 구성:

- 팩 제목

### 7.2 방 만들기

팩을 고른 뒤 한 화면에서 목표 인원과 초대 방식을 정한다.

필수 항목:

- 방장 닉네임
- 몇 명이 함께하나요?: `2명`부터 `8명`까지 선택 칩
- 안내: `방장님을 포함한 인원이에요.`
- 어떻게 함께할까요?: `친구에게 초대` / `피드에서 모집`
- 얼마나 해볼까요?

  - `제대로`: 팩 기본 16~~20문항·약 2~~3분
  - `길게`: 24문항·약 4~5분
  - `새 문항으로 계속`: 8문항씩 결과를 보고 이어가기

- 방 이름: 기본값 `{닉네임}의 취향 대결`
- 참여 마감: 기본 7일
- 방장 승인 후 참여는 후속 버전

CTA:

> 우리끼리 방 만들기

방을 만든 직후 초대와 내 답변 시작을 나란히 제공한다. 방장이 먼저 완주해야 공유할 수 있도록 막지 않는다.

`친구에게 초대`는 검색과 피드에 노출되지 않는 난수 링크 방이며 비회원 닉네임 참여를 허용한다. `피드에서 모집`은 로그인한 방장만 만들 수 있고, 신고·차단과 한 계정 한 자리 원칙을 적용한다.

목표 인원은 권장값이 아니라 고정 정원이다.

- 모집 중에는 방장이 8명 이내에서 정원을 늘릴 수 있다.
- 이미 참여한 인원보다 작게 줄일 수 없다.
- 첫 결과가 열린 뒤에는 정원을 바꾸지 않는다.
- 동시 입장 시 서버가 원자적으로 자리를 확보하며 정원을 초과한 임시 참여자를 만들지 않는다.
- 진입 직후 15분간 자리를 예약하고 첫 답을 저장하지 않으면 자동 해제한다.
- 가득 찬 방에는 `이 방은 다 찼어요`와 `같은 팩으로 새 방 만들기`를 제공한다.

## 8. 궁합 점수

모든 문항에 같은 채점 규칙을 적용하지 않는다. 문항팩은 생성할 때 다음 템플릿 중 하나를 명시한다.

| 템플릿                              | 적합한 주제                                   | 같은 답의 의미                                    | 대표 결과                      |
| ----------------------------------- | --------------------------------------------- | ------------------------------------------------- | ------------------------------ |
| `taste_sync` 취향 유사형            | 장소·음식·취미·콘텐츠                         | 함께 선택할 때 의견이 모일 가능성                 | 취향 싱크                      |
| `relationship_standard` 관계 기준형 | 연락·시간·돈·약속                             | 사전에 조율할 거리가 적음                         | 관계 기준 싱크                 |
| `ideal_preference` 이상형 취향형    | 끌리는 행동·분위기                            | 좋아하는 사람의 모습이 비슷함                     | 이상형 취향 닮음도             |
| `reciprocal_fit` 상호 적합형        | 데이트 주도·위로·연락·갈등 대응               | 내가 바라는 방식과 상대가 실제 하는 방식이 맞물림 | 서로의 이상형 적중도·역할 호흡 |
| `dilemma_fun` 재미 딜레마형         | 평생 하나·극한 선택·초능력                    | 이 게임에서 같은 선택을 한 정도                   | 선택 케미                      |
| `discovery_only` 발견형             | 외모·패션·목소리 등 기능적 궁합과 무관한 선호 | 단순한 취향 발견                                  | 서로 새로 알게 된 취향         |

`dilemma_fun` 점수는 실제 생활 취향이나 관계 적합도를 뜻하지 않는다. `우리 선택 케미`와 `가장 황당하게 갈린 질문`만 보여준다. `다르면 보완된다`는 일반 규칙은 사용하지 않는다. 상보성은 역할이 맞물리는 일부 장면에서만, 한 사람이 바라는 행동을 다른 사람이 실제 제공할 때 계산한다. 성별에 따른 고정 보완 규칙은 적용하지 않는다.

### 8.1 2인 취향 궁합

`taste_sync`와 `relationship_standard`의 기본 산식이다.

```text
2인 취향 궁합 =
같은 option_id를 선택한 문항 수 ÷ 함께 완료한 채점 문항 수 × 100
```

16개 중 12개가 같으면 75점이다.

표시:

> 민지와 나의 취향 궁합 75점
> 16개 중 12개를 똑같이 골랐어요.

점수는 서버에서 반올림하고 `matchCount`, `comparedCount`, `scoringVersion`을 함께 저장한다. 인기 선택지, 뉴앙 코드, 성별, 연령, 전체 응답 분포를 몰래 가중하지 않는다.

`relationship_standard`의 같은 답은 관계가 더 좋다는 뜻이 아니라 같은 상황에서 기대하는 방식이 비슷하다는 뜻이다. 다른 답은 `미리 얘기하면 좋은 주제`로 보여준다.

### 8.2 2인 결과 구간

| 점수   | 결과명         | 설명                                               |
| ------ | -------------- | -------------------------------------------------- |
| 90~100 | 거의 한마음    | 대부분의 질문에서 같은 쪽을 골랐어요.              |
| 75~89  | 취향 메이트    | 함께 좋아하는 선택이 아주 많아요.                  |
| 60~74  | 은근히 잘 통함 | 다른 선택보다 같은 선택이 더 많아요.               |
| 40~59  | 반반 케미      | 통하는 부분과 갈리는 부분이 모두 또렷해요.         |
| 20~39  | 반전 취향      | 서로 다른 선택이 많아 새롭게 발견할 취향이 많아요. |
| 0~19   | 극과 극 케미   | 같은 질문에서도 정반대를 고르는 반전 조합이에요.   |

`천생연분`, `안 맞는 사이`, `갈등 위험`처럼 관계의 질을 단정하는 표현은 사용하지 않는다.

### 8.3 그룹 취향 궁합

`taste_sync` 완주자들의 모든 2인 조합 점수를 계산한 뒤 반올림 전 점수의 평균을 낸다.

```text
그룹 취향 궁합 =
모든 2인 조합의 반올림 전 점수 합 ÷ 2인 조합 수

2인 조합 수 = n × (n - 1) ÷ 2
```

4명이면 6개 조합, 5명이면 10개 조합을 평균한다.

이 방식은 `우리 방에서 가능한 모든 두 사람이 얼마나 자주 같은 선택을 했는가`로 설명한다. 참여 인원에 따라 이론적 최저점이 달라지므로 다른 방과 순위를 겨루는 점수로 사용하지 않는다.

### 8.4 이상형 취향 닮음도

`끌리는 사람`의 그룹 플레이는 `ideal_preference`로 제공한다. 두 사람이 같은 이상형을 골랐다는 사실만 보여주며 두 참가자가 서로 연인으로 잘 맞는다는 뜻으로 해석하지 않는다.

```text
이상형 취향 닮음도 =
같은 이상형 option_id를 선택한 문항 수 ÷ 비교 문항 수 × 100
```

결과 문구:

> 둘은 끌리는 포인트가 16개 중 11개 같아요.
> 먼저 장난을 거는 사람과 데이트를 계획해 주는 사람에게 함께 마음이 가네요.

그룹에서는 `우리 모임이 공통으로 끌리는 포인트`와 `취향이 가장 팽팽하게 갈린 포인트`를 보여주되 `그룹 연애 궁합`은 만들지 않는다.

### 8.5 서로의 이상형 적중도와 역할 호흡

`reciprocal_fit`은 `끌리는 사람`과 별개의 2인 전용 팩 `우리 둘의 연애 케미`에 사용한다. 각 의미 축은 다음 두 문항을 한 쌍으로 가진다.

1. `상대에게 바라는 방식`
2. `내가 실제로 하는 방식`

예:

| 의미 축     | 상대에게 바라는 문항                            | 자기 행동 문항                             |
| ----------- | ----------------------------------------------- | ------------------------------------------ |
| 데이트 주도 | 날짜와 장소를 먼저 제안 / 내 제안에 빠르게 호응 | 내가 먼저 제안 / 상대 제안에 빠르게 호응   |
| 위로        | 해결 방법을 같이 찾기 / 내 편에서 충분히 듣기   | 해결 방법을 같이 찾기 / 감정을 충분히 듣기 |
| 연락        | 짧게라도 자주 안부 / 하루 끝에 긴 대화          | 짧게 자주 안부 / 하루 끝에 길게 대화       |
| 갈등        | 먼저 대화를 열기 / 생각할 시간을 준 뒤 확인     | 먼저 대화를 열기 / 시간을 준 뒤 다시 확인  |
| 선물        | 지금 필요한 실용템 / 오래 간직할 추억템         | 필요한 물건 챙기기 / 둘만의 의미 담기      |
| 애정 표현   | 좋아한다고 자주 말하기 / 행동으로 챙겨주기      | 말로 자주 표현 / 행동으로 챙기기           |

게임 중 같은 축의 두 문항을 연달아 보여주지 않는다. 참가자가 채점 방향을 눈치채고 답을 맞추는 것을 줄이기 위해 순서를 섞되 동일한 `meaning_code`로 연결한다.

```text
A 방향 적중 = A가 바라는 방식과 B가 실제 하는 방식의 일치
B 방향 적중 = B가 바라는 방식과 A가 실제 하는 방식의 일치

상호 적합도 =
(A 방향 일치 수 + B 방향 일치 수)
÷ (비교 축 수 × 2) × 100
```

단일 숫자만으로 관계를 요약하지 않고 다음 세 축을 함께 보여준다.

- `서로의 이상형 적중도`: 바라는 방식과 상대 행동이 교차해 맞는 정도
- `관계 기준 싱크`: 연락·시간·약속처럼 합의가 필요한 기준의 공통점
- `역할 호흡`: 계획·대화 주도처럼 역할이 자연스럽게 맞물리는 장면

두 방향은 반드시 따로 확인할 수 있어야 한다.

> 민지가 준호에게 끌릴 포인트 5/6
> 준호가 민지에게 끌릴 포인트 4/6

대표값이 필요하면 세 축의 단순 평균을 `이번 게임 케미`로 표시한다. 임의의 심리학적 가중치를 두거나 관계 성공 가능성으로 설명하지 않는다.

### 8.6 그룹 결과 구간

| 점수   | 결과명                    |
| ------ | ------------------------- |
| 80~100 | 거의 한마음인 팀          |
| 65~79  | 자주 통하는 팀            |
| 50~64  | 공통점도 개성도 있는 팀   |
| 0~49   | 선택이 뚜렷하게 갈리는 팀 |

낮은 점수를 억지로 좋게 포장하지 않는다. 대신 사람 자체를 평가하지 않고 실제로 어떤 선택이 달랐는지 보여준다.

### 9.4 한 명씩 비교해 보기

참여자를 가입 순서 또는 가나다순으로 표시한다. 궁합 순위를 기본 제공하지 않는다.

- 민지와 나
- 준호와 나
- 수빈과 나

참여자를 선택하면 현재 사용자와 해당 참여자만의 1:1 결과를 보여준다. A가 동의 없이 B와 C만의 결과를 보는 기능은 제공하지 않는다.

### 9.5 우리에게 맞는 다음 행동

응답으로 직접 뒷받침될 때만 제안한다.

- 5명 모두 바다 선택 → `다음 여행 후보로 바다를 저장해 보세요.`
- 4명이 매운맛 선택 → `매운 음식 모임이 잘 맞아요.`
- 실내와 야외가 반반 → `날씨에 따라 정하면 가장 빨라요.`

## 10. 1:1 결과 화면

`taste_sync` 기본 상단:

상단:

> 민지와 나의 취향 궁합 83점
> 24개 중 20개가 같아요.

섹션:

1. 주제별 일치도
2. 둘이 잘 맞는 선택 최대 3개
3. 확실히 다른 선택 최대 3개
4. 전체 답변 비교
5. 다음 대화거리

필터:

- 전체
- 같은 선택
- 다른 선택

좋은 설명:

- `여행지는 둘 다 바다`
- `야식은 둘 다 치킨`
- `나는 산, 민지는 바다`

피해야 할 설명:

- `두 사람은 자극 추구 성향이 일치해요`
- `둘은 여행 궁합이 나빠요`

후속 CTA:

- `둘이 다른 주제로 다시 하기`
- `갈린 선택만 다시 붙기`
- `이 결과 공유하기`

`ideal_preference`는 상단을 `둘의 이상형 취향 닮음도`로 바꾸고 `둘이 서로 잘 맞는다`는 문구를 사용하지 않는다. `reciprocal_fit`은 다음 순서로 별도 구성한다.

1. `서로의 이상형 적중도`
2. `민지가 나에게서 좋아할 포인트`
3. `내가 민지에게서 좋아할 포인트`
4. `관계 기준 싱크`
5. `역할이 자연스럽게 맞물리는 장면`
6. `서로 한 번 맞춰보면 좋은 장면`

같은 답과 다른 답을 한 축으로 섞어 높고 낮은 궁합으로 표현하지 않는다. 어떤 차이는 조율 대상이고, 어떤 차이는 역할 호흡이며, 어떤 취향은 단순한 발견이라는 의미를 결과 카드마다 명시한다.

공개 시작 기준은 `검수를 통과한 서로 다른 문항 수`다. 목표 수를 채우기 위해 약한 문항을 공개하지 않는다. 문항 풀 목표는 운영 데이터와 사용자 제안을 검수해 점진적으로 확장한다.

모든 선택지는 같은 수준의 개념이어야 하고, 한쪽만 명백히 좋아 보이거나 성숙해 보이면 안 된다. 추상적인 성향 단어보다 한국 사용자가 장면을 즉시 떠올릴 수 있는 음식·장소·행동을 쓴다. 아래 표는 대표 샘플이며 전체 후보군은 `docs/NUANG_TOGETHER_BALANCE_GAME_CONTENT_CATALOG.md`에서 관리한다. 국내 밸런스 게임에서 반복되는 인기 소재와 대비 방식을 참고하되 문장을 그대로 복제하지 않고 뉴앙용으로 다시 쓴다. 출시 전 모바일 가독성·선택 분포·표현 중복을 검수한다.

## 12. 문항 설계 기준

- 한 문항에는 한 가지 취향만 담는다.
- 선택지는 같은 수준의 개념과 비슷한 길이로 작성한다.
- 상황 문장은 한 문장으로 짧게 쓴다.
- 선택지는 모바일에서 한눈에 읽히도록 가급적 10자 안팎으로 쓴다.
- `감성 vs 실용`, `자유 vs 안정` 같은 추상 명사만 두지 않고 실제 장면·대상·행동으로 바꾼다.
- 이름만 읽어도 맛과 경험이 떠오르는 한국 생활 소재를 우선한다.
- 두 선택지는 서로 겹치지 않아야 한다. `바로 쓸 물건 vs 의미 있는 물건`처럼 한쪽이 다른 쪽의 장점도 가질 수 있는 대립은 쓰지 않는다.
- 가격·품질 차이 때문에 한쪽이 명백히 유리한 조합을 피한다.
- 한 선택지에 성격·외모·생활습관을 여러 개 묶지 않는다.
- 두 선택지 모두 충분한 장점과 포기 비용이 있어 고른 이유를 말하고 싶게 만든다.
- `지금 더 끌리는 쪽`을 고른다는 규칙을 첫 화면에 안내한다.
- 기본 모드에는 `둘 다`, `둘 다 아님`, `모르겠음`을 두지 않는다.
- 도덕성, 능력, 소득, 외모 우열을 평가하는 대립을 만들지 않는다.
- 전 연령 팩에서는 성적 내용, 외모 비하, 성별 고정관념을 제외한다.
- 같은 팩에서 문장 구조와 하위 관점이 반복되지 않게 한다.
- 선택지 좌우 위치는 참여자별로 무작위화하되 저장 값은 동일한 `option_id`를 사용한다.
- 재미용 만장일치 문항은 `보너스`로 표시하고 점수에서 제외할 수 있다.
- `reciprocal_fit`의 이상형 문항과 자기 행동 문항은 동일한 `meaning_code`와 강도로 대응한다.
- 따뜻함·존중·신뢰·동의·경계 존중처럼 다를수록 좋아지는 특성이 아닌 영역에는 상보성 점수를 주지 않는다.
- 불안·회피, 통제·감시, 폭력·집착, 성별 고정 역할을 반대라서 잘 맞는 조합으로 해석하지 않는다.

문항 운영 기준:

- 권장 선택 분포: 30:70~70:30
- 허용 선택 분포: 20:80~80:20
- 여러 방에서 85:15 이상이 지속되면 수정·교체 검토
- 특정 문항의 응답 시간·이탈·수정률이 급증하면 모호성 검토
- 팩 수정 시 기존 방은 이전 버전에 고정

문항 순서는 `익숙하고 가벼운 선택 → 실제 생활 취향 → 고른 이유가 궁금해지는 선택`으로 구성한다. 밸런스 게임의 핵심 재미는 선택 자체보다 서로의 이유를 듣는 데 있으므로 결과 화면마다 `왜 이쪽을 골랐어?` 대화 카드를 연결한다.

실제 사용자 문항은 자료의 문장을 대량 복사하지 않고 반복되는 소재·대비 구조·한국 생활 맥락만 추출해 새로 작성한다.

- [푸망 사용자 제작 음악 취향 테스트](https://poomang.com/6szudq): 추상적인 성향 단어보다 공연 장면과 실제 행동으로 선택지를 만드는 패턴 확인
- [네이트판 사용자 밸런스게임 스레드](https://pann.nate.com/talk/370703854): 두 선택지 모두 장점과 손해가 뚜렷해 이유를 말하고 싶게 만드는 사용자 반응형 문항 확인
- [커플 질문 앱](https://play.google.com/store/apps/details?id=org.techtown.loverquestion&hl=ko): 과거·현재·미래·우선순위를 주제로 대화를 이어가는 커플용 질문 제품 구조 확인
- [밸런스 게임 질문 모음](https://flat.social/ko/blog/would-you-rather-questions): 음식·여행·커플·그룹 카테고리와 선택 뒤 이유를 나누는 파티형 사용 맥락 확인

관계과학 근거:

- [Dyrenforth et al. (2010)](https://pubmed.ncbi.nlm.nih.gov/20718544/): 세 국가 대규모 부부 표본에서 성격 유사성은 개인·상대 효과를 통제한 뒤 관계·삶 만족도 변량의 0.5% 미만을 설명
- [Weidmann et al. (2023)](https://pmc.ncbi.nlm.nih.gov/articles/PMC10312100/): 성격 특질·하위 특질 유사성이 관계 만족도와 강건하게 연결되지 않음을 확인
- [Sadler & Woody (2003)](https://pubmed.ncbi.nlm.nih.gov/12518972/): 대인관계 상호작용에서 친화성의 유사 반응과 주도성의 제한적 상보성 검토
- [Joel et al. (2020)](https://doi.org/10.1073/pnas.1917036117): 43개 종단 커플 데이터에서 인지된 헌신·감사·갈등 같은 실제 관계 과정이 관계의 질을 설명하는 주요 변수임을 확인
- [Eastwick et al. (2025)](https://pmc.ncbi.nlm.nih.gov/articles/PMC12622239/): 이상형과 상대 특성의 적합은 일부 예측력이 있지만 효과가 제한적이므로 여러 장면의 교차 적합으로 설명하고 관계 성공을 단정하지 않음

이 근거에 따라 뉴앙은 `비슷하면 무조건 좋은 관계`, `반대면 무조건 천생연분`, `남녀는 반대여야 잘 맞는다`는 규칙을 사용하지 않는다. 취향의 유사성, 관계 기준의 공통점, 원하는 방식과 실제 행동의 상호 적합을 분리한다.

### 12.2 팩·라운드·한 판의 구분

```text
팩
└─ 여러 하위 주제와 큰 문항 풀
   └─ 한 판
      ├─ 라운드 1: 8문항
      ├─ 라운드 2: 8문항
      └─ 라운드 3: 8문항
```

- `팩`: 장기간 확장되는 콘텐츠 라이브러리
- `한 판`: 방장이 선택한 길이와 멤버로 진행하는 게임
- `라운드`: 8문항 단위의 완료·결과·계속하기 지점
- `누적 결과`: 해당 방에서 함께 완료한 모든 라운드 기준
- `이번 라운드 결과`: 방금 완료한 8문항 기준

`reciprocal_fit` 라운드는 4개의 의미 축마다 선호 문항과 자기 행동 문항을 한 쌍으로 포함해 총 8문항으로 구성한다. 의미 쌍이 라운드를 가로질러 끊기지 않게 한다.

### 12.3 문항 조합 엔진

방 생성 시 서버가 `session_recipe_version`과 `room_question_seed`를 고정한다. 같은 방의 모든 참여자는 같은 문항과 같은 문항 순서를 받는다.

선정 우선순위:

1. 해당 그룹이 아직 함께 보지 않은 문항
2. 각 참여자가 최근 90일 안에 보지 않은 문항
3. 팩의 하위 주제·강도·문항 구조가 골고루 포함되는 조합
4. 운영상 분포가 지나치게 치우치지 않고 모호성 신호가 낮은 문항
5. 최근 추가된 문항과 안정적으로 검증된 문항의 혼합

중복 제한:

- 같은 한 판 안에서는 중복 0개
- 같은 멤버의 새 한 판은 최근 90일 문항과 중복을 원칙적으로 20% 이하로 유지
- 새 문항이 부족하면 시작 전에 `새 질문 10개 + 다시 만나는 질문 6개`처럼 정확히 알림
- 참여자별 좌우 위치는 바꿀 수 있지만 문항 의미와 `option_id`는 동일

하위 주제 층화 예:

- `우리 뭐 먹을까?`: 한식·분식·중식·고기·야식·디저트·카페·먹는 방식
- `우리 어디갈까?`: 자연·도시·숙소·이동·일정·계절·사진·비용
- `끌리는 사람`: 표현·연락·대화·위로·갈등·데이트·기념일·생활
- `웃긴 극한 선택`: 신체 불편·일상 망신·디지털·음식·시간·상상 상황

사용자가 `이 질문은 건너뛰기`를 누르면 개인만 다른 문항을 받지 않는다. 비교 가능성을 유지하기 위해 아직 아무도 답하지 않은 방은 공통 대체 문항으로 교환하고, 이미 응답자가 있으면 답변 없이 넘긴 뒤 해당 문항을 그 참여자의 비교 분모에서 제외한다.

### 12.4 강도와 이용 맥락

각 팩과 문항에 다음을 표시한다.

- `intensity`: `light | lively | deep`
- `audience`: `all | friends | couple | family | team`
- `sensitivity`: `general | personal | private`
- `occasion`: `first_meet | date | trip | party | daily | remote`

방장은 `가볍게 웃기기`, `서로 더 알아가기`, `진지하게 맞춰보기` 중 분위기를 고를 수 있다. 강도는 문항의 자극성을 높이는 기능이 아니라 얼마나 개인적인 대화를 요구하는지를 조절한다. 전 연령 기본값은 `light`다.

## 13. 결과 하이라이트 선정

메인 점수는 모든 채점 문항에 같은 가중치를 사용한다. 결과 화면의 순서에만 문항 메타데이터를 활용한다.

문항 메타데이터:

- `topic`
- `highlight_priority`
- `conversation_value`
- `sensitivity_level`
- `scored`
- `template_version`

선정 규칙:

- 일치 최대 3개, 차이 최대 3개
- 한 주제만 반복하지 않도록 다양성 확보
- 실제 약속이나 대화에 유용한 문항 우선
- 전부 일치하면 차이 대신 `둘이 다음에 해볼 선택`
- 일치가 하나도 없으면 억지 공통점을 만들지 않고 `서로 바꿔 경험해볼 선택`
- 민감한 선택은 공유 카드 기본값에서 제외

## 14. 참여·결과 엣지 케이스

방 상태는 하나의 `status`로 뭉치지 않는다.

- `join_status`: `open | full | closed | expired`
- `result_status`: `waiting | provisional | final`
- `lifecycle_status`: `active | closed | deleted`

참여자는 `reserved → joined → in_progress → completed`로 진행하며 `left | removed | reservation_expired`를 예외 상태로 둔다.

### 미완주

- 미완주자는 그룹 공식 점수에서 제외한다.
- 미응답을 불일치로 계산하지 않는다.
- 한 명만 완주하면 점수를 만들지 않는다.
- 결과에는 `완주자 4명 기준`을 명시한다.

### 중도 합류

- 같은 고정 팩 버전을 처음부터 답한다.
- 완주 전에는 기존 현재 결과를 바꾸지 않는다.
- 완주 순간 새 현재 결과 스냅샷을 만든다.
- `지훈님의 결과가 반영되어 그룹 결과가 업데이트됐어요`라고 알린다.

### 정원과 결과 확정

- 목표 정원은 방장 포함 2~8명이며 서버의 원자적 조건부 갱신으로 초과 참여를 막는다.
- 2명 이상 완료하면 `현재 결과`를 연다.
- 목표 정원의 전원이 완료하면 `최종 결과`로 자동 확정한다.
- 정원이 차지 않아도 2명 이상 완료했다면 방장이 `이 인원으로 마감`할 수 있다.
- 진행 중인 사람이 있으면 결과에서 빠진다는 확인을 받은 뒤 마감한다.
- 마감일에 2명 이상 완료했으면 자동 확정하고, 1명만 완료했으면 점수 없이 종료한다.
- 결과에는 `4명 정원 · 완주자 3명 기준`처럼 목표와 실제 기준을 함께 표시한다.
- 첫 답을 저장하지 않은 예약은 15분 뒤 해제하고 자리를 다시 연다.

### 중도 이탈

- 첫 답 전 이탈은 자리 예약을 즉시 반환한다.
- 미완주 이탈은 응답을 공식 결과에서 제외하고 자리를 다시 연다.
- 완주자 삭제 요청은 다음 스냅샷에서 제외하고 관련 1:1 결과와 공유 링크를 무효화한다.
- 방장 이탈 전에는 `방장 넘기기` 또는 `방 닫기`를 선택한다.
- 피드 모집방의 방장 이전은 로그인 참여자에게만 가능하다.

### 동률

- 가장 잘 통한 주제가 동률이면 모두 표시한다.
- 참여자를 점수 순으로 줄 세우지 않는다.
- `가장 안 맞는 사람`과 `최악의 궁합`을 제공하지 않는다.

### 수정과 중복 제출

- 결과 공개 전에는 이전 선택을 수정할 수 있다.
- 완료 뒤에는 응답을 바꾸지 않고 새 라운드를 만든다.
- 응답 API에 idempotency key와 client sequence를 적용한다.
- `(room_id, participant_id, item_id)`를 유일 키로 둔다.

## 15. 관계 안전과 공개 범위

- 참여 전에 `완료 후 방 참여자에게 서로의 선택이 공개된다`고 알린다.
- 완료 전에는 다른 참여자의 선택을 숨긴다.
- 그룹 화면에서 현재 사용자는 자신과 각 참여자의 1:1 결과만 볼 수 있다.
- 다른 두 사람만의 결과는 기본 공개하지 않는다.
- 공유 카드에는 개별 답변과 실명을 기본 포함하지 않는다.
- 개별 답변이 포함된 카드는 사용자가 항목을 직접 선택한 경우에만 만든다.
- 방장은 참여 종료, 링크 비활성화, 방 삭제를 할 수 있다.
- 참여자는 방마다 다른 닉네임을 사용할 수 있다.
- 초대 링크는 추측하기 어려운 난수 토큰으로 만든다.
- 익명 방의 원본 응답은 기본 30일 뒤 삭제한다.
- 방 또는 참여자 삭제 시 관련 1:1 결과와 공유 링크를 무효화한다.
- 피드 모집방의 상세 결과는 실제 참여자에게만 공개한다.
- 피드에는 방장이 허용한 무기명 그룹 요약만 공유하고 이름별 답과 1:1 결과는 노출하지 않는다.
- 공개 모집방은 신고·차단·참여자 제거·재입장 금지 목록을 제공한다.
- 차단 관계인 사용자의 공개 방 카드를 숨기고 상호 참여를 막는다.
- 방장 혼자 있을 때만 비공개 초대방과 피드 모집방 사이를 전환할 수 있다. 두 번째 참여자 진입 뒤에는 같은 팩으로 새 방을 만들도록 한다.

### 17.1 오픈 밸런스의 결과 산식

오픈 밸런스는 임의의 두 참여자가 같은 답을 골랐을 확률을 문항별 집계만으로 계산한다. 문항 `j`의 A 선택자가 `a`, B 선택자가 `b`, 완주자가 `n`명일 때:

```text
문항별 동일 선택 쌍 = C(a, 2) + C(b, 2)
문항별 가능한 전체 쌍 = C(n, 2)

전체 취향 일치도 =
각 문항의 동일 선택 쌍 비율 평균 × 100
```

> 전체 취향 일치도 68%
> 참여자 두 명을 무작위로 골랐을 때 같은 답을 고를 확률이에요.

개인 결과는 각 문항에서 `나를 제외하고 나와 같은 답을 고른 사람의 비율`을 평균한다.

> 나는 전체와 74% 통했어요.
> 20개 중 14개는 다수 선택과 같았어요.

추가 결과:

- 가장 압도적으로 모인 문항
- 가장 팽팽하게 갈린 문항
- 내가 대세와 달랐던 선택
- `1,284명 완료 · 7월 31일 15:20 기준`과 같은 집계 시점

100명 단계에서는 2~~5초, 1,000명 이상에서는 10~~30초 단위로 집계를 갱신한다. 완료자 100명 증가, 30초 경과, 게임 종료 중 먼저 도달한 조건으로 새 스냅샷을 만들고 종료 시 불변 최종 스냅샷을 생성한다. 무제한 상시 게임은 최종값 대신 모든 결과에 시각과 참여자 수를 표시한다.

오픈 모드에는 참여자 전체 목록, 사람별 답, 임의의 두 사람 궁합, 방장용 원본 답 다운로드를 제공하지 않는다. 방장도 개인 응답은 볼 수 없고 집계만 확인한다.

## 18. 행동 데이터 기반 자동 개선

플레이 과정 자체를 품질 검수 수단으로 사용한다. 별도의 긴 설문을 강요하지 않는다.

수집 이벤트:

- 팩 노출·선택
- 게임 길이·강도 선택
- 방 생성
- 초대 링크 복사·공유
- 초대 링크 진입
- 참여 시작
- 문항별 응답 시간
- 선택 변경
- 문항별 이탈
- 팩 완주
- 라운드 완주
- `새 문항 8개 더` 선택
- 문항 노출·재노출
- 질문 건너뛰기·즐겨찾기
- 두 번째 완주자 발생
- 그룹 결과 조회
- 1:1 결과 조회
- 결과 공유
- 같은 멤버 재게임
- 저장 그룹 재방문
- 오늘 한 문제·주간 요약 조회
- `이 질문이 애매했어요`

자동 검토 규칙 예:

- 선택 분포 85:15 이상 지속 → 균형 검토 대기열
- 특정 문항 응답 시간 급증 → 표현 모호성 검토
- 특정 문항 직후 이탈 증가 → 길이·민감도 검토
- 선택 변경률 급증 → 선택지 구분과 터치 UX 검토
- 팩 완주율 하락 → 후반 문항 순서와 중복 검토
- 새 문항 비율 하락 → 해당 팩 콘텐츠 제작 우선순위 상승
- 같은 그룹 재게임률 상승 + 특정 하위 주제 소진 → 하위 덱 확장
- 첫 라운드 완주율은 높지만 계속률이 낮음 → 결과 CTA·다음 문항 예고 검토
- 새 버전은 이전 버전과 완주율·분포·재게임률 비교

문항 수정은 자동 배포하지 않는다. 시스템이 후보를 만들고 운영자가 승인한 새 팩 버전만 공개한다.

### 18.1 콘텐츠 공급 운영

문항 상태:

```text
draft
→ editorial_review
→ safety_review
→ ready
→ published
→ watch
→ revised | retired
```

- 매주 최소 2개 대표 팩에 새 문항을 공급한다.
- 팩 카드에 `이번 주 새 질문 8개`처럼 실제 추가 수를 표시한다.
- 자동 시스템은 선택 쏠림·응답 지연·건너뛰기·애매함 신고를 종합해 `watch` 후보를 만든다.
- 운영자는 대체 문항과 기존 문항의 분포·완주·재게임 영향을 비교한 뒤 새 버전을 승인한다.
- 유행성이 높은 음식·콘텐츠·장소 문항은 `trend_sensitive`와 재검토 날짜를 가진다.
- 사용자 제안은 `접수 → 검토 중 → 승인 → 반려` 상태를 제공하고 승인 전 공개 문항 풀에 들어가지 않는다.
- 원문과 지나치게 유사한 제안, 특정 커뮤니티 내부자만 이해하는 표현, 브랜드를 비하하거나 광고처럼 보이는 문항은 제외한다.

팩 건강 대시보드:

- 공개 가능한 새 문항 수
- 사용자·그룹별 미노출 문항 비율
- 최근 90일 평균 중복률
- 하위 주제별 문항 수와 노출 편중
- 선택 분포·응답 시간·건너뛰기·신고
- 첫 라운드 완주율·계속률·같은 그룹 재게임률
- 신규 문항이 기존 문항보다 만든 추가 체류와 결과 공유

## 19. 결과 공유와 재참여

기본 공유 카드:

- 팩 이름
- 그룹 또는 2인 취향 궁합
- 결과명
- 참여 인원
- `너도 같이 해볼래?`

개별 응답은 기본 카드에 넣지 않는다.

피드에는 두 종류의 카드가 있다.

1. `함께할 사람 모집`: 아직 자리가 남은 2~8명 방으로 들어가는 참여 카드
2. `결과 공유`: 방장이 허용한 그룹 점수와 무기명 하이라이트를 보여주는 결과 카드

피드 모집은 기존 `투표`와 다르다. 다른 사람의 분포를 먼저 보고 한 항목에 답하는 투표가 아니라, 같은 팩을 끝까지 완료한 참여자들끼리 결과를 보는 방이다. 모집 카드 삭제는 방을 자동 삭제하지 않지만 피드 진입을 닫고, 방 삭제·마감은 피드 카드 상태에 즉시 반영한다.

재참여 장치:

- `다른 주제로 다시 하기`
- 같은 멤버 유지
- `갈린 선택만 다시 붙기`
- 계절 팩: 여름휴가, 연말모임, 새 학기
- 상황 팩: 첫 만남, 여행 전, 커플, 친구 모임
- `우리끼리 가장 갈린 질문 TOP 3`
- 새 참여자 완료 알림

사용자 제작 팩은 안전성·저작권·품질 문제 때문에 MVP에서 제외한다.

### 19.1 반복 플레이와 체류 루프

한 번의 긴 검사보다 다시 열 이유를 여러 층으로 만든다.

#### 즉시 계속

- 라운드 결과에서 `새 질문 8개 더`
- `우리끼리 가장 갈린 3개 결승전`
- `상대가 뭘 골랐을지 맞혀보기`
- 다 같이 고른 장소·음식·활동을 `우리 후보`에 저장

#### 같은 멤버 재방문

- 자주 함께하는 그룹 저장
- `지난번보다 새로 통하는 선택 4개`
- 같은 팩 재대결 시 미출제 문항 우선
- 한 달 뒤 같은 문항을 다시 골랐을 때 `그때와 지금` 비교
- 주간 요약: 가장 한마음이었던 선택, 가장 갈린 선택, 새로 들어온 멤버

#### 짧은 일상 루프

- `오늘 우리 한 문제`: 저장된 그룹에 하루 한 문항 공개
- 본인이 먼저 답해야 다른 사람의 답을 볼 수 있음
- 하루 결과 뒤 `한 판 더`로 자연스럽게 연결
- 알림은 그룹당 하루 최대 1회, 주간 요약 1회
- 연속 참여 일수는 개인 경쟁보다 `우리 그룹이 함께 답한 날`로 표시

#### 콘텐츠 발견

- 홈 선반에 `새 문항이 많이 남은 팩`, `요즘 많이 갈리는 팩`, `이 멤버와 아직 안 한 팩`
- 계절·행사 팩: 여름휴가, 장마, 연말모임, 새 학기, 시험 끝, 명절
- 실제 일정과 연결되는 팩: 여행 전, 메뉴 결정, 팀 프로젝트 시작, 같이 살기 전
- 즐겨찾기한 질문과 다시 이야기하고 싶은 질문 모음

### 19.2 선택 뒤의 대화 장치

밸런스 게임의 체류는 답을 누르는 시간보다 선택 이유를 나누는 시간에서 만들어진다.

- 결과 문항마다 선택형 이유 칩: `맛`, `편함`, `가격`, `추억`, `새로움` 등
- 원하는 사람만 80자 이내 한 줄 이유 작성
- `왜 이쪽을 골랐어?` 대화 카드
- 상대의 이유를 본 뒤 `의외예요`, `나도 그래요`, `다음에 해봐요` 반응
- 이유 작성은 채점에 포함하지 않고 공개 범위는 해당 방으로 제한
- 피드 공유 시 이유와 작성자를 자동 포함하지 않음

### 19.3 후속 게임 모드

| 모드          | 방식                                     | 결과                    |
| ------------- | ---------------------------------------- | ----------------------- |
| 기본 선택     | 내가 더 끌리는 쪽 선택                   | 취향 싱크·선택 케미     |
| 상대 맞히기   | 내 답 전에 특정 상대의 답 예측           | 서로를 얼마나 잘 아는지 |
| 다수파 맞히기 | 내 선택 뒤 그룹의 다수 선택 예측         | 그룹 감각 점수          |
| 오늘 한 문제  | 저장 그룹이 하루 한 문항 답변            | 일일 결과·주간 요약     |
| 실시간 공개   | 제한 시간 뒤 모두의 선택 동시 공개       | 현장 반응·갈림          |
| 결승전        | 가장 갈린 문항을 다시 선택하고 이유 공유 | 최종 선택·대화          |

`상대를 얼마나 잘 아는지`와 `둘이 얼마나 잘 맞는지`는 다른 결과이므로 점수를 합치지 않는다.

### 19.4 수익화 원칙

초대받은 사람이 결과를 보기 위해 결제하게 만들지 않는다. 바이럴 흐름을 막지 않으면서 큰 콘텐츠 라이브러리와 반복 플레이 가치를 유료화한다.

- 무료: 대표 팩, 오늘 한 문제, 주간 순환 팩, 8·16문항 게임
- 뉴앙 플러스: 전체 팩 라이브러리, 24문항·계속하기, 상세 그룹 히스토리, `그때와 지금`, 고급 결과 테마
- 방장 패스: 유료 방장이 연 프리미엄 팩은 초대 참여자 모두 무료로 플레이
- 시즌 패스: 여름휴가·연말·새 학기 등 기간형 팩 묶음
- 공식 협업 팩: 영화·여행·식음료 브랜드의 명시된 스폰서 팩
- 후속 사용자 제작 비공개 팩: 검수·신고·저작권 관리가 준비된 뒤 제공

궁합 점수의 상세 근거나 이미 함께 완료한 결과를 결제벽 뒤에 숨기지 않는다. 결제 가치는 더 많은 주제, 더 긴 히스토리, 더 풍부한 재게임에 둔다.

## 22. 성공 지표

초기 목표 가설:

- 팩 상세 → 방 생성 전환율: 35% 이상
- 초대 링크 진입 → 응답 시작률: 75% 이상
- 응답 시작 → 첫 8문항 라운드 완주율: 90% 이상
- 16~20문항 기본전 완주율: 82% 이상
- 첫 라운드 결과 → 새 문항 8개 계속률: 30% 이상
- 생성된 방 중 2명 이상 완주 비율: 55% 이상
- 그룹 결과에서 1:1 비교 진입률: 50% 이상
- 결과 공유율: 15% 이상
- 결과에서 다른 팩 시작률: 20% 이상
- 첫 플레이 후 14일 이내 재참여율: 25% 이상
- 저장 그룹의 주간 재참여율: 35% 이상
- 같은 그룹의 30일 내 서로 다른 팩 이용 수: 중앙값 3개 이상
- 재게임 문항 중 최근 90일 중복률: 20% 이하
- 팩별 문항 소진 전 이탈률과 `새 문항 없음` 노출률
- 문항별 애매함·신고 비율: 2% 미만

가장 중요한 지표는 `방 생성 후 실제로 두 명 이상이 결과를 본 비율`이다. 장기 지표는 `같은 그룹이 30일 안에 다시 와서 새로운 팩 또는 새 문항 라운드를 완료한 비율`이다.

## 23. 필수 테스트

### 산식

- 8개 전부 일치 → 100점
- 16개 중 12개 일치 → 75점
- 20개 중 10개 일치 → 50점
- 24개 중 18개 일치 → 75점
- 전부 불일치 → 0점
- A-B 점수와 B-A 점수가 동일
- 참여자 배열 순서를 바꿔도 그룹 점수가 동일
- 2명 그룹 점수가 해당 1:1 점수와 동일
- 전원 같은 답이면 그룹 100점
- 그룹 점수가 반올림 전 모든 1:1 점수 평균과 동일
- 미응답이 불일치로 계산되지 않음
- 다른 팩 버전이 섞이지 않음
- 좌우 표시 순서가 바뀌어도 `option_id` 기준 점수는 동일
- 중복 제출이 점수에 영향을 주지 않음
- `reciprocal_fit`에서 A의 선호와 B의 행동, B의 선호와 A의 행동이 각 방향으로 정확히 계산됨
- 같은 이상형을 고른 값이 상호 적합도로 잘못 사용되지 않음
- 성별은 상호 적합도 산식에 입력되지 않음
- 오픈 밸런스 집계 산식이 작은 표본의 모든 2인 조합 직접 계산과 일치
- 같은 방의 모든 참여자에게 동일한 `room_question_seed` 문항이 제공됨
- 좌우 위치 무작위화가 문항 선택과 결과를 바꾸지 않음
- 같은 한 판 안에서 중복 문항이 없음
- 최근 90일 새 문항이 충분할 때 같은 그룹 재게임 중복률이 20% 이하
- 8·16·20·24문항 길이에서 결과 분모가 실제 완료 문항 수와 일치
- 두 라운드 누적 결과가 각 라운드의 원시 일치 수 합산 결과와 일치

### 통합

- 2인 정상 완주
- 3인 이상 그룹 완주
- 한 명 중도 이탈 후 완주자만으로 결과 생성
- 중도 합류 완주 전 기존 결과 유지
- 중도 합류 완료 후 새 결과 스냅샷 생성
- 2명 완료 시 현재 결과 생성
- 목표 정원 전원 완료 시 최종 결과 확정
- 정원 미달 상태에서 방장 마감 후 완주자 기준 최종 결과 확정
- 동시에 남은 한 자리에 진입할 때 한 명만 좌석 확보
- 15분 안에 첫 답이 없으면 예약 좌석 반환
- 가득 찬 피드 모집 카드가 모집 완료로 갱신
- 피드 모집 카드 삭제·방 마감·방 삭제 상태 동기화
- 새로고침·재접속 후 진행률 복구
- 정확히 반반으로 갈린 문항
- 가장 높은 주제 동률
- 익명 참여자 재접속
- 만료된 방 코드
- 동시에 마지막 답을 제출하는 경쟁 조건
- 이전 결과 스냅샷과 새 결과 혼동 방지

### 권한

- A는 자신의 A-B 결과 조회 가능
- B도 같은 A-B 결과 조회 가능
- A는 동의 없이 B-C 결과 조회 불가
- 비참여자는 방 결과 조회 불가
- 공유 링크에 개별 답안이 기본 노출되지 않음
- 만료된 방 코드는 접근 불가
- 참여자 삭제 시 관련 공유 결과 무효화

### 접근성과 UI

- 모바일 360px 이상에서 가로 스크롤 없음
- 두 선택지가 잘리지 않고 읽힘
- 색상 없이도 선택 상태를 이해할 수 있음
- 키보드와 스크린리더로 참여 가능
- 터치 영역 최소 44px
- 네트워크 실패 뒤 마지막 저장 문항부터 복구
- 선택 중 타인의 응답·분포가 노출되지 않음

## 24. MVP 수용 기준

### 명칭 분리

- 기존 커뮤니티 사용자 화면에서 `밸런스 게임` 문구가 남아 있지 않다.
- 커뮤니티에는 `투표`, 검사 > 함께하기에는 `밸런스 게임`이 표시된다.
- 기존 `balance_game` 데이터와 통계가 그대로 작동한다.
- 새 게임은 `together_balance_game` 도메인을 사용한다.

### 참여

- 방장은 주제 선택 후 목표 정원 2~8명과 `친구에게 초대`·`피드에서 모집` 중 하나를 고를 수 있다.
- 방장은 팩에서 지원하는 `8`, `16~20`, `24`, `계속` 길이를 고를 수 있다.
- 목표 정원을 넘는 참여자는 원자적으로 차단된다.
- 초대받은 사람은 가입 없이 닉네임만으로 시작할 수 있다.
- 피드 모집방은 로그인, 신고, 차단, 한 계정 한 자리 규칙을 적용한다.
- 모든 참여자에게 동일 버전·동일 문항 순서가 제공된다.
- 좌우 위치가 달라도 고정 `option_id`로 같은 답을 판별한다.
- 선택 즉시 저장되고 새로고침 뒤 이어서 할 수 있다.
- 완료 전 다른 사람의 답이 보이지 않는다.
- 같은 방 안에 중복 문항이 없고 모든 참여자가 같은 라운드 문항을 받는다.
- 라운드 결과 뒤 같은 멤버로 새 문항 8개를 이어갈 수 있다.

### 결과

- 완료자가 2명 미만이면 궁합 점수가 열리지 않는다.
- 2명 이상 완료하면 현재 결과가 열린다.
- 목표 정원 전원 완료 또는 방장 마감 시 최종 결과가 열린다.
- 그룹 점수는 모든 2인 조합의 반올림 전 평균과 일치한다.
- 전원 일치와 가장 갈린 문항을 확인할 수 있다.
- 참여자를 선택하면 현재 사용자와 해당 참여자만의 결과를 볼 수 있다.
- 같은 선택과 다른 선택을 문항별로 확인할 수 있다.
- 후발 참여자가 완료하면 결과가 새 스냅샷으로 정확히 갱신된다.
- `끌리는 사람`은 이상형 취향 닮음도로 표시되고 참가자 서로의 연애 궁합으로 표시되지 않는다.
- `우리 둘의 연애 케미`는 선호와 상대 자기 행동을 양방향 교차해 적중도와 역할 호흡을 표시한다.

## 25. 구현 순서

1. 용어·도메인 경계 고정
2. `taste_sync`·`ideal_preference`·`reciprocal_fit`·`dilemma_fun` 템플릿과 결과 의미 고정
3. 콘텐츠 카탈로그 검수와 공개 출시 8개 팩의 최소 문항 풀 확보

9. 응답 러너와 자동 저장
