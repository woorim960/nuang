## 운영자가 지금 한 번만 할 일

Supabase SQL Editor에서 아래 파일 전체를 실행한다.

`supabase/migrations/202608030003_marketing_email_release1.sql`

실행 순서:

1. Supabase 프로젝트를 연다.
2. 왼쪽 메뉴에서 `SQL Editor`를 연다.
3. `New query`를 누른다.
4. 위 파일의 내용을 처음부터 끝까지 복사해 붙여넣는다.
5. `Run`을 누른다.
6. 오류 없이 완료되면 Codex에게 `202608030003 실행 완료`라고 알려준다.

직접 DB 연결은 현재 저장된 비밀번호와 맞지 않아 Codex가 대신 실행할 수 없었다. 이 작업은 데이터 삭제가 아니라 캠페인·발송 상태 테이블과 안전 함수를 추가하는 마이그레이션이다.

## SQL 실행 뒤 Codex가 마무리할 일

1. 운영센터 `/admin/marketing` 데이터 연결 확인
2. 현재 로그인한 운영자 이메일로 실제 테스트 메일 1건 발송
3. 제목 `(광고)`, 발신자, Reply-To, 본문, 모바일 레이아웃, 수신거부 링크 확인
4. 원클릭 수신거부와 suppression 기록 확인
5. Resend 전달 webhook과 운영센터 집계 확인
6. 테스트용 동의를 원상 복구
7. 모든 Gate 통과 후 `MARKETING_EMAIL_SEND_ENABLED=true` 적용
8. 마지막 운영 재배포와 smoke test

## 첫 실제 캠페인 운영 순서

1. 운영센터의 `이메일 캠페인`에서 초안을 작성한다.
2. `운영자 테스트`를 눌러 본인 메일에서 확인한다.
3. 제목과 본문, 링크를 다시 읽고 `승인`한다.
4. 예약 시각을 고르거나 바로 대기열에 넣는다.
5. 발송 중 이상이 보이면 즉시 `일시중지`한다.
6. 전달·반송·신고·수신거부·실패 수치를 확인한다.

운영자는 회원의 동의를 대신 켤 수 없고 원문 이메일 목록을 내려받을 수 없다. 캠페인 대상을 확정한 뒤에도 실제 발송 직전에 동의와 인증 상태를 다시 확인한다.

## 법률 확인 기준

변호사나 별도 기관의 사전 승인을 받아야만 이메일을 보낼 수 있는 구조는 아니다. Release 1은 대한민국 현행 법령과 KISA 안내에 맞춘 기술 Gate를 적용했다. 다만 아래 상황에서는 외부 법률 검토를 권장한다.

- SMS·앱 푸시 등 새 광고 채널을 열 때
- 오후 9시 이후 광고 발송을 검토할 때
- 해외 사용자를 대상으로 현지 마케팅을 시작할 때
- 민감정보나 제3자 데이터를 광고 대상 선정에 사용하려 할 때
- 법령 또는 KISA 안내가 크게 바뀔 때

이 내부 판단 과정이나 법률 검토 여부를 사용자에게 별도 경고 문구로 노출하지 않는다. 사용자에게는 명확한 선택권과 정상적으로 동작하는 설정만 제공한다.
