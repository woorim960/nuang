# 뉴앙 베타 출시·운영 기준서

- 버전: `nuang-beta-v1.0`
- 확정일: 2026-08-05
- 출시 트랙: `value_validation_beta`
- 목표: 심리측정의 정식 인증이 아니라 실제 사용가치·완료·재방문·소셜 확장 가능성 검증

이 문서는 NUANG Beta의 출시 판단에 관한 현재 기준이다. 과거 MVP 감사·제품
기획 문서와 출시 조건이 충돌하면 이 문서와 `scripts/mvp-go-live-gates.json`을
우선하며, 유예 항목을 완료 또는 승인으로 해석하지 않는다.

## 1. 베타의 약속

뉴앙 베타는 검사 연구와 외부 법률 검토를 완료한 것처럼 표시하지 않는다. AI는
사람 검토와 같은 체크리스트·독립 역할·반론·증거 원장·재현 절차로 사전검토를
수행하지만 효력은 내부 위험 발견과 개선에 한정한다.

- 사용자 결과: 자기이해와 대화를 위한 탐색 자료
- 금지 주장: 진단, 능력, 순위, 합격·부적합, 과학적 정확도 보장, 검증 완료
- AI 최고 상태: `사람 검토 준비`
- 사람 연구 상태: `유예 · 승인 아님`
- 외부 법률 검토 상태: `유예 · 승인 아님`
- 후보 결과 기본 공개 범위: 본인 전용
- 후보 결과 공개 프로필·공유·피드·사람 비교: 사람 검증 전 서버 차단

## 2. 출시 필수와 유예 항목

### 베타 출시 필수

1. AI 측정 사전검토 네 트랙과 blocker 조치
2. AI 법률·개인정보 사전대조와 실제 서비스 흐름 일치
3. Google·Kakao 운영 OAuth 실제 왕복
4. 보안·개인정보 P0 및 운영 migration 재검증
5. 비방해형 사용자 가치 분석과 운영센터 집계
6. 전체 자동 테스트·모바일/데스크톱 E2E·운영 smoke
7. 배포 후보와 운영 배포 commit 일치

2026-08-05 현재 1~~5는 기록된 코드·운영 증빙으로 완료했다. 6~~7은 최종 전체
QA와 단일 출시 후보·배포 SHA를 만드는 `release_candidate` 게이트에서 함께
완료한다. 최소 법률·개인정보 게이트의 완료는 외부 법률 승인과 별개다.

### 기록을 남기고 유예

| 항목                              | 재검토 시점                                                                      |
| --------------------------------- | -------------------------------------------------------------------------------- |
| 독립 사람 연구와 실제 정량 타당화 | 정식 검사를 표방하거나 후보 결과를 공개 프로필·공유·비교에 연결하기 전           |
| 외부 법률 전문가 검토             | 유료화, 실제 광고 본운영, 만 14세 미만 가입, 정식 공개 확대 중 가장 이른 시점 전 |

유예된 항목은 출시 검사기에서 삭제하지 않는다. 유예 사유·일자·재검토 조건이
없으면 유효한 유예로 인정하지 않는다.

## 3. AI 사전검토

상세 프로토콜은 `NUANG_AI_MEASUREMENT_PREREVIEW_PLAN.md`를 기준으로 한다.

2026-08-05에는 quick/full 후보 코어를 대상으로 네 트랙을 실제 실행했다. 재현
패킷은
`docs/research/ai-prereview/NUANG-AI-MEASUREMENT-PREREVIEW-1.0/2026-08-05-core-candidate-r1/`
에 보관하며, 상태는 `completed_with_blockers`, 사람 gate 효과는 `none`이다. AI가
안전하게 고칠 수 있는 공개 전파와 결과 문구 문제는 조치했고, 실제 표본·DIF·
EFA/CFA·신뢰도·적응형 문항 인지검토는 사람 검증 유예 항목으로 남겼다. 따라서
AI 사전검토 절차는 베타 기준으로 완료했지만 측정 도구를 `validated`나 `active`로
승격하지 않았다.

| 트랙             | AI 역할                                      | 사용자 출시 전 개선 대상                     |
| ---------------- | -------------------------------------------- | -------------------------------------------- |
| 인지·내용        | 문항 이해, 단일 행동, 일상어, 결과 주장 범위 | 모호·이중 질문·과장 결과 문구                |
| 공정성·불변성    | 문화·성별·직업·장애·문해·자원 전제 위험      | 낙인·도덕성·능력 오독과 접근성               |
| 정량 파일럿 준비 | 표본·제외·결측·재검사·분석 실패 규칙         | 실제 연구 전에 발견 가능한 설계·코드 결함    |
| 신뢰도·구조      | 경쟁 모형·불확실성·경계·점수-문구 연결       | 합성 데이터로 통과를 만들지 않는 fail-closed |

모든 AI 의견은 다수결로 blocker를 없애지 않으며 반론과 소수 위험 의견을 함께
보존한다.

## 8. 베타 모집과 판단

### 점진 공개

- 운영자 주변 사용자부터 별도 최소 인원 없이 순차적으로 초대
- 실제 사용 피드백을 반영하며 같은 베타에서 계속 개발·배포
- 안정화 이후 SNS를 통해 불특정 사용자에게 자연스럽게 공개 범위 확대
- 모바일 기종과 로그인 제공자가 한쪽에만 치우치지 않는지 함께 확인
- 릴리스 버전별 완료율·반복 사용·공유/비교·불편 신호와 실제 표본 수를 함께 표시

베타 확대와 MVP 전환은 특정 모집 인원으로 자동 결정하지 않는다. 치명 보안·
개인정보 사고 0건, 주요 흐름 안정성, 검사 완료와 반복 사용, 사용자가 스스로
설명할 수 있는 핵심 가치, 다음 개선 우선순위의 명확성을 함께 보고 운영자가
결정한다. 비율 목표는 실제 기준선이 쌓인 뒤 릴리스별로 정한다.

## 9. 마지막 운영자 작업

Google·Kakao 운영 도메인·callback·동의 화면과 실제 로그인·연결·로그아웃·
재로그인은 완료 증빙을 남겼다. 이후 운영자에게 남는 확인은 다음과 같다.

1. 정책 문서의 실제 운영 정보와 고객 문의 이메일 수신 확인
2. 최종 배포 후보 SHA와 전체 QA 결과 확인
3. 새 베타 사용자에게 베타·비진단·의견 수집 범위 안내
4. 최종 배포 승인

필수 조건을 모두 완료해도 자동으로 운영 배포되지 않는다. 운영자의 최종 배포
승인 뒤에만 공개한다.
