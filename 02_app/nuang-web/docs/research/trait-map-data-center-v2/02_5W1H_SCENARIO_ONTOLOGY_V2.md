# 뉴앙 5W1H 상황 분류체계 v2

- 계약: `NUANG-TRAIT-MAP-SCENARIO-ONTOLOGY.v2`
- canonical 상황: `72개`
- 핵심 맥락: `6개`
- 맥락별 대표 순간: `12개`

## 1. 왜 상황을 분리하는가

성향은 한 번의 행동이 아니라 여러 상황에서 반복되는 생각·감정·행동의
경향이다. 같은 사람도 가족과 있을 때, 처음 보는 사람과 있을 때, 갈등이
생겼을 때 다른 반응을 보일 수 있다.

따라서 “ENAKQ는 이렇게 행동한다”라는 한 문장 대신 다음을 분리한다.

- 누구와 있는가
- 언제 일어난 일인가
- 어디에서 일어났는가
- 무엇을 해야 하는가
- 어떤 과정과 행동을 관찰하는가
- 어떤 성향 방향이 이유를 설명할 후보인가

상황 변화가 성격 상태 표현에 영향을 준다는
[Whole Trait Theory](https://pubmed.ncbi.nlm.nih.gov/26097268/)와 주요 상황
특성을 별도로 분류한
[DIAMONDS 연구](https://pubmed.ncbi.nlm.nih.gov/25133715/)를 구조 설계에
참고한다. 두 연구를 뉴앙 코드의 직접 검증으로 사용하지는 않는다.

## 2. 여섯 가지 핵심 맥락

| 맥락 | 누구 |
| --- | --- |
| 일반·일상 | 나 자신 |
| 가족 | 나와 가족 |
| 친구 | 나와 친구 |
| 연인 | 나와 연인 |
| 마음 가는 사람 | 나와 알아가고 싶은 사람 |
| 업무·학습 | 나와 동료·팀 |

향후 학교·온라인 커뮤니티·낯선 집단은 `supplemental` 상황으로 추가할 수
있다. v2의 72개 필수 커버리지는 위 6개 맥락으로 고정한다.

## 3. 열두 가지 대표 순간

| ID | 순간 | 확인하는 일 |
| --- | --- | --- |
| ordinary_choice | 평소 선택 | 무엇부터 살피고 고르는가 |
| new_encounter | 새로운 만남·일 | 어떻게 관심을 두고 시작하는가 |
| group_participation | 여러 사람과 함께함 | 어떻게 참여하고 표현하는가 |
| plan_change | 계획 변경 | 변화에 어떤 생각과 반응이 나타나는가 |
| uncertainty | 불확실함 | 무엇을 더 찾고 무엇을 걱정하는가 |
| disagreement | 의견 차이·갈등 | 무엇에 주목하고 어떻게 푸는가 |
| support_requested | 상대가 힘든 일을 말함 | 마음과 해결 중 무엇을 먼저 살피는가 |
| need_expression | 내 필요를 말함 | 언제 어떻게 요청하는가 |
| boundary | 거절·선 정하기 | 내 선택과 상대 선택을 어떻게 다루는가 |
| success | 좋은 결과 | 기쁨을 어떻게 느끼고 나누는가 |
| setback | 실수·실패 | 처음 무엇을 생각하고 어떻게 움직이는가 |
| aftermath | 일이 지나간 뒤 | 어떻게 회복하고 관계를 다시 잇는가 |

6개 맥락에 12개 순간을 각각 연결해 72개 canonical 상황을 만든다.

## 4. 5W1H 필드

### Who

- `self`
- `family_member`
- `friend`
- `partner`
- `person_of_interest`
- `colleague`
- `manager`
- `direct_report`
- `unfamiliar_person`
- `group`

### When

위 12개 대표 순간을 사용한다. “평소”, “가끔”처럼 시간 범위가 모호한
표현만으로 상황을 만들지 않는다.

### Where

- 혼자 있는 곳
- 집
- 오프라인 모임
- 사적인 대화
- 온라인 대화
- 직장
- 학교
- 공공장소

장소는 성향을 판정하는 변수가 아니라 행동이 달라질 수 있는 조건이다.

### What

- 선택하기
- 먼저 연락하거나 말 걸기
- 여러 사람과 함께하기
- 바뀐 계획에 대응하기
- 정보와 가능성 찾기
- 의견 차이 풀기
- 상대의 어려움에 반응하기
- 내 필요 표현하기
- 거절하거나 선을 존중하기
- 좋은 결과에 반응하기
- 실수나 실패에 반응하기
- 회복하고 다시 연결하기

### How

다음 관찰 채널을 분리한다.

- 먼저 향하는 관심
- 처음 드는 생각
- 실제 나타나는 반응
- 말과 대화 방식
- 선택
- 행동을 이어가는 방식
- 감정이 활성화되는 방식
- 회복 방식

처음 드는 생각과 실제 반응을 같은 것으로 저장하지 않는다. 같은 생각이
들어도 경험·가치·관계에 따라 다른 행동을 선택할 수 있기 때문이다.

### Why

‘왜’는 마음을 읽는 문장이 아니라 측정된 방향으로 설명할 수 있는 후보를
기록한다.

| 렌즈 | 설명 후보 |
| --- | --- |
| SE | 사람 사이 에너지와 먼저 표현하는 방식 |
| OE | 구체적인 정보와 확장 탐색 중 관심이 향하는 방식 |
| RO | 관계에서 원인·해결과 상대 마음 중 먼저 주목하는 곳 |
| SM | 시작·지속·정리와 상황 영향 |
| ER | 걱정과 감정이 활성화되는 속도와 크기 |

예를 들어 `A`가 있다는 이유만으로 “상대를 사랑해서”라고 설명하지 않는다.
측정된 범위 안에서 “상대의 감정 상태가 먼저 눈에 들어오는 경향”이라고
설명한다.

## 5. 상황 claim의 필수 데이터

상황별 claim에는 다음 정보가 필요하다.

- `scenarioId`
- 대표 코드
- 축 점수
- 필요한 경우 facet 점수
- 관계 맥락
- 상황 신호
- claim 근거
- 처음 생각·실제 반응을 보여줄 경우 해당 개인 과정 신호
- 공개 범위
- 검토와 발행 상태

관계 맥락이나 상황 신호가 없으면 관계별 문구를 개인 결과처럼 호출하지 않는다.

## 6. 상황 설명 작성 구조

```text
상황
→ 먼저 눈에 들어오는 것
→ 처음 드는 생각
→ 실제 나타나기 쉬운 반응
→ 상대가 그렇게 받아들일 수 있는 이유
→ 잘 통하는 대화 방법
```

한 상황에서 다섯 축을 모두 억지로 설명하지 않는다. 해당 장면과 직접 관련된
축·facet만 선택한다.

## 7. 상황 커버리지 승인

역할형 하나가 상황 커버리지를 통과하려면 다음을 만족해야 한다.

- 72개 canonical 상황이 모두 연결됨
- 6개 관계 맥락별 12개 상황이 빠짐없이 존재
- 상황 ID 중복 0건
- 한 상황에 관찰 채널 2개 이상
- 한 상황에 금지 추론 1개 이상
- 상황 claim이 `scenario_context`를 필수 신호로 요구
- 가족·친구·연인·마음 가는 사람·업무 claim이
  `relationship_context`를 요구
- 상황별 설명과 일반 설명의 contentKey 중복 0건

## 8. 제품에서의 사용

72개 상황을 한 화면에 나열하지 않는다.

- 정밀 검사 결과: 점수와 관련된 6~10개 장면
- 내 성향 상세: 사용자가 고른 관계·상황 중심
- 성향지도 상세: 맥락별 탐색
- 나와 비교하기: 두 사람의 차이가 큰 장면 중심
- 커뮤니티: 오늘의 질문·밸런스 게임에 안전한 일부 장면

같은 상황 데이터가 여러 화면에 사용되더라도 원본 claim은 한 번만 관리한다.
