# 뉴앙 근거·Claim 승인 기준 v2

- 기준: `NUANG-TRAIT-MAP-EVIDENCE-CLAIM-STANDARD.v2`
- 상태: `FOUNDATION_LOCKED`
- 목적: 논문 수가 아니라 추적 가능한 근거와 검증으로 성향 문장을 승인한다.

## 1. 근거 수집 원칙

근거 검색은 다음 순서를 따른다.

1. 질문과 구성개념을 먼저 정의한다.
2. 검색식·데이터베이스·기간·언어 범위를 기록한다.
3. 제목·초록 단계에서 포함·제외한다.
4. 원문 단계에서 포함·제외 이유를 기록한다.
5. 논문 전체가 아니라 필요한 결과 단위로 추출한다.
6. 뉴앙 축·facet과의 관계를 `부분 일치·인접·비동일`로 매핑한다.
7. 지지 결과뿐 아니라 반대·무효 결과도 저장한다.
8. 새 근거가 들어오면 기존 claim 영향 범위를 다시 계산한다.

검색 과정은 [PRISMA 2020](https://www.prisma-statement.org/)의 투명한 보고
원칙을 참고한다. PRISMA를 지켰다는 사실이 개별 claim의 타당성을 자동으로
보장하지는 않는다.

## 2. 우선 근거 유형

다음 순서로 우선한다.

1. 공식 검사·측정 표준
2. 메타분석·체계적 문헌고찰
3. 사전등록·등록보고 연구
4. 종단·반복 측정·경험표집 연구
5. 독립 표본을 사용한 심리측정 연구
6. 문화 간 비교와 한국어·한국 표본 연구
7. 일반 동료평가 연구
8. 뉴앙 자체 정성·정량 연구

뉴앙 자체 연구는 외부 근거를 대체하지 않는다. 외부 연구도 뉴앙의 문항과
32개 조합을 직접 검증한 것으로 확대 해석하지 않는다.

## 3. 근거 자료 필수 필드

- 자료 ID
- 제목·저자·연도
- DOI 또는 확인 가능한 URL
- 연구 분야
- 연구 설계
- 표본·국가·언어
- 표본 수
- 사용한 측정 도구
- 포함·제외 상태와 이유
- 편향 위험
- 뉴앙과의 직접성
- 문화 적합성
- 반복·독립 표본 여부

## 4. 논문에서 결과를 추출하는 단위

한 논문에서 서로 다른 결과가 여러 개 나올 수 있으므로 `source`와 `finding`을
분리한다.

각 finding은 다음을 가진다.

- 어떤 구성개념을 다뤘는가
- 어떤 집단에서 확인했는가
- 어떤 상황과 관계 맥락인가
- 결과가 지지·보완·반박·무효 중 무엇인가
- 효과 크기와 구간이 있는가
- 어떤 제한이 있는가
- 누가 추출하고 누가 재확인했는가

요약문만 읽고 finding을 확정하지 않는다. 핵심 claim은 원문 방법과 결과를
확인한다.

## 5. 근거 등급

| 등급 | 의미 | 사용 범위 |
| --- | --- | --- |
| A | 여러 독립 연구와 높은 품질의 종합 근거가 일관됨 | 핵심 정의·안전한 일반 경향 후보 |
| B | 두 개 이상의 적절한 연구 또는 독립 표본이 지지 | 상황·관계 경향 후보 |
| C | 한 연구·간접 근거·문화 적응 미확인 | 연구용 또는 인지검사 후보 |
| D | 이론·뉴앙 가설·내부 관찰 수준 | 고객 발행 금지, 정량 검증 필요 |

등급은 연구 설계뿐 아니라 뉴앙 claim과의 직접성을 함께 본다. 좋은 메타분석도
뉴앙이 측정하지 않는 구성개념에 관한 것이라면 직접 등급은 내려간다.

## 6. Claim 구조

각 claim은 다음을 포함한다.

- 안정적인 `claimId`
- 설명 대상: 축·facet·상호작용·역할형
- claim 범위: 정의·상황·비교·방법 경계
- 어떤 종류의 경향인가
- 연구용 명제
- 고객용 짧은·표준·장문 문구
- 관계 맥락과 상황 ID
- 필요한 실제 사용자 신호
- 근거 finding과 독립 source
- 근거 상태와 등급
- 개인정보 범위
- 위험 영역
- 전문 검토 상태
- 발행 상태

문구가 다듬어져도 의미가 같으면 claim ID를 유지한다. 의미가 달라지면 새
claim ID를 만든다.

## 7. Claim 상태

```text
unmapped
→ mapped_provisional
→ external_supported
→ nuang_validation_required
→ supported
→ validated
→ approved
→ published
```

어느 단계에서든 근거가 충돌하거나 위험이 발견되면 `hold` 또는 `rejected`로
이동한다.

### 상태 의미

- `external_supported`: 외부 구성개념 수준의 근거가 있음
- `nuang_validation_required`: 뉴앙 점수·문구·조합과의 연결은 검증 전
- `supported`: 정성·정량 자료가 미리 정한 기준을 지지
- `validated`: 재현·공정성·이해 가능성까지 통과
- `approved`: 고객 문구와 제품 노출 검토 통과
- `published`: 특정 릴리스에 포함

## 8. 고객용 Claim 승인 조건

모든 고객용 claim:

- finding 1개 이상
- 추적 가능한 source 1개 이상
- 필요한 사용자 신호가 실제로 존재
- 성격심리·심리측정·안전·쉬운 문장 검토 통과
- 동일 의미의 contentKey 중복 없음
- 고객용 짧은·표준·장문 문구 존재

고위험 claim:

- 서로 독립적인 source 2개 이상
- 관계심리·임상안전 검토 필수
- 뉴앙 사용자 자료에서 별도 확인
- 결과·능력·진단을 직접 확정하지 않음

고위험 영역:

- 관계 성공·만족
- 상대의 호감·끌림
- 정신건강·임상
- 능력
- 업무 성과

## 9. 인지 내용타당도

실제 사용자가 다음 네 단계를 어떻게 거치는지 확인한다.

1. 이해: 문장을 어떤 뜻으로 읽는가
2. 회상: 어떤 실제 경험을 떠올리는가
3. 판단: 경험의 무엇을 기준으로 삼는가
4. 표현: 자신의 경험을 답과 문장으로 옮길 수 있는가

관련성·포괄성·이해 가능성을 분리하는
[COSMIN 내용타당도 방법론](https://pmc.ncbi.nlm.nih.gov/articles/PMC5891557/)
을 참고한다.

‘나와 잘 맞는 것 같다’는 반응만으로 정확성을 승인하지 않는다. 정확한 이해,
구체적 경험 회상, 오해·낙인 여부를 별도로 기록한다.

## 10. 정량 검증

분석 전에 다음을 고정한다.

- 주요 가설과 보조 가설
- 표본과 제외 기준
- 결측 처리
- 측정모형과 경쟁모형
- 핵심 지표와 승인선
- 검사-재검사
- 홀드아웃 또는 교차검증
- 주요 집단의 측정동일성·DIF
- 다중 비교 처리
- 경계형·facet 분화형 처리

결과를 본 뒤 유리한 기준으로 승인선을 바꾸지 않는다. 분석 계획은 내부
타임스탬프 잠금 또는 OSF 사전등록으로 보존한다.

## 11. 쉬운 한국어 승인

고객 문구는 다음을 통과해야 한다.

- 한 문장에 핵심 내용 하나
- 번역체와 추상 명사 남용 없음
- ‘리듬’, ‘장면’, ‘방향’처럼 문맥 없이 모호한 표현을 피함
- 행동과 이유를 구체적인 일상말로 설명
- `그럴 수도 있고 아닐 수도 있다`는 면책 문구 반복 없음
- 능력·도덕성·우열을 암시하지 않음
- 어린 사용자와 성향검사에 익숙하지 않은 사용자도 이해
- 모바일 줄바꿈에서도 의미 단위가 깨지지 않음

명확한 고객 문구를 만들기 위해 연구 불확실성을 숨기는 것이 아니라,
검증된 범위만 선명하게 말하고 나머지는 발행하지 않는다.

## 12. 성향 패키지 승인 기준

한 역할형은 다음을 모두 충족해야 한다.

- 16개 필수 장
- 공백 제외 50,000~60,000자
- claim 100개 이상
- source 30개 이상
- 72개 상황 연결
- 5개 인접 코드 비교
- 모든 전문 검토 통과
- 인지검사 통과
- 정량검증 통과
- 중복·모순·개인정보 감사 통과

이 기준은 코드 계약과 자동 테스트에도 동일하게 적용한다.
