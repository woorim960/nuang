# 뉴앙 서비스 내 검증 흐름 v1

## 목적

사용자가 뉴앙을 이용하는 흐름 안에서 문항의 이해도와 성향지도 설명의 적합도를
가볍게 남길 수 있게 한다. 수집된 기록은 검토 대기 신호이며, 고객용 검사 문항,
점수 규칙, 성향지도 문장을 자동으로 바꾸지 않는다.

## 1. 문항 검증

### 고객용 검사와 연구용 문항의 분리

- 빠른 코어와 정밀 코어는 현재 고정된 고객용 릴리스를 계속 사용한다.
- 연구 화면의 응답은 고객 결과를 계산하지 않는다.
- 후보 문항은 인지 검토, 전문가 검토, 정량 검증을 통과하기 전까지 고객용
  검사에 들어가지 않는다.

### 한 번의 참여에 보여줄 문항

서버가 참여를 시작할 때 아래 12문항을 배정하고 세션에 스냅샷으로 고정한다.

1. 현재 빠른 검사 문항 4개
2. 현재 정밀 검사 문항 중 빠른 검사에 없는 문항 4개
3. 150개 후보 은행 중 현재 검사와 겹치지 않는 문항 4개

같은 출처 안에서는 지금까지 덜 노출된 문항을 우선하고, 다섯 성향 영역이 한쪽에
쏠리지 않도록 고른다. 선택한 뒤에는 질문 순서를 섞는다.

새 세션 컬럼 마이그레이션 전후 모두 같은 문항을 검증할 수 있도록 서버가
세션 ID와 12문항 순서를 묶은 서명 증표도 발급한다. 제출 시 DB 스냅샷을
우선하고, 스냅샷 컬럼이 아직 없으면 서명 증표를 검증한다. 서명이 바뀌거나 다른
세션의 증표면 저장하지 않는다.

### 후보 문항 원장

- Supabase에는 후보 문항 150개와 베타 문항 60개를 별도 릴리스로 보관한다.
- 고객용 활성 상태가 아니라 각각 `candidate`, `beta`로 유지한다.
- `npm run research:core:measurement-catalog:check`로 원장 수를 확인한다.
- 누락됐을 때만 `npm run research:core:measurement-catalog:sync`로 비파괴
  upsert한다.
- 동기화 스크립트는 이미 `validated` 또는 `active`인 릴리스를 덮어쓰지 않는다.

### 저장하는 신호

- 처음 고른 답과 마지막 답
- 답을 바꾼 횟수
- 처음 답하기까지 걸린 시간
- `이 질문이 헷갈렸어요` 선택 여부와 짧은 리뷰
- `이 상황은 답하기 어려워요`의 이유
- 전체 완료 시간과 품질 제외 사유

### 반영 규칙

- 문항별 8개 응답부터 초기 위험 신호를 계산한다.
- 헷갈림, 문구 불명확, 판단 어려움, 답 변경 비율이 기준을 넘으면 사람 검토
  목록에 올린다.
- 자동 분석은 후보를 추천할 뿐, 고객용 릴리스를 직접 교체하거나 활성화하지
  않는다.

### 후보 문항 승격 잠금

후보 문항은 아래 조건을 모두 만족해야 `전문가 검토 가능` 상태가 된다.

- 유효 응답 80개 이상
- 문구 불명확 10% 이하
- 헷갈림 표시 12% 이하
- 판단 어려움 18% 이하
- 답 변경 20% 이하
- 답변 시간 중앙값 0.8초 이상

이 기준을 통과해도 고객용 검사로 자동 승격하지 않는다. 전문가가 측정 의도,
편향, 중복, 표현, 점수 방향을 별도로 검토하고 승인한 뒤 새 고객용 릴리스를
만들어야 한다. 정책 버전은
`GATE-C-CANDIDATE-PROMOTION-POLICY-1.0`으로 고정해 결과를 재현한다.

## 2. 검사 탭 진입

검사 탭 하단의 `검사 질문 리뷰하기` 한 곳에서 진입한다.

- 예상 시간과 이벤트 핵심 정보만 먼저 보여준다.
- 연구 동의와 기본 통계 정보는 시작 화면에서 받는다.
- 검사 중에는 실제 코어 검사와 같은 질문 컴포넌트를 사용한다.
- 완료 화면에서 피드백이 뉴앙코드 분석의 정밀도와 정확도 개선에 쓰인다는 점을
  알려준다.

## 3. 리뷰 이벤트

연구 응답과 회원 계정·이벤트 응모 기록은 분리해야 한다.

- 안내 문구: 리뷰 참여자 중 10명 추첨, 스타벅스 모바일 금액권 5,000원
- 이벤트 응모는 연구 참여와 별도 선택으로 운영한다.
- 시작일은 두지 않는다. MVP 공개 시점부터 참여할 수 있다.
- 응모 마감: 2026년 9월 30일 23:59(한국시간)
- 추첨·발표: 2026년 10월 1일
- 연락 수단: 회원 비공개 프로필에 등록한 국내 휴대전화번호
- 중복 기준: 완료한 참여를 가진 회원 계정·휴대전화번호별 한 번
- 이벤트 응모 기록 삭제: 2026년 11월 1일 자동 삭제
- 회원 연락처 보관: 계정 정보로 유지하며 회원이 프로필에서 직접 변경·삭제
- MVP 공개와 함께 별도 시작일 없이 응모를 연다.
  `GATE_C_REVIEW_EVENT_ENTRY_ENABLED=false`는 긴급 중단용으로만 사용한다.

### 응모 데이터 분리

- 연구 세션에는 이름·이메일·휴대전화 번호를 저장하지 않는다.
- 이벤트 응모 저장소에는 연구 응답, 참여번호, 공개 보관 번호와 암호화된
  휴대전화번호를 저장하지 않는다.
- 참여 여부는 캠페인별 HMAC 조회값으로 한 번만 확인하며 원본 보관 번호는 즉시
  버린다.
- 휴대전화번호는 회원 비공개 프로필에서 계정별 AAD를 적용한 AES-256-GCM으로
  암호화하고, 이벤트 중복 응모 확인에는 되돌릴 수 없는 HMAC 값만 사용한다.
- 연락처 방식은 `mobile_phone`과 `email`을 지원하지만, 실제 운영에서는 승인된
  한 방식만 서버 설정으로 연다.
- 이벤트 응모 기록은 보관 종료일이 지나면 매일 자동 삭제하고, 회원 연락처와
  연구 응답의 보관 기간은 각각 별도로 관리한다.
- 회원이 연락처를 삭제할 때 진행 중인 이벤트가 있으면 응모 취소를 함께
  확인한다.
- MVP에서는 번호 형식만 확인해 `미인증`으로 저장한다. 출시 이후 SMS 인증을
  추가해도 같은 연락처 필드와 `verified` 상태를 사용한다.
- 발표일 전까지 응모 API와 입력 화면을 열고, 마감 시각이 지나면 서버와 화면을
  함께 닫는다.

## 4. 성향지도 섹션 피드백

### 노출 조건

- 로그인 계정에 저장된 대표 검사 결과 코드와 현재 상세 지도의 코드가 같을 때만
  섹션별 링크를 노출한다.
- 정밀 검사 결과가 있으면 정밀 결과를 우선하고, 없으면 가장 최근 빠른 결과를
  사용한다.
- 다른 사람의 코드, 결과가 없는 계정, 로그인하지 않은 상태에서는 노출하지
  않는다.

### 입력 흐름

각 상세 섹션의 본문 아래에 작은 링크
`이 설명은 나와 얼마나 비슷한가요?`를 둔다.

- 매우 비슷해요
- 대체로 비슷해요
- 조금 달라요
- 많이 달라요
- 선택 입력: 어떤 점이 비슷하거나 달랐는지 짧은 메모

같은 사용자는 같은 안내서 버전과 섹션에 대한 의견을 다시 저장해 수정할 수 있다.

### 반영 규칙

- 공개된 안내서 문장을 자동 수정하지 않는다.
- 코드·장·섹션·안내서 버전별로 집계한다.
- 섹션별 20개 응답이 모인 뒤 `조금 달라요`와 `많이 달라요`의 합이 30%
  이상이면 전문 검토 대상으로 올린다.
- 문장 수정 후 안내서 버전을 올리고, 이전 버전 피드백과 섞지 않는다.
