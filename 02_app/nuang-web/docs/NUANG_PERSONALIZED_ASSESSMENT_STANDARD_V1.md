# 뉴앙 고객맞춤형 검사 표준 v1

> 보존 문서: 이 문서에는 `도움이 되었는지`를 측정하던 이전 설계가
> 포함되어 있다. 현재 공식 기준은
> `NUANG_COMFORT_STYLE_OFFICIAL_STANDARD.md`의 `도움이 얼마나
> 필요했는지` 설계를 따른다. 다음 검사 제작 기준은 각 검사의 최신 표준
> 문서와 코드의 버전 계약을 우선한다.

## 이 문서의 목적

이 표준은 `위로받을 때 필요한 것`을 개편하며 확정한 제작 절차다. 앞으로
새 검사를 만들 때 문항 수만 늘리거나 긴 공통 문장을 결과에 붙이지 않는다.
무엇을 측정했는지, 어떤 답에서 어떤 문장이 나왔는지, 말해도 되는 범위가
어디까지인지 코드와 테스트로 추적할 수 있어야 고객맞춤형 검사로 공개한다.

## 개편 전 감사 결과

### 실제로 개인화되던 부분

- 세 도움의 평균점수는 사용자의 답으로 계산했다.
- 답하기 어려운 장면은 50점으로 채우지 않았다.
- 한 도움에서 3개 이상의 장면에 답했을 때만 결과를 보여줬다.

### 고객맞춤형이라고 보기 어려웠던 부분

1. 0~~37점, 38~~62점, 63~100점의 세 문장만 사용했다. 63점과 100점이
   같은 설명을 받았다.
2. 27개 조합은 9개 고정 문장을 이어 붙이는 수준이었다. 조합마다 달라지는
   위로 순서나 요청 문장이 없었다.
3. 도움마다 서로 다른 상황을 물어 평균을 비교했다. 점수 차이가 도움의
   차이인지 상황의 차이인지 구분하기 어려웠다.
4. 평균만 저장해 같은 50점인 `50·50·50·50`과
   `0·0·100·100`을 구분하지 못했다.
5. `실제적인 도움`처럼 문항이 묻지 않은 물리적 부담 분담까지 결과가
   넓어질 수 있었다.
6. 낮은 점수를 반대 위로에 대한 선호처럼 읽을 여지가 있었다.
7. “장면별로 살펴봤다”고 안내했지만 실제 리포트는 장면별 점수를
   사용하지 않았다.

## 심리·측정 설계 원칙

### 1. 측정 대상

이 검사는 최근 6개월에 기억나는 힘든 장면에서 아래 행동이 **얼마나
도움이 되었는지**를 정리한다.

- 마음을 알아주는 도움: 판단하지 않고 듣고 마음을 인정하는 행동
- 방법을 함께 찾는 도움: 막힌 지점, 선택지, 첫 행동을 함께 정리하는 행동
- 내 속도와 선택: 도움의 시점·종류·마지막 선택을 당사자가 정할 수 있게
  하는 전달 방식

앞의 두 영역은 `무엇을 해주는가`, 마지막 영역은 `어떻게 건네는가`다.
하나의 서열로 합치지 않고 화면에서도 두 층위로 나눠 보여준다.

### 2. 측정하지 않는 것

이 검사만으로 아래 내용을 말하지 않는다.

- 공감 능력, 이기심, 독립성이나 의존성
- 애착유형, 우울, 불안이나 그 밖의 정신건강 상태
- 관계의 좋고 나쁨, 상대의 진심, 관계의 미래
- 실제 생활에서 도움을 받으면 반드시 좋아진다는 인과효과
- 다른 사람보다 높거나 낮다는 순위·백분위

### 3. 공통 장면 행렬

상황의 차이와 도움의 차이를 섞지 않기 위해 같은 네 장면마다 세 도움을
모두 묻는다.

| 장면                      | 마음을 알아주는 도움      | 방법을 함께 찾는 도움     | 내 속도와 선택               |
| ------------------------- | ------------------------- | ------------------------- | ---------------------------- |
| 가까운 사람과 오해가 생김 | 판단 없이 들어줌          | 어긋난 지점을 정리함      | 말할 준비와 속도를 존중함    |
| 일이 겹쳐 막막함          | 지친 마음을 알아줌        | 우선순위와 첫 행동을 고름 | 필요한 도움을 먼저 물음      |
| 중요한 결정을 앞둠        | 걱정을 가볍게 여기지 않음 | 선택지의 장단점을 정리함  | 결정을 재촉하지 않음         |
| 실수로 자신감이 떨어짐    | 속상함을 인정함           | 다음 행동을 하나 정함     | 조언 전에 필요한 도움을 물음 |

## 채점과 개인화 규칙

### 1. 답변 환산

5개 답변을 0·25·50·75·100점으로 환산하고 도움별 평균을 반올림한다.
답하기 어려운 장면은 결측으로 두며 50점으로 대체하지 않는다. 한 도움에서
유효 응답이 3개 미만이면 그 도움의 점수와 해석을 공개하지 않는다.

### 2. 답변 의미 구간

| 환산점수 | 고객 문구                 |
| -------- | ------------------------- |
| 0~12     | 거의 도움이 되지 않았어요 |
| 13~37    | 도움이 적었어요           |
| 38~62    | 적당히 도움이 됐어요      |
| 63~87    | 꽤 도움이 됐어요          |
| 88~100   | 매우 도움이 됐어요        |

이 구간은 규준·백분위·진단 절단점이 아니다. 5개 답변 선택지의 뜻을
0~100점에서 읽기 쉽게 옮긴 설명 구간이다.

### 3. 평균과 함께 보존할 값

- 문항별 환산점수
- 도움별 유효 응답 수
- 평균, 최솟값, 최댓값
- 점수 범위와 모집단 표준편차
- 응답 패턴: 범위가 50점 이상이면 `varied`, 미만이면 `steady`

같은 평균이라도 `steady`는 여러 장면에서 비슷하게 느낀 결과로,
`varied`는 장면에 따라 도움이 크게 달랐던 결과로 설명한다.

### 4. 반드시 처리할 결과 모양

- 한 도움이 분명히 높은 경우
- 두 도움이 12점 이내로 비슷한 경우
- 세 도움이 모두 높은 경우
- 세 도움이 모두 낮은 경우
- 평균은 중간이지만 장면 차이가 큰 경우
- 한 도움의 유효 응답이 부족한 경우
- 도움 내용은 높고 선택·속도는 낮은 경우와 그 반대

낮은 점수는 `반대 도움을 좋아한다`로 바꾸지 않는다. 제시한 행동이 최근
장면에서 도움이 적었다는 내용까지만 말한다.

## 결과 리포트 계약

리포트는 아래 순서로 조립한다.

1. 정확한 세 점수와 한 문장 위로 조합
2. `무엇이 도움이 됐나요?` 아래 두 도움
3. `어떻게 도움받을 때 편했나요?` 아래 속도·선택
4. 장면별로 가장 도움이 된 행동과 점수 차이
5. 나에게 맞는 위로 순서
6. 가까운 사람에게 보여줄 한 문장
7. 가족·친구·연인·업무에 적용하는 예시
8. 위로가 어긋났을 때 확인할 종류·시점·양
9. 이번 주 작은 실험
10. 현재 대표 뉴앙 코드가 있다면 다섯 축과 이번 결과를 함께 읽는 설명

각 개인화 단락은 `claimId`를 가진다. 점수 주장에는 도움 ID와 점수를,
장면 주장에는 문항 ID를 연결한다. 관계별 문장은 관계별 차이를
측정했다는 주장으로 쓰지 않고 결과를 적용하는 안내라고 명시한다.

점수 환산식, 결측 처리 기준, 구간 절단점, 패턴 판정 임곗값과 같은 내부
규칙은 고객 리포트 본문에 노출하지 않는다. 이 정보는 버전이 지정된
측정 계약·운영 문서·자동화 테스트에서만 관리한다. 고객에게는 점수의
일상적인 뜻과 결과를 활용하는 방법만 보여준다.

## 화면 원칙

- 결과 첫 화면에서 검사명 다음에 개인화된 위로 조합을 먼저 보여준다.
- 정확한 점수는 숨기지 않는다.
- `무엇`과 `어떻게`를 한 목록에 섞지 않고 제목으로 구분한다.
- 장문 설명보다 먼저 세 단계 위로 순서를 보여준다.
- 답이 부족한 도움은 “중간”으로 보이지 않게 완전히 제외하고 이유를
  설명한다.
- 낮은 점수의 회색 처리로 오류처럼 보이게 만들지 않는다.
- 점수 도움말에서 능력·순위·반대 선호가 아님을 짧게 설명한다.
- `1.`, `2.`, `3.`으로 시작하는 행동 순서는 한 문단에 붙이지 않고
  실제 순서 목록으로 렌더링한다.
- 가족·친구·연인·업무처럼 대상이 다른 안내는 대상명을 별도 라벨로
  두고 한 행씩 분리한다.
- 제목은 `text-wrap: balance`, 본문은 `text-wrap: pretty`를 기본으로
  사용하고, 짧은 단계 라벨은 임의로 글자 중간에서 줄바꿈하지 않는다.
- 340px 이하 화면에서는 관계별 라벨과 설명을 세로로 쌓되 정보 순서는
  유지한다.
- 새 리포트는 문자열을 직접 반복 렌더링하지 않고 공통
  `AssessmentReportRichText` 컴포넌트의 문단·번호 목록·라벨 목록
  블록을 사용한다.
- 긴 상세 리포트는 핵심 결과·점수·바로 쓸 수 있는 문장을 먼저 보여주고,
  나머지 섹션은 같은 화면 안에서 열어 보는 점진적 공개 구조를 사용한다.
- 짧은 대상 라벨과 긴 뉴앙코드 라벨은 같은 고정 너비를 사용하지 않는다.
  공통 리포트 컴포넌트의 `compact`·`wide` 레이아웃을 용도에 맞게 고른다.
- 뉴앙코드 설명은 검사 점수나 결과 순위를 바꾸지 않는다. 현재 코드의
  승인된 별칭과 다섯 축을 사용해 결과를 요청하고 활용하는 방식만
  보완한다.
- 과거 결과에 현재 코드를 동적으로 연결하면 화면에 `현재 내 뉴앙 코드`
  라고 명시하고, 완료 당시 결과와 최신 코드 참고 정보를 시각적으로
  분리한다.

## 버전·저장 원칙

문항, 채점, 리포트는 각각 독립된 버전을 가진다.

- 문항: `comfort-style-v2-common-scenes-2026-07-28`
- 채점: `comfort-style-scoring-v3-pattern-aware`
- 리포트: `comfort-style-report-v5-progressive-code-aware`

문항 또는 채점 버전이 다른 과거 결과를 현재 문장으로 다시 해석하지 않는다.
서버는 브라우저가 보낸 점수를 신뢰하지 않고 공식 문항의 완전성을 확인한 뒤
직접 재채점한다. 결과 스냅샷과 근거 점수를 함께 보존해 문구가 바뀌어도
사용자가 당시 본 결과를 임의로 바꾸지 않는다.

## 전문 협업 절차

1. 기획자가 고객의 질문과 결과에서 해야 할 다음 행동을 정의한다.
2. 심리학 검토자가 구성개념, 과잉해석, 관계 적용 범위를 점검한다.
3. 성향검사 설계자가 문항 행렬, 결측, 채점, 결과 모양을 설계한다.
4. 국문 검토자가 번역체·추상어·중복을 없애고 생활 문장으로 바꾼다.
5. 디자이너가 정보 순서와 읽기 부담을 검토한다.
6. 개발자가 문항→점수→근거 ID→문장→화면의 추적성을 구현한다.
7. 테스터가 모든 경계점, 동점, 결측, 동일 평균·다른 패턴을 자동화한다.
8. 연구 데이터를 받은 뒤 문항과 리포트를 같은 버전에서 함께 재검토한다.

## 출시 전 검증

현재 개편은 **내용·구조 타당성을 높인 MVP 측정 설계**다. 아직 규준화된
심리검사라고 부르지 않는다. 아래 연구를 통과한 버전에만 검증 상태를
부여한다.

1. 전문가가 각 문항의 관련성·포괄성·이해가능성을 독립 평가한다.
2. 다양한 연령의 한국어 사용자를 대상으로 인지면담을 진행한다.
3. 문항별 결측률, 천장·바닥 효과와 선택지 분포를 확인한다.
4. 순서형 자료에 맞는 요인분석과 오메가 신뢰도를 검토한다.
5. 일정 기간 뒤 재검사 안정성을 확인한다.
6. 관련 개념과의 수렴타당도, 다른 개념과의 변별타당도를 확인한다.
7. 연령·성별 등 집단 간 측정불변성과 문항편향을 확인한다.
8. 일상 기록에서 실제로 도움이 되었다고 느낀 경험과 연결되는지 살펴본다.

## 자동화된 필수 테스트

- 네 공통 장면마다 세 도움 문항이 정확히 한 개씩 존재한다.
- 도움마다 4문항이며 역문항을 사용하지 않는다.
- 0·12·13·37·38·62·63·87·88·100점 경계 문구가 정확하다.
- `50·50·50·50`과 `0·0·100·100`이 다른 리포트를 만든다.
- 낮은 점수에서 반대 선호 문장을 생성하지 않는다.
- 동점, 전체 높음, 전체 낮음, 결측 결과가 비어 있지 않다.
- 장면별 문장은 실제 문항 점수가 있을 때만 생성한다.
- 개인화 문장에 내부 코드가 노출되지 않는다.
- 문항·채점 버전이 다른 결과를 현재 결과로 열지 않는다.
- 32개 뉴앙코드와 대표 점수 상황을 교차해 각 코드의 승인 별칭·다섯 축
  라벨·근거 ID·성향지도 링크가 정확한지 전수 검사한다.
- 결과 화면은 320·360·390·430px에서 가로 넘침, 제목 고립,
  라벨 침범과 접기·펼치기 동작을 확인한다.

구성개념과 한국어 문항에 적용한다.

## 앞으로 모든 검사를 만드는 공통 순서

1. 사용자가 결과로 알고 싶은 질문을 먼저 한 문장으로 고정한다.
2. 비슷해 보이는 구성개념과 측정하지 않을 내용을 분리한다.
3. 학술·상업 검사에서 구성개념 구조와 검증 방법만 조사하고 저작권과
   사용 허가를 기록한다.
4. 한국어 생활 장면으로 문항 후보를 만들고 한 문항에는 한 행동만 둔다.
5. 전문가 내용 타당도 검토와 남녀노소 인지면담을 통과시킨다.
6. 파일럿에서 문항 분포, 결측, 요인 구조, 신뢰도, 재검사 안정성,
   집단 간 불변성을 확인한다.
7. 점수 하나가 아니라 문항 패턴·하위 영역·상황 차이를 보존한다.
8. 리포트는 핵심 결과→정확한 수치→상황별 설명→대상별 적용→작은 행동
   순으로 구성한다.
9. 모든 개인화 문장은 근거 문항 또는 하위 영역과 연결한다.
10. 계산 규칙은 내부에서 버전 관리하고 고객 화면에는 해석과 활용만
    제공한다.
11. 공통 리포트 블록으로 가독성을 확인하고 320px부터 넓은 화면까지
    시각 회귀 테스트를 진행한다.
12. 문항·채점·리포트·규준을 독립 버전으로 배포하고 실제 자료가
    쌓일 때마다 재검증한다.

## 다음 검사를 만들 때의 승인 체크리스트

- [ ] 검사 이름만 보고 측정 대상이 이해되는가
- [ ] 측정 대상과 측정하지 않는 내용을 한 문장씩 정의했는가
- [ ] 서로 비교할 하위 영역이 같은 상황과 문항 수를 사용하는가
- [ ] 각 하위 영역에 최소 4개의 직접 문항이 있는가
- [ ] 평균 외에 문항 패턴을 보존하는가
- [ ] 낮은 점수를 반대 성향으로 추론하지 않는가
- [ ] 모든 점수 경계와 결측에 고객 문장이 있는가
- [ ] 결과의 모든 개인화 주장에 근거 ID가 있는가
- [ ] 장문 리포트의 각 단락이 서로 다른 질문에 답하는가
- [ ] 문항·채점·리포트 버전을 독립 관리하는가
- [ ] 한국어 인지면담과 실제 사용자 검증 계획이 있는가
